1. Создать `docs/phase-05/technical.md` НА РУССКОМ:
   - Заголовок: "Фаза 5: Голосовые звонки — Техническая документация"
   - Архитектура:
     - Диаграмма взаимодействия: Client <-> Hub Backend <-> LiveKit Server. Backend = REST API (токены, комнаты). LiveKit = WebRTC SFU (медиа). Client подключается к LiveKit напрямую через WebSocket (сигнализация) и UDP (медиа).
     - Caddy проксирует ТОЛЬКО сигнальный WS (/livekit/*). UDP-порты 50000-50100 экспонируются напрямую.
   - Структура модуля backend:
     - internal/calls/: handler.go, service.go, repository.go, chat.go, models.go
     - Ent-схемы: Call, CallParticipant
     - MongoDB: call_chat_messages (эфемерный чат)
   - Структура фронтенда:
     - components/calls/: CallRoom, CallControls, ParticipantList, ScreenShareView, CallChat, CallButton, CallPanel
     - api/calls.ts, stores/callStore.ts
   - API Reference:
     - POST /api/calls — создать звонок
     - POST /api/calls/:callId/join — присоединиться
     - POST /api/calls/:callId/leave — выйти
     - POST /api/calls/:callId/end — завершить
     - POST /api/calls/:callId/raise-hand — поднять/опустить руку
     - GET /api/calls/channel/:channelId — активный звонок канала
     - POST /api/calls/:callId/chat — отправить сообщение в чат
     - GET /api/calls/:callId/chat — получить сообщения чата
     - POST /api/calls/webhook — LiveKit webhook (без auth)
   - NATS subjects: calls.channel.{channelID}.{event}, calls.chat.{callID}
   - Конфигурация: LIVEKIT_URL, LIVEKIT_API_KEY, LIVEKIT_API_SECRET
   - Docker Compose: LiveKit service, порты, livekit.yaml
   - Безопасность: JWT-токены LiveKit подписаны shared secret, webhook верифицируется через JWT + SHA256
   - Известные ограничения и решения: Fiber/fasthttp RequestCtx reuse, empty_timeout для cleanup, nil-safe NATS
