# Бизнес-документация: Phase 1 -- Фундамент и инфраструктура

## 1. Обзор
Краткое описание что реализовано в Phase 1 и какие потребности закрывает.

## 2. Аутентификация и пользователи

### 2.1. Вход через Magic Link (AUTH-01)
- Пользователь вводит email
- Получает 6-значный код (через Resend или лог в dev-режиме)
- Вводит код -- получает доступ
- Rate limit: 3 запроса за 10 минут на email
- Код действителен 5 минут

### 2.2. Вход через Telegram (AUTH-02)
- Пользователь нажимает кнопку "Войти через Telegram"
- Telegram Widget отправляет initData
- Сервер верифицирует HMAC-SHA256 подпись
- Автоматическая привязка по telegram_id

### 2.3. Режим регистрации (AUTH-03)
- Два режима: открытый и только по приглашению
- Администратор переключает через API
- В режиме "только по приглашению" новые пользователи должны использовать invite-ссылку

### 2.4. Профиль пользователя (AUTH-04)
- Поля: имя, отображаемое имя, аватар, email, Telegram, должность, отдел, телефон, часовой пояс, язык, дата рождения
- Редактирование через UI (/settings/profile)

### 2.5. Системные роли (AUTH-05)
- Admin: полный доступ ко всем проектам и настройкам
- Member: стандартный доступ, создание проектов

### 2.6. Управление сессиями (AUTH-06)
- Множественные сессии (десктоп + мобильное)
- Список активных сессий с устройством и IP
- Завершение отдельных сессий
- JWT access token (15 мин) + refresh token (30 дней)

### 2.7. Уведомление о новой сессии (AUTH-07)
- При входе с нового устройства публикуется событие
- (В будущем: уведомление в мессенджер/Telegram)

### 2.8. Онбординг (AUTH-08)
- Шаг 1: заполнение профиля
- Шаг 2: обзорный тур
- Шаг 3: создание или присоединение к проекту

## 3. Проекты

### 3.1. Создание проекта (PROJ-01)
- Любой пользователь (Admin/Member) может создать проект
- При создании задаётся имя и уникальный ключ (для нумерации задач)
- Автоматически создаются: заглушка трекера, пространство TMS, чат проекта, канал, дашборд

### 3.2. Управление проектом (PROJ-02)
- Owner управляет: участниками, ролями, командами, настройками
- Редактирование названия, описания, аватара

### 3.3. Роли в проекте (PROJ-03)
- Фиксированные: Owner, Developer, Tester, Viewer
- Кастомные роли с bitmap-разрешениями (25+ гранулярных прав)
- RBAC middleware проверяет разрешения на каждом запросе

### 3.4. Приглашения и команды (PROJ-04)
- Invite-ссылки с указанием роли, лимитом использования и сроком действия
- Команды: группы пользователей, добавляются в проект целиком

### 3.5. Архивирование (PROJ-06)
- Read-only альтернатива удалению
- Архивированный проект доступен для просмотра, но не для редактирования

### 3.6. Корзина (PROJ-07)
- Soft delete: проект попадает в корзину на 30 дней
- Восстановление из корзины
- Окончательное удаление только Admin

## 4. UI/UX

### 4.1. Навигация (UI-01)
- Сворачиваемый sidebar: проекты, настройки, корзина
- Topbar: поиск (placeholder), уведомления (placeholder), профиль

### 4.2. Обработка ошибок (UI-07)
- Toast уведомления при ошибках API
- Request ID для отладки
- Страницы 404/500/403

### 4.3. Файлы (UI-08)
- Drag & drop загрузка
- Ctrl+V вставка
- Presigned URLs (прямая загрузка в SeaweedFS)

## 5. Инфраструктура

### 5.1. WebSocket Gateway
- Единое WebSocket соединение на клиента
- NATS bridge для fan-out событий
- Подписка на "комнаты" (project:{id})

### 5.2. Outbox Pattern
- PG+MongoDB консистентность через outbox таблицу
- Worker поллит pending события каждые 100ms
- Retry до 10 попыток

### 5.3. Файловое хранилище
- SeaweedFS (S3-совместимый)
- Presigned URLs для upload/download
- Метаданные в PostgreSQL
