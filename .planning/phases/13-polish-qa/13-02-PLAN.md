  <action>
Verify that all Dashboard and Kanban animations use only compositor-safe CSS properties (transform, opacity, filter). These are the properties that run on the GPU compositor thread and achieve 60fps even under 4x CPU throttle.

Check these specific animations in app.css:
1. `@keyframes dashEnterUp` (line ~1160) — should only animate opacity + transform. VERIFY.
2. `@keyframes kanbanEnterUp` (line ~1070) — should only animate opacity + transform. VERIFY.
3. `.kanban-card` transition (line ~1085) — check what properties are in the transition. `all` is NOT compositor-safe because it transitions layout properties too. If `transition: all 260ms` exists, replace with explicit `transition: transform 260ms var(--ease), box-shadow 260ms var(--ease), border-color 260ms var(--ease), opacity 260ms var(--ease);`
4. `.kanban-card:hover` — uses transform (good) and box-shadow (acceptable, not layout-triggering).
5. `.kanban-card:active` — uses transform and box-shadow (good).
6. `.dash-widget` transition (line ~1220) — if `all`, replace with explicit properties.
7. `.dash-qa-btn` transitions — check for `all`.
8. `.widget-card` (line ~806) — check for `all`.

For each animation/transition that uses `transition: all`, replace `all` with the specific properties actually being animated (transform, box-shadow, border-color, opacity, background, filter).

Also check the base layer rule at line ~399: `button, a, input, select, textarea { transition: all 150ms var(--ease); }` — this is a global rule applying `transition: all` to all interactive elements. This is NOT compositor-safe and can cause layout thrashing. Replace with specific properties:
```css
button, a, input, select, textarea {
  transition: color 150ms var(--ease), background-color 150ms var(--ease), border-color 150ms var(--ease), box-shadow 150ms var(--ease), opacity 150ms var(--ease);
}
```

After changes:
