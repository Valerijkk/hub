1. **AuditLog Ent schema** -- Create as defined in RESEARCH.md (id, action, entity_type, entity_id, user_id, project_id, details JSON, ip_address, user_agent, created_at). No edges needed (standalone log table). Run `go generate ./ent`.

2. **Soft-delete fields** -- Add `deleted_at` nullable Time field to Issue, TestCase, FileMetadata schemas (same pattern as Project):
   ```go
   field.Time("deleted_at").Optional().Nillable()
   ```
   Add index on `deleted_at` for each. Run `go generate ./ent`.
   IMPORTANT: After adding deleted_at, ALL existing queries for issues/test_cases/files across tracker, tms, storage modules must filter `Where(issue.DeletedAtIsNil())`. Update existing repository query methods in tracker, tms, storage to add this filter. This is critical to avoid showing trashed items in normal views.

3. **audit/repository.go** -- Ent-backed: `CreateAuditLog`, `ListAuditLogs(filters: action, entity_type, user_id, project_id, date_from, date_to, page, per_page)`.

4. **audit/consumer.go** -- NATS JetStream durable consumer (separate stream "AUDIT"):
   - Subjects: same as notification consumer (`project.>`, `tracker.>`, `messenger.channel.>`, `tms.>`, `calls.channel.>`, `auth.session.>`).
   - Durable name: "audit-logger".
   - processEvent: extract action from subject (e.g. `tracker.{projID}.issue.created` -> action="create", entity_type="issue"), extract entity_id and user_id from payload, save AuditLog record.
   - Also log auth events: `auth.session.{userID}.created` -> action="login", `auth.session.{userID}.revoked` -> action="logout".

5. **audit/service.go** -- `AuditService`:
   - `ListAuditLogs(ctx, filters)` -- paginated with all filters, admin-only
   - `GetResourceLimits(ctx)` -- read from SystemSetting: keys `limit.file.max_size_mb`, `limit.user.max_projects`, `limit.project.max_storage_mb`
   - `UpdateResourceLimit(ctx, key, value)` -- admin-only, update SystemSetting
   - `CheckLimit(ctx, limitKey, currentValue)` -- returns bool (within limit)
   - **Trash operations:**
     * `ListTrash(ctx, entityType, projectID, page, perPage)` -- query WHERE deleted_at IS NOT NULL AND deleted_at > now - 30 days
     * `RestoreItem(ctx, entityType, entityID)` -- set deleted_at = nil
     * `PurgeExpired(ctx)` -- cron: permanently delete WHERE deleted_at < now - 30 days (hard delete)
     * `SoftDelete(ctx, entityType, entityID)` -- set deleted_at = now
   - **User management:**
     * `DeactivateUser(ctx, userID)` -- set User status to deactivated (add `status` enum field to User schema: "active"/"deactivated", default "active"), revoke all sessions
     * `ReassignTasks(ctx, fromUserID, toUserID)` -- bulk update issues WHERE assignee_id = fromUser
     * `DeleteUserGDPR(ctx, userID)` -- cascade: delete all PG data (issues reassigned first), anonymize MongoDB messages (replace sender_id with nil, sender_name with "Удалённый пользователь"), delete user record

6. **User schema update** -- Add `status` enum field: Values("active", "deactivated"), Default("active"). Update auth middleware to reject deactivated users.

7. **audit/handler.go** -- Routes (all admin-only):
   - `GET /api/admin/audit` -- list audit logs with query filters
   - `GET /api/admin/limits` -- get current limits
   - `PUT /api/admin/limits/:key` -- update limit
   - `GET /api/admin/trash?type=issue&project_id=...` -- list trashed items
   - `POST /api/admin/trash/:type/:id/restore` -- restore item
   - `POST /api/admin/users/:id/deactivate` -- deactivate user
   - `POST /api/admin/users/:id/reassign` -- reassign tasks (body: {to_user_id})
   - `DELETE /api/admin/users/:id/gdpr` -- GDPR delete

8. **main.go wiring** -- Create audit consumer, service, handler. Wire routes. Start purge cron (goroutine with 24h ticker calling PurgeExpired).

9. **Update existing modules** -- In tracker, tms, storage repositories: add `.Where(issue.DeletedAtIsNil())` to all List/Get queries. In tracker delete handler: change from hard delete to soft delete (set deleted_at). Same for tms and storage.

10. **Unit tests** -- Test audit log filtering, limit checking, soft-delete/restore logic, GDPR cascade.
