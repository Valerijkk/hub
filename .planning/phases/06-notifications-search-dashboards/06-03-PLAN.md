1. **DashboardLayout Ent schema** -- Create as defined in RESEARCH.md. Add edge from User: `edge.To("dashboard_layouts", DashboardLayout.Type)`. Run `go generate ./ent`.

2. **dashboard/dto.go** -- Define:
   - `LayoutItem` struct: I string, X/Y/W/H int, WidgetType string, Config map[string]interface{}
   - `LayoutDTO`: DashboardType, ProjectID, Items []LayoutItem
   - `PersonalData`: MyTasks []TaskSummary, UnreadCount int, UpcomingCalls []CallSummary, RecentRuns []RunSummary, Deadlines []TaskSummary, TimeToday int (minutes)
   - `ProjectStats`: TasksByStatus map[string]int, BurndownData []DataPoint, VelocityData []DataPoint, BugCount int, TeamActivity []ActivityEntry, TestTrends []DataPoint, Coverage float64, FlakyCount int, Unassigned int, Overdue int
   - `AdminStats`: TotalUsers int, ActiveUsers int, TotalProjects int, TotalIssues int, DAU/WAU/MAU int, StorageUsed int64, ServiceHealth map[string]string, TopProjects []ProjectRank
   - Supporting types: TaskSummary, CallSummary, RunSummary, DataPoint, ActivityEntry, ProjectRank

3. **dashboard/service.go** -- `DashboardService` with constructor `NewDashboardService(db, rdb, mongoDB)`:
   - `GetPersonalDashboardData(ctx, userID)`: direct queries --
     * MyTasks: issues WHERE assignee_id = userID AND status NOT IN (done, closed), limit 20, order by priority
     * UnreadCount: Redis key from messenger unread service (HGETALL)
     * UpcomingCalls: calls WHERE status = 'scheduled' AND participants includes userID (next 7 days)
     * RecentRuns: test_runs WHERE created_by = userID, last 5, order by created_at desc
     * Deadlines: issues WHERE assignee_id = userID AND due_date BETWEEN now AND now+7days, order by due_date
     * TimeToday: SUM(time_logs.minutes) WHERE user_id = userID AND date = today
   - `GetProjectStats(ctx, projectID)`: Redis-cached (key `dashboard:project:{id}`, TTL 5min, fallback to live query) --
     * TasksByStatus: GROUP BY status_id on issues WHERE project_id
     * BurndownData: daily completed task count over sprint/last 30 days
     * VelocityData: completed issues per week over last 10 weeks
     * BugCount: COUNT issues WHERE type=bug AND status NOT done
     * TestTrends: test run pass rates over last 10 runs
     * Coverage, FlakyCount, Unassigned, Overdue: direct counts
   - `GetAdminStats(ctx)`: require admin role check --
     * TotalUsers, ActiveUsers (last 30 days from sessions)
     * TotalProjects, TotalIssues
     * DAU/WAU/MAU from sessions created_at
     * StorageUsed: SUM file_metadata.file_size
     * ServiceHealth: ping PG, Redis, NATS, MongoDB, SeaweedFS (check connectivity)
     * TopProjects: top 5 by issue count
   - `GetLayout(ctx, userID, dashboardType, projectID)`: Ent query on DashboardLayout
   - `SaveLayout(ctx, userID, dashboardType, projectID, items []LayoutItem)`: Ent upsert

4. **dashboard/handler.go** -- Routes:
   - `GET /api/dashboard/personal` -- personal widget data
   - `GET /api/dashboard/project/:projectId` -- project stats (require project membership)
   - `GET /api/dashboard/admin` -- admin stats (require admin role)
   - `GET /api/dashboard/layout?type=personal&project_id=...` -- get saved layout
   - `PUT /api/dashboard/layout` -- save layout

5. **main.go wiring** -- Create `dashboard.NewDashboardService(db, rdb, mongoDB)`, `dashboard.NewHandler(dashSvc)`, call `handler.RegisterRoutes(api, requireAuth, rbacSvc)`.

6. **Unit tests** -- Test personal data aggregation with mock DB, test Redis cache hit/miss for project stats, test admin role gate.

   - `getAdminDashboard()` -> GET /api/dashboard/admin

4. **WidgetGrid** (widget-grid.tsx) -- Wrapper around `ReactGridLayout` (responsive with `WidthProvider`):
   - Props: items (LayoutItem[]), onLayoutChange callback, editable boolean.
   - Map each LayoutItem to a widget component by `widgetType` using a registry.
   - Cols: lg=12, md=10, sm=6, xs=4. Row height 80px.
   - Resize handles visible in edit mode. Drag handle on widget header.
   - "Добавить виджет" button opens a picker dialog when in edit mode.
   - "Редактировать" / "Готово" toggle button.
   - On layout change, debounce and call saveLayout API.

5. **Widget components** -- Each widget is a Card with header (title + optional refresh button) and body:
   - **my-tasks.tsx**: Table/list of user's tasks with status badge, priority icon, title (link to issue). Max 10 rows.
   - **unread-messages.tsx**: List of channels with unread count, click to navigate. Integrates with messenger unread data.
   - **upcoming-calls.tsx**: List of scheduled calls with time, channel name, join button.
   - **task-status-chart.tsx**: DonutChart (Tremor) showing task count by status for project.
   - **burndown-chart.tsx**: AreaChart (Tremor) showing ideal vs actual completion over sprint/month.
   - **velocity-chart.tsx**: BarChart (Tremor) showing completed issues per week.
   - **test-trends.tsx**: AreaChart showing pass/fail/skip trends over recent test runs.
   - **team-activity.tsx**: List of recent activities (commits, comments, status changes) in project.
   - **system-health.tsx**: Status indicators (green/red dots) for PG, Redis, NATS, MongoDB, SeaweedFS.
   - **storage-usage.tsx**: BarChart showing storage per project + total.
   - **time-tracking.tsx**: Today's tracked time with progress bar, weekly summary.
   - **deadlines.tsx**: List of issues with approaching due dates, days remaining badge.
