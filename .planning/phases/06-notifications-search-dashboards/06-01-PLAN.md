2. **notification/events.go** -- Define NotificationType constants mapping NATS subjects to notification types:
   - `assigned` (tracker issue assigned)
   - `mentioned` (comment with @mention)
   - `status_changed` (issue moved)
   - `comment_added` (comment on assigned issue)
   - `message_received` (DM or mentioned in channel)
   - `call_started` (call in user's channel)
   - `run_completed` (test run completed)
   - `deadline_approaching` (issue due in 24h -- cron)
   - `blocker_added` (blocking relation created)
   Define `SubjectToType(subject string) string` mapping function.

3. **notification/dto.go** -- Request/response DTOs: `NotificationDTO`, `NotificationListResponse` (paginated), `PreferenceDTO`, `PreferenceUpdateRequest`, `MarkReadRequest`.

4. **notification/repository.go** -- Ent-backed repository: `CreateNotification`, `ListByUser` (paginated, filter by is_read), `MarkRead`, `MarkAllRead`, `CountUnread`, `GetPreferences`, `UpsertPreference`. Use composite unique index for dedup: if same (user_id, type, entity_id) within 2 seconds, skip.

5. **notification/consumer.go** -- NATS JetStream durable consumer:
   - In constructor accept `*natsclient.Client`, `*Repository`, `*NotificationService`. Get JetStream context from `nc.Conn()` via `jetstream.New(nc.Conn())`.
   - Create stream "NOTIFICATIONS" with subjects: `project.>`, `tracker.>`, `messenger.channel.>`, `tms.>`, `calls.channel.>`.
   - Create durable consumer "notification-dispatcher" with AckExplicit, MaxDeliver=5, AckWait=30s.
   - `processEvent` method: parse subject -> determine NotificationType via SubjectToType; unmarshal event payload; resolve recipients (assignee for assigned, mentioned users for mentions, project members for status changes, etc.); for each recipient call `service.Dispatch(ctx, userID, notifType, payload)`.
   - 2-second debounce window: use in-memory map[string]time.Time keyed by "userID:type:entityID"; skip if last dispatch < 2s ago.

6. **notification/service.go** -- `NotificationService` with `Dispatch(ctx, userID, notifType, title, body, entityType, entityID, projectID, actorID, isUrgent)`:
   - Check preference: `repo.GetPreferences(ctx, userID)` -- if disabled for this type+channel, skip.
   - Check quiet hours: load user timezone, convert current time, compare with quiet_hours_start/end. If in quiet hours and not urgent, skip.
   - Save notification via repo.
   - Publish to NATS `notification.user.{userID}` for WS delivery (core NATS, not JetStream -- ephemeral).
   - If telegram channel enabled and user has telegram_id, queue to telegram sender.
   Also: `ListNotifications`, `MarkRead`, `MarkAllRead`, `GetUnreadCount`, `GetPreferences`, `UpdatePreference`.

7. **notification/telegram.go** -- `TelegramSender` struct wrapping telego.Bot:
   - `NewTelegramSender(botToken string)` -- nil-safe: if botToken empty, return nil sender (no-op Send).
   - `Send(ctx, telegramChatID int64, title, body string) error` -- format with MarkdownV2, send via telego.
   - Buffered channel (cap 100) + worker goroutine with 35ms delay between sends for rate limiting.
   - `Start(ctx)` and `Stop()` lifecycle methods.

8. **WS bridge** -- Add `notification.user.>` subscription to `bridge.go Start()`:
   ```go
   notifSub, err := b.nats.Subscribe("notification.user.>", func(msg *nats.Msg) {
       parts := strings.SplitN(msg.Subject, ".", 3)
       if len(parts) < 3 { return }
       userID := parts[2]
       var payload any
       if len(msg.Data) > 0 { _ = json.Unmarshal(msg.Data, &payload) }
       b.hub.SendToUser(userID, ServerMessage{Type: TypeEvent, Event: "notification.new", Payload: payload})
   })
   ```

9. **main.go wiring** -- After calls module init, before WS gateway section:
   - Create `notification.NewRepository(db)`
   - Create `notification.NewTelegramSender(cfg.Telegram.BotToken)` (nil-safe)
   - Create `notification.NewNotificationService(repo, nc, telegramSender, db)`
   - Create `notification.NewConsumer(nc, repo, svc)`, call `consumer.Start(ctx)` in goroutine
   - Create `notification.NewHandler(svc)`, call `handler.RegisterRoutes(api, requireAuth)`
   - Start telegram sender if not nil

10. **Config** -- TelegramConfig already has BotToken. Add `TelegramNotifyBotToken` field (separate from auth bot) OR reuse existing BotToken. Decision: reuse existing BotToken (same bot for auth and notifications). No config changes needed.

11. **Handler routes** (notification/handler.go):
    - `GET /api/notifications` -- list paginated (page, per_page query params), filter by is_read
    - `GET /api/notifications/unread-count` -- returns {count: N}

    - `PATCH /api/notifications/read-all` -- mark all read
    - `GET /api/notifications/preferences` -- list preferences
    - `PUT /api/notifications/preferences` -- upsert preference

12. **Unit tests** (service_test.go) -- Test preference checking (enabled/disabled), quiet hours (in/out of window, urgent bypass), dispatch flow with mock repository. Use testify.
