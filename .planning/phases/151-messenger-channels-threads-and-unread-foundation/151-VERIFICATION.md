## Verified bounded slice

- Channel responses carry a fresh server-authoritative capability snapshot; the frontend fails closed when that snapshot is absent. Core Get/List plus Create/Update channel, new/existing DM, and AcceptInvite response callsites now resolve fresh `ReadTimeline` recipient projection before returning.
- `GET /messenger/channels/discover` provides a read-only, non-paginated browse seed: at most 100 live public same-tenant global/project channels in `created_at DESC, id DESC` order, filtered by fresh `ReadTimeline` authority. It performs no join, leave, invite, Mongo, or event side effect and does not guarantee completeness beyond the first 100 rows.
- The frontend exposes that seed only through a lazy identity-scoped `Обзор каналов` dialog. It hides stale data during refetch/error, removes 401/403 cache payloads without retry, preserves server order, renders only `public && can_read`, and has no channel navigation, Join/Leave, request-access, or optimistic membership action.
- Direct replies persist and project `also_send_to_channel`; a flagged reply is the same canonical record in the root timeline and thread, and nonce replay cannot change the flag.
- Thread/timeline cache keys, unread state, channel state, reconnect refetch, and revoke cleanup are scoped to the current user/channel resource rather than reconstructed client arithmetic.
- `channel_removed` is a direct client revoke barrier for message fetch, typing, composer sends/retries/uploads, message actions, forward targets, and route rendering. A server-authorized `channel_created` event is the only realtime path that clears that barrier before authoritative refetch; stale channel snapshots remain filtered while revoked.
- Message mutation UI projects exact capabilities for reply, reaction, thread read, pin, bookmark, forward, edit, and delete. An ordinary current member may delete only their own message; owner/admin/moderator may delete any message. Click-time guards re-read current membership/capabilities after awaits.
- Bookmark enrichment is channel-bound and two-phase: PostgreSQL bookmark rows are grouped by distinct `channel_id`, each unique target receives one fresh `ReadTimeline` proof, every proof completes before Mongo, denied targets are omitted, source order is preserved, and a message whose `ChannelID` differs from the bookmark channel cannot populate `ContentPreview`.
- The frontend bookmarks query is scoped to the authenticated user. Delayed A responses, remove completion, navigation, generic cache rows, and the disabled `__no-user__` sentinel cache cannot expose or mutate B/no-user state.
- Pinned-message list projection is channel-bound after fresh requested-channel authority: nil and foreign-channel repository rows are omitted before a response can be built.
- Pin toggling fails closed on repository ambiguity: only Ent NotFound reaches AddPin, an existing pin reaches RemovePin, and every other `FindPin` error returns Internal 500 with zero pin mutation.
- Frontend pinned-message queries are scoped by channel and authenticated user; no-user generic/sentinel cache rows are masked, delayed A results cannot render for B, and an A unpin finishing after an identity switch cannot invalidate or replace B state.
- Authenticated pinned-list rendering separates loading, retryable error, successful-empty, and populated states; error cannot render as empty.
- Pinned-list visibility and fetching require explicit `can_list_pins`; unpin visibility and mutation require `can_pin`. Missing capabilities fail closed, while click-time and post-await guards re-read the latest channel DTO snapshot, current store capabilities, identity/channel binding, and revoke state before mutation or exact cache invalidation.
- Message-row pin completion invalidates only the exact authenticated user/channel pins key. It requires identity plus latest DTO/store `can_pin` before the request and repeats identity, capability, and revoke checks after await; response metadata is insufficient for optimistic pin-row synthesis, so no pin/message cache payload is fabricated.
- Root timeline fetches, reconnect invalidation, WS deltas, generic invalidation, optimistic edit, and pinned previews now use the exact authenticated user/channel message key. A-to-B delayed responses remain isolated, and no-user state performs no fetch/room/event work while masking both flattened messages and raw query data from legacy and sentinel caches.
- Paged thread replies and production ThreadPanel detail use separate current-user cache schemas, so their incompatible payload types cannot collide. Delayed A data stays in A keys; no-user fetch/room/event/render paths expose neither raw nor projected cache data. Identity cleanup preserves current-user root/thread/pin/bookmark/channel/unread/discovery keys and removes stale identities; revoke matching remains channel-scoped at key index 2.
- Production ThreadPanel now uses the detail query only for the parent and renders replies exclusively from the identity-scoped WS-aware paged cache. Parent and reply loading are independent; revoke synchronously masks resident root/thread hook data, parent, replies, and composer. A bounded per-user/channel/root pending map merges `message_sent` deltas that arrive during the initial replies fetch, and send completion invalidates the immutable snapshotted root key rather than live composer state.
- The thread delta buffer also covers resident-cache refetch: direct replies are queued while the exact query fetches and replay only after fetching settles. The 100-row cap records overflow and schedules one exact canonical recovery refetch after merge, so eviction is bounded but not silently permanent.
- Edit, delete, and reaction deltas patch resident thread state immediately and enter a bounded ordered per-scope journal while an exact fetch/recovery is active. The journal overlays both raw and flattened public data, so stale responses cannot transiently restore pre-edit or deleted replies while canonical recovery remains unresolved. Reconcile and overflow coalesce into exact recovery; the journal clears only after an unrearmed recovery completes. Mutation-journal overflow masks public thread data fail-closed until canonical recovery.
- Pending composer work is principal-bound. The immutable send snapshot carries `userId`; initial/retry and post-await paths fail closed after an identity change, prior-user retries are discarded, and access loss resets active sending state. Thread issue links use a user-scoped query key and mask render/mutations without identity or after channel revoke.
- Backend `ListThreadIssueLinks` now requires the current actor and executes `FindChannelInProject` → fresh `IsProjectMember(projectID, actorID)` → `IsChannelMember(channelID, actorID)` before any link read. Global/foreign/deleted channels, inactive/non-project actors, and channel non-members share the same 404; either membership-proof infrastructure failure maps to one redacted 500. Authorized empty remains `[]`; no Mongo root-existence proof is claimed, and the existing issue-project response filter remains defence in depth.
- Task 128 statically synchronizes `backend/docs/docs.go`, `swagger.json`, and `swagger.yaml`. A single order-insensitive semantic oracle rejects the legacy promotion path, requires the scoped channel/message `POST` with exact `channelId`, `messageId`, body, and `201`, and validates `UnreadResponse` as four `int64` maps plus `any_unread`. The runner consumes the checkout’s `backend/docs` through a read-only bind; it does not invoke a generator or mutate sources.
- Task 98 binds the promotion source to the already-authorized route channel. The service requires a private `FindLiveMessageInChannel(channelID, messageID)` capability and never falls back to a generic source-ID read. Mongo executes one `_id + channel_id + deleted_at:nil` lookup; missing, deleted, and foreign-channel sources collapse to one 404, while capability/store/invariant failures return a redacted 500 before target checks, issue creation, linking, backlink writes, or events.
- Task 99 adds a fresh target-project authority boundary after that source proof. The RBAC repository resolves an active actor and an exact active, non-soft-deleted project through the actor organization, then resolves current membership/custom role for ordinary actors. The decision path never reads PermissionCache; founder/admin bypass occurs only after live same-organization target proof. Unavailable targets collapse to 404, live targets without `task.create` to 403, and dependency/query/invariant failures to redacted 500 before downstream reads or effects.
- Scoped reaction authorization and both forward proofs run before Mongo. Legacy reaction and forward membership checks also run before message lookup, preventing message-existence oracles.
- Forward semantics are split explicitly: source requires `CanRead && CanForward`; target requires `CanPost`.
- Production WebSocket room authorization, per-user channel lifecycle delivery, and channel event audience resolution use `WSChannelAuthority` with a fresh PostgreSQL `ChannelActionReceiveEvent` proof; denied, duplicate, and malformed candidates are filtered before delivery.
- A valid active user with no authorized unread targets receives four empty maps and `any_unread=false` with zero unread-coordinator/Mongo calls.
- The unbound pure post-create seam now accepts a full prepared `MessageDocument`, deep-copies JSON/attachments/mentions/resolved mentions, assigns server UTC/pending state, rejects server-managed fields, and stops invalid JSON before any repository call. This is a prerequisite only, not a production binding.
