### B. `backend/internal/apigateway/webhook_test.go` (EXTEND, ≥ 3 тестов)
К текущему `TestSendWebhook_BlocksLoopbackSSRF` добавить:
- `TestSendWebhook_AllowsPublicURL_200` — поднять `httptest.NewServer`, проверить что dispatcher успешно его дёрнул, statusCode=200, body соответствует.
- `TestSendWebhook_5xxRetries` — `httptest.NewServer` с handler возвращающим 503, проверить что `deliverWithRetry` делает несколько попыток (минимум 2 hit-а сервера). Использовать `atomic.Int32` для подсчёта запросов на сервере.

### D. `backend/internal/auth/magiclink_test.go` (NEW, ≥ 3 тестов)

- `TestMagicLink_SendMagicLink_RateLimit` — 3 раза SendMagicLink подряд → 4-й → `ErrMagicLinkRateLimited`.

## Risk + Rollback
- **Risk:** `miniredis` или `sqlite3` могут потребовать `CGO_ENABLED=1` для sqlite (mattn/go-sqlite3). Если CI отключает CGO — использовать `modernc.org/sqlite` (pure-Go) через ent с `ent/dialect/sql/schema`. **Решение:** сначала попробовать `mattn/go-sqlite3`; при провале CI — переключиться на `modernc.org/sqlite`. Зафиксировать выбор в SUMMARY.
- **Risk:** Webhook retry-логика читает state из DB; в `TestSendWebhook_5xxRetries` нужно не ent, а тестировать **только** `sendWebhook` (низкоуровневый HTTP-вызов) — это безопасно и не требует БД.
- **Risk:** Outbox panic test потребует interface extraction для nats publisher. Это **минимальное** изменение production-кода (1 строка) — допустимо в этом плане.
- **Rollback:** Каждый файл — отдельный коммит (`test(apigateway): add webhook signing tests`, etc.). Откат через `git revert` любого из них.
