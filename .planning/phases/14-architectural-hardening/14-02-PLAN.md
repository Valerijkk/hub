## Goal
Расщепить CallService (479 строк, mixes LiveKit RPC + DB persistence + NATS publish + ephemeral chat)
на три коллабораторов:
1. **CallRoomService** — все вызовы LiveKit RoomServiceClient (CreateRoom, DeleteRoom, UpdateParticipant, GenerateToken).
2. **CallEventPublisher** — публикация NATS-событий (`calls.channel.*.started/joined/left/ended`, `calls.chat.<id>`).
3. **CallChatService** — эфемерный чат звонков (SendChatMessage, ListChatMessages), использует `ChatRepository`.

`CallService` остаётся тонким orchestrator (≤ 250 строк), который оркестрирует эти три коллаборатора + `EntRepository`.

## Scope

**In:**
- Создать `service_room.go` с `CallRoomService` — wrapper над `*lksdk.RoomServiceClient`.
- Создать `service_events.go` с `CallEventPublisher` — wrapper над `*natsclient.Client`, инкапсулирует subject строки.
- Создать `service_chat.go` с `CallChatService` — поглощает существующие методы `SendChatMessage` / `ListChatMessages` (плюс работу с `chatRepo`).
- Перепаковать `service.go` в orchestrator, который:
    - хранит `room *CallRoomService`, `pub *CallEventPublisher`, `chat *CallChatService`, `repo *EntRepository`
    - сохраняет существующий публичный API (`CreateCall`, `JoinCall`, `EndCall`, etc.) — back-compat для handler.go
    - **никаких прямых вызовов `s.roomClient.X`, `s.nats.PublishJSON(...)`, `s.chatRepo.X` — всё через коллабораторов.**
- `EntRepository` (repository.go) — **проверить покрытие**: текущие методы (GetCall, CreateCall, AddParticipant, RemoveParticipant, UpdateCallEnded, UpdateCallStarted, GetCallByRoomName, GetCallByInviteCode, GetActiveCallByChannel, IsChannelMember, GetChannelMemberRole) уже покрывают весь usage. **Никаких новых методов не нужно.**
- Сохранить `ErrCallForbidden` и `defaultMaxCallParticipants` как package-level (по требованию handler/tests).

**Out:**
- `handler.go`, `handler_calls.go`, `handler_recording.go`, `handler_scheduled.go` — НЕ изменяем. `CallService` сохраняет публичные сигнатуры.
- `recording.go`, `scheduled.go`, `chat.go`, `dto.go`, `models.go` — НЕ изменяем (они уже разделены по подсистемам).
- Никаких изменений в `cmd/server/main.go` (`NewCallService` сохраняет сигнатуру).
- `chat_test.go`, `recording_test.go` — НЕ изменяем (зависят только от ChatRepository / EntRepository).

### service.go (orchestrator, целевой ≤ 220 строк)
```go
type CallService struct {
    repo *EntRepository
    room *CallRoomService
    pub  *CallEventPublisher
    chat *CallChatService
}

// NewCallService СОХРАНЯЕТ существующую сигнатуру (см. backend/cmd/server/main.go).
func NewCallService(cfg config.LiveKitConfig, repo *EntRepository, nc *natsclient.Client, chatRepo *ChatRepository) *CallService {
    pub := NewCallEventPublisher(nc)
    return &CallService{
        repo: repo,
        room: NewCallRoomService(cfg),
        pub:  pub,
        chat: NewCallChatService(repo, chatRepo, pub),
    }
}

// Сохраняемые публичные методы (делегируют, добавляя оркестрацию):
//   GenerateToken          -> s.room.GenerateToken
//   CreateCall             -> s.room.CreateRoom + s.repo.CreateCall + s.room.GenerateToken + s.repo.AddParticipant + s.pub.Started
//   CreateInstantCall      -> аналогично, без s.pub.Started
//   JoinCall               -> s.repo.GetCall + authz + s.repo.AddParticipant + s.room.GenerateToken + s.pub.Joined
//   JoinByInviteCode       -> ...
//   LeaveCall              -> s.repo.GetCall + s.repo.RemoveParticipant + s.pub.Left
//   EndCall                -> s.repo.GetCall + authz + s.room.DeleteRoom + s.repo.UpdateCallEnded + s.pub.Ended
//   GetActiveCallByChannel -> s.repo.GetActiveCallByChannel
//   SetRaiseHand           -> s.room.UpdateParticipantMetadata
//   OnRoomStarted          -> s.repo.UpdateCallStarted
//   OnRoomFinished         -> s.repo.GetCallByRoomName + s.repo.UpdateCallEnded + s.chat.DeleteCallChat + s.pub.Ended
//   SendChatMessage        -> s.chat.SendMessage
//   ListChatMessages       -> s.chat.ListMessages
//   OnParticipantJoined    -> s.repo.GetCallByRoomName + s.repo.AddParticipant
//   OnParticipantLeft      -> s.repo.GetCallByRoomName + s.repo.RemoveParticipant
```

Helper `channelIDStr` переезжает в `service_events.go` (private). `toCallResponse` остаётся в `service.go` (используется orchestrator-методами).

`OnRoomFinished` — нужен метод `s.chat.DeleteCallChat(ctx, callID string)` в `CallChatService`, или оставить прямой вызов `s.chat.chat.DeleteCallChat`. **Решение**: добавить `func (s *CallChatService) DeleteCallChat(ctx, callID string)` (no-op если chat==nil) — incapsulate nil-check.

## Risk + Rollback
- **Risk:** `OnRoomFinished` имеет ветку `if s.chatRepo != nil` для optional MongoDB — после рефакторинга nil-check переезжает в `CallChatService.DeleteCallChat` (no-op if `s.chat == nil`). Покрыть случай в существующем `chat_test.go`, если он импортирует internal.
- **Risk:** `CallChatService.SendMessage` сейчас публикует ChatMessage event сам — после рефакторинга публикация через `s.pub.ChatMessage`. Семантика та же.
- **Rollback:** Один атомарный коммит `refactor(calls): split CallService into Room/Events/Chat (SC-14-2)`. Откат через `git revert <sha>`.
