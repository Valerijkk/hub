## Goal
Расщепить AuthService (667 строк, mixes JWT/refresh/sessions/magic-link/Telegram/profile/onboarding/registration mode)
на 4 субсервиса в одном пакете `auth`. Сохранить полную back-compat хендлеров и main.go wiring через
композитный `AuthService`, который делегирует на субсервисы.

## Scope

**In:**
- Создать `SessionService` (JWT, refresh-токены, CreateSession/RefreshToken/Logout/ListSessions/RevokeSession)
- Создать `LoginService` (LoginWithMagicLink, LoginWithTelegram, LoginWithTelegramUser, findOrCreateUser*)
- Создать `ProfileService` (GetMe, UpdateProfile, CompleteOnboarding, UserToResponse)
- Создать `RegistrationModeService` (GetRegistrationMode, SetRegistrationMode, upsertSystemSetting, checkRegistrationAllowed, isFirstUser)
- Превратить `AuthService` в **тонкий orchestrator** (≤ 250 строк), хранящий ссылки на 4 субсервиса и проксирующий вызовы хендлеров на них (для сохранения сигнатур handler.go).
- Каждый субсервис: собственный конструктор `NewXxxService(...)`, собственный `*ent.Client`/`*redis.Client` зависимости передаются явно.
- Каждый субсервис ≤ 250 строк.
- Обновить `service_test.go` чтобы он компилировался (использует только публичные методы).

**Out:**
- Никаких изменений в `handler.go` (сигнатуры методов остаются — оркестратор делегирует).
- Никаких изменений в `cmd/server/main.go` (конструктор `NewAuthService` сохраняет ту же сигнатуру, внутри создаёт все 4 субсервиса).
- `magiclink.go`, `telegram.go`, `telegram_bot.go`, `resend.go`, `middleware.go`, `events.go`, `dto.go` — не трогаем.
- Permission представление — не трогаем (это 14-05).

### service.go (orchestrator, целевой ≤ 100 строк)
```go
type AuthService struct {
    Sessions  *SessionService
    Login     *LoginService
    Profile   *ProfileService
    RegMode   *RegistrationModeService
    // public fields — handler.go обращается через h.service.Sessions.X(), h.service.Login.Y() и т.д.

    // Также сохраняем приватный magicLink, т.к. handler.go обращается к service.magicLink (см. handler.go:88,97).
    magicLink *MagicLinkService
}

// NewAuthService СОХРАНЯЕТ существующую сигнатуру (не ломаем main.go!).
func NewAuthService(
    db *ent.Client,
    rdb *redis.Client,
    nats *natsclient.Client,
    jwtSecret string,
    accessTTL, refreshTTL time.Duration,
    magicLink *MagicLinkService,
    botToken string,
) *AuthService {
    sessions := NewSessionService(db, rdb, nats, jwtSecret, accessTTL, refreshTTL)
    regMode := NewRegistrationModeService(db)
    login := NewLoginService(db, magicLink, botToken, sessions, regMode)
    profile := NewProfileService(db)
    return &AuthService{Sessions: sessions, Login: login, Profile: profile, RegMode: regMode, magicLink: magicLink}
}

// Делегирующие методы — БЭК-КОМПАТ для handler.go (handler вызывает h.service.LoginWithMagicLink и т.д.).
// Каждый — однострочный пасс-через. НИКАКОЙ бизнес-логики здесь.
func (s *AuthService) ParseAccessToken(t string) (*JWTClaims, error) { return s.Sessions.ParseAccessToken(t) }
func (s *AuthService) CreateSession(ctx, uid uuid.UUID, dev, ip string) (*TokenPairResponse, error) { return s.Sessions.CreateSession(ctx, uid, dev, ip) }
func (s *AuthService) RefreshToken(ctx, t string) (*TokenPairResponse, error) { return s.Sessions.RefreshToken(ctx, t) }
func (s *AuthService) Logout(ctx, sid uuid.UUID) error { return s.Sessions.Logout(ctx, sid) }
func (s *AuthService) ListSessions(ctx, uid uuid.UUID) ([]*ent.Session, error) { return s.Sessions.ListSessions(ctx, uid) }
func (s *AuthService) RevokeSession(ctx, uid, sid uuid.UUID) error { return s.Sessions.RevokeSession(ctx, uid, sid) }
func (s *AuthService) LoginWithMagicLink(ctx, email, code, dev, ip string) (*TokenPairResponse, error) { return s.Login.LoginWithMagicLink(ctx, email, code, dev, ip) }
func (s *AuthService) LoginWithTelegram(ctx, initData, dev, ip string) (*TokenPairResponse, error) { return s.Login.LoginWithTelegram(ctx, initData, dev, ip) }
func (s *AuthService) LoginWithTelegramUser(ctx, tg *TelegramUser, dev, ip string) (*TokenPairResponse, error) { return s.Login.LoginWithTelegramUser(ctx, tg, dev, ip) }
func (s *AuthService) GetMe(ctx, uid uuid.UUID) (*ent.User, error) { return s.Profile.GetMe(ctx, uid) }
func (s *AuthService) UpdateProfile(ctx, uid uuid.UUID, req UpdateProfileRequest) (*ent.User, error) { return s.Profile.UpdateProfile(ctx, uid, req) }
func (s *AuthService) CompleteOnboarding(ctx, uid uuid.UUID, req OnboardingCompleteRequest) (*ent.User, error) { return s.Profile.CompleteOnboarding(ctx, uid, req) }
func (s *AuthService) GetRegistrationMode(ctx) (string, error) { return s.RegMode.GetRegistrationMode(ctx) }
func (s *AuthService) SetRegistrationMode(ctx, mode string) error { return s.RegMode.SetRegistrationMode(ctx, mode) }
```

`handler.go` ссылается на `s.service.magicLink` (приватное поле) — оставляем это поле в orchestrator-структуре, остальное проксируем.

## Risk + Rollback
- **Risk:** Циклическая зависимость LoginService↔SessionService↔RegistrationModeService — сейчас граф ациклический (Login→Sessions+RegMode, остальные не зависят друг от друга). Если возникнет — Login пусть принимает `RegMode` как интерфейс с 2 методами.
- **Risk:** Test файл `service_test.go` тестирует приватные методы (TestVerifyTelegramAuth — это в telegram.go, не service.go, так что безопасно). Остальные функции в service_test.go используют только публичный API.
- **Rollback:** Один атомарный коммит `refactor(auth): split AuthService into 4 subservices (SC-14-1)`. Откат через `git revert <sha>`. main.go и handler.go не меняются — нет каскадных эффектов.
