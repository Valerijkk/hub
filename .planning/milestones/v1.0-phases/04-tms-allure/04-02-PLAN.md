1. Extend the backend TMS module from plan 04-01 with test run execution logic:

**repository.go** -- add methods:
- `AddTestCasesToRun(ctx, runID uuid.UUID, caseIDs []uuid.UUID) error` -- bulk-create TestResult entries (one per test case) with status "unknown"
- `UpdateTestResult(ctx, resultID uuid.UUID, input UpdateTestResultInput) (*ent.TestResult, error)` -- update status, comment, step_results, add files edge
- `GetTestResult(ctx, resultID uuid.UUID) (*ent.TestResult, error)` -- eager-load test_case, files, executed_by
- `ListTestRunResults(ctx, runID uuid.UUID) ([]*ent.TestResult, error)` -- eager-load test_case, files
- `AssignTestersToRun(ctx, runID uuid.UUID, userIDs []uuid.UUID) error` -- set M2M assignees edge
- `GetTestRunWithResults(ctx, runID uuid.UUID) (*ent.TestRun, error)` -- eager-load results with nested test_case + files

**dto.go** -- add:
- `AddTestCasesToRunRequest { CaseIDs []string }` -- list of test case UUIDs to add
- `UpdateTestResultRequest { Status string, Comment string, StepResults []StepResultInput }` -- step-level results
- `StepResultInput { StepOrder int, Status string, Comment string, FileIDs []string }` -- per-step with evidence
- `AssignTestersRequest { UserIDs []string }`
- `TestRunDetailResponse` -- full run with results list, assignees, stats
- `TestResultDetailResponse` -- result with test case info, files, step results

**service.go** -- add methods:
- `AddTestCasesToRun`: Validate all case IDs exist in same project. Create result entries. Update run total_count.
- `ExecuteTestResult`: Validate run is in_progress. Update result with status, step_results, comment. Link files (file IDs must reference existing FileMetadata). Set executed_by to current user. Recompute run stats (passed_count, failed_count, etc.) after each result update.
- `AssignTestersToRun`: Validate users are project members. Set assignees.
- `GetTestRunDetail`: Return run with all results, stats, assignees.
- `StartTestRun`: Transition created->in_progress, set started_at.
- `CompleteTestRun`: Transition in_progress->completed, set completed_at. Publish EventTestRunCompleted via outbox.

**handler.go** -- add endpoints:
- `POST /runs/:runId/cases` -> AddTestCasesToRun (PermTestRunCreate)
- `PUT /runs/:runId/results/:resultId` -> ExecuteTestResult (PermTestRunExecute)
- `POST /runs/:runId/assignees` -> AssignTestersToRun (PermTestRunCreate)
- `POST /runs/:runId/start` -> StartTestRun (PermTestRunExecute)
- `POST /runs/:runId/complete` -> CompleteTestRun (PermTestRunExecute)
- Add Swagger annotations IN RUSSIAN.

**service_test.go** -- add tests:
- TestAddTestCasesToRun: Verify results created for each case.
- TestExecuteTestResult_UpdatesStats: Verify run counters update after result.
- TestCompleteTestRun: Verify transition and completed_at set.
- TestStartTestRun_InvalidTransition: From completed should fail without reopen.

2. Create **frontend/src/shared/api/tms.ts**: API client for all TMS endpoints following existing api/ pattern. Functions:
- Test cases: createTestCase, listTestCases, getTestCase, updateTestCase, deleteTestCase, listVersions, rollbackVersion
- Suites: createSuite, listSuites, updateSuite, deleteSuite
- Components: createComponent, listComponents, deleteComponent
- Runs: createTestRun, listTestRuns, getTestRunDetail, startRun, completeRun, reopenRun, addCasesToRun, assignTesters
- Results: updateTestResult
- All functions use the existing fetch wrapper pattern from `frontend/src/shared/api/`.

3. Create **frontend/src/shared/stores/tms-store.ts**: Zustand store for TMS module state. Fields:
- testCases: TestCase[], selectedTestCase: TestCase | null
- suites: Suite[], selectedSuite: Suite | null
- testRuns: TestRun[], selectedRun: TestRun | null
- filters: { suiteId, status, priority, search }
- Actions: fetchTestCases, fetchTestRuns, fetchRunDetail, updateFilter, etc. Each action calls tmsApi.
