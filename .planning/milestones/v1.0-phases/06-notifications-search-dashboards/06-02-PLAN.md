  <action>
1. **SavedFilter Ent schema** -- Create as defined in RESEARCH.md. Add edge from User: `edge.To("saved_filters", SavedFilter.Type)`. Run `go generate ./ent`.

2. **Atlas migration for tsvector columns** -- Create a manual SQL migration file at `backend/ent/migrate/migrations/` that adds `search_vector tsvector GENERATED ALWAYS AS (...)` STORED columns and GIN indexes to: issues, test_cases, users, projects, file_metadata tables. Use `'simple'` text search config (works for both Russian and English without stemming). Exact SQL as in RESEARCH.md section "Atlas Migration: tsvector + GIN Index". NOTE: Ent does not support tsvector natively; these columns are added via raw migration only (not in Ent schema fields). If the project uses atlas auto-migration (`atlas migrate diff`), add the tsvector columns via a custom migration script that runs after Ent auto-migration. Alternative: if the project uses `db.Schema.Create(ctx)` for auto-migration, create a `search/indexer.go` with `EnsureSearchIndexes(ctx, db)` function that executes raw `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` SQL statements, and call it from main.go after DB init.

3. **search/dto.go** -- Define:
   - `SearchResult` struct: ID, Type (issue/test_case/user/project/channel/file/message), Title, Subtitle, ProjectID, URL, Score float64
   - `SearchRequest`: Query string, Types []string (filter), Limit int
   - `SearchResponse`: Results []SearchResult, Total int
   - `SavedFilterDTO`, `SavedFilterCreateRequest`, `SavedFilterListResponse`

4. **search/service.go** -- `SearchService` with:
   - Constructor: `NewSearchService(db *ent.Client, mongoDB *mongo.Database)`.
   - `Search(ctx, query, userID, types []string, limit int) ([]SearchResult, error)`:
     - Pre-fetch user's project IDs from project_members table (one query, cache in context).
     - Launch parallel goroutines for PG + MongoDB search.
     - PG search: raw SQL `SELECT id, issue_key, title, ts_rank(search_vector, plainto_tsquery('simple', $1)) AS rank FROM issues WHERE search_vector @@ plainto_tsquery('simple', $1) AND project_id = ANY($2) ORDER BY rank DESC LIMIT 10`. Similar queries for test_cases, users (no project filter), projects (filter by membership), file_metadata, channels.
     - MongoDB search: `$text: {$search: query}` with `channel_id IN user's channel IDs` filter, projection with textScore, limit 10.
     - Merge results by score, limit to requested count (default 20).
     - Permission filter: issues/test_cases/channels filtered by project membership in WHERE clause (not post-query).
   - `CreateSavedFilter`, `ListSavedFilters(userID, projectID)`, `DeleteSavedFilter`, `ShareFilter(filterID, share bool)`.

5. **search/handler.go** -- Routes:
   - `GET /api/search?q=...&type=issue,test_case,user&limit=20` -- global search
   - `POST /api/filters` -- create saved filter
   - `GET /api/filters?project_id=...` -- list saved filters (own + shared in project)
   - `DELETE /api/filters/:id` -- delete saved filter
   - `PATCH /api/filters/:id/share` -- toggle shared

6. **main.go wiring** -- Create `search.NewSearchService(db, mongoDB)`, `search.NewHandler(searchSvc)`, call `handler.RegisterRoutes(api, requireAuth)`. Call `search.EnsureSearchIndexes(ctx, db)` after DB init if using the function approach for tsvector columns.

7. **Unit tests** (service_test.go) -- Test search result merging, permission filtering logic (user without project access should not see results), saved filter CRUD. Use mock for DB queries.
