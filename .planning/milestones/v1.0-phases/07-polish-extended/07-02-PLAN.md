  <action>
1. Создать Ent-схему `GitHubIntegration` (`backend/ent/schema/githubintegration.go`):
   - Поля: id (UUID), repo_owner (string), repo_name (string), access_token (string, sensitive), webhook_secret (string), merge_status_id (optional UUID -- целевой статус при мерже PR, GHUB-04), created_at.
   - Edge: project (M2O к Project).
   - Unique index: (project_id, repo_owner, repo_name).

2. Создать Ent-схему `GitHubLink` (`backend/ent/schema/githublink.go`):
   - Поля: id (UUID), link_type (enum: commit/pull_request), external_id (string -- GitHub PR number или commit SHA), title (string), url (string), status (enum: open/merged/closed/none), author (string), branch (string, optional), created_at, updated_at.
   - Edges: issue (M2O к Issue), integration (M2O к GitHubIntegration).
   - Index: (issue_id), (external_id, link_type).

3. Запустить `go generate ./ent`.

4. Создать GitHub module (`backend/internal/github/`):
   - `dto.go`: GitHubLinkResponse, CreateIntegrationRequest, LinkPreviewResponse, CreateBranchRequest.
   - `repository.go`: Repository interface -- CRUD для GitHubIntegration и GitHubLink.
   - `service.go`: GitHubService struct с repo, trackerRepo, go-github client, nats.
     - HandlePushWebhook (GHUB-02): парсит push event payload, для каждого коммита ищет `\b([A-Z]+-\d+)\b` в message. Для каждого найденного ключа проверяет существование задачи через trackerRepo.FindIssueByKey. Если существует -- создаёт GitHubLink type=commit.
     - HandlePRWebhook (GHUB-01, GHUB-03, GHUB-04): парсит pull_request event.
       - opened/reopened: создаёт или обновляет GitHubLink type=pull_request, status=open. Ищет task keys в title и body.
       - closed+merged: обновляет status=merged. Если integration.merge_status_id != nil -- вызывает workflow ValidateTransition и обновляет статус задачи (GHUB-04). Публикует NATS event.
       - closed (не merged): обновляет status=closed.
     - CreateBranch (GHUB-05): используя go-github client, создаёт ветку от default branch. Имя: slugify(issueKey + "-" + issue.Title), например "hub-123-fix-login". Возвращает branch name.
     - ValidateWebhookSignature: проверяет X-Hub-Signature-256 через HMAC-SHA256.
   - `preview.go`: LinkPreviewService (MSG-11).
     - GetLinkPreview(url): определяет тип ссылки:
       - Внутренняя задача (regex `/issues/[A-Z]+-\d+`): загружает из БД, возвращает title, status, assignee, type.
       - Внутренний тест-кейс (regex `/tms/.*test-cases`): загружает из БД.
       - Внешний URL: использует otiai10/opengraph/v2 для получения OG title, description, image.
     - Кеширует превью в Redis на 1 час.
   - `handler.go`:
     - POST /api/github/webhook -- HandleWebhook (без auth, валидация по signature).
     - POST /api/projects/:projectId/github/integrations -- CreateIntegration (auth + owner).
     - GET /api/projects/:projectId/github/integrations -- ListIntegrations.
     - DELETE /api/projects/:projectId/github/integrations/:id -- DeleteIntegration.
     - GET /api/issues/:issueKey/github-links -- ListGitHubLinks.
     - POST /api/issues/:issueKey/github/create-branch -- CreateBranch (GHUB-05).
     - GET /api/link-preview?url=... -- GetLinkPreview (auth required, MSG-11).

5. Зарегистрировать github module в main.go.

6. `go get github.com/google/go-github/v68 github.com/otiai10/opengraph/v2`.

7. Unit-тесты: HandlePushWebhook (regex matching, word boundaries), HandlePRWebhook (status transitions), ValidateWebhookSignature, GetLinkPreview (internal + external).
