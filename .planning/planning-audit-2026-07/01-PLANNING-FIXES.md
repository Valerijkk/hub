# Что править в планировании — план работ

**Дата:** 2026-07-27
**Источник:** [`00-PLANNING-AUDIT.md`](00-PLANNING-AUDIT.md)
**Принцип:** сначала перестать врать в статусе, потом закрывать разрывы кодом.

Находки аудита делятся на три класса, и лечатся они по-разному:

| Класс | Что это | Как чинится |
|---|---|---|
| **A. Ложный статус** | Планирование утверждает то, чего нет | Правкой `.planning/`, кода не касается |
| **B. Невыполненное требование** | Спека требует, код не делает | Кодом — новые фазы |
| **C. Нерешённое решение** | Выбор сделан дефолтом, не подтверждён | Подтверждением владельца |

## Класс A — ложный статус (правится только документами)

### A1. Ввести различие «задачи закрыты» и «цель достигнута»

**Проблема.** Фазы 122 и 124 закрыты с недостигнутой метрикой (`00-PLANNING-AUDIT.md` §2).
Правило закрытия смотрит на чекбоксы `- [x]`, а не на раздел Goal.

**Что сделать:**

1. В `STATE.md` разделить счётчик на два:
   ```yaml
   progress:
       total_phases: 125
       tasks_completed: 125      # чекбоксы
       goals_verified: <факт>    # цель достигнута И подтверждена VERIFICATION.md
   ```
2. Пересчитать `goals_verified` честно: фаза считается достигшей цели, только если
   есть `VERIFICATION.md` **и** метрики из Goal взяты.
3. В `122-tms-project-82/PLAN.md` и `124-floor-82/PLAN.md` добавить блок
   `## Goal not met` с фактическими числами и ссылкой на фазу, которая разрыв добрала (FA-11).

### A2. Закрыть дыру в верификации — 51 фаза

**Проблема.** 45% фаз не имеют `VERIFICATION.md` при статусе «завершено».

**Что сделать:**

1. Составить полный список 51 фазы (скрипт в §«Проверка» ниже).
2. Разделить их на три группы:
   - **Ретро-верифицируемые** — цель измерима, можно проверить сейчас → создать `VERIFICATION.md` с фактическим замером
   - **Неверифицируемые** — контекст утрачен → пометить `VERIFICATION-SKIPPED.md` с причиной, честно
   - **Требующие перепроверки** — цель не взята → вернуть в работу
3. Ни одна фаза не остаётся без артефакта, объясняющего её статус.

### A3. Перестать выдавать протухшее покрытие за текущее

2. Обновить `COVERAGE.md` с новой датой; старые цифры перенести в раздел

## Класс B — невыполненные требования (нужны фазы с кодом)

### B1. FR-INTR-08 — новость невосстановима *(приоритет: высокий)*

`NewsPost` имеет `deleted_at`, но отсутствует в типах корзины. Пост удаляется
мягко и **достать его нечем** — данные лежат в БД недоступными.

**Фаза:** добавить `newspost` в `ListTrash` / `RestoreItem` / `SoftDelete`
(`backend/internal/audit/service.go`), с каскадом на связанный опрос и голоса
согласно формулировке FR-INTR-08.

### B2. FR-CAL-05 — у серий нет корзины *(приоритет: высокий)*

У `ent/schema/scheduledcall.go` есть `rrule`, но `deleted_at` отсутствует полностью.
Ни soft delete, ни корзины.

**Фаза:** добавить `deleted_at` в схему, реализовать удаление серии со всеми
вхождениями в корзину, зарегистрировать тип в корзине.

### B3. NFR-24 — `version` на 17 схемах из 83 *(приоритет: средний)*

Формулировка «на каждой изменяемой Ent» выполнена на 20%.

**Решение принимается до фазы:**
- либо раскатать `VersionMixin` на все изменяемые схемы,
- либо **сузить формулировку NFR-24** до реального списка и обосновать.

Второй путь честнее, если optimistic lock реально нужен не везде. Но выбор
должен быть зафиксирован, а не оставлен в текущем виде.

### B4. NFR-11 — корзина на 15 схемах из 83, API знает 4 типа *(приоритет: средний)*

То же решение: раскатывать или сузить формулировку. Сейчас документ обещает
одно, код делает другое, и никто этого не отслеживает.

### B5. Модуль Wiki — решение о скоупе *(приоритет: требует владельца)*

FR-WIKI-01…04 полностью специфицированы, кода нет, роадмап о них не знает.

**Варианты:**
- завести фазы и строить,
- официально вынести за скоуп v4 с пометкой в спеке,
- удалить из спеки.

Любой вариант лучше текущего молчания. Дополнительно: решение GZ-SEC-17/18/19
по GDPR ссылается на каскад в wiki — оно тоже станет невалидным без модуля.

## Проверка

Скрипты для перепроверки любого утверждения аудита:

```bash
# Фазы без верификации
cd .planning/phases
for d in */; do [ -f "$d/VERIFICATION.md" ] || echo "$d"; done

# Схемы с version / deleted_at
cd backend/ent/schema
echo "всего: $(ls *.go | wc -l)"
echo "version: $(grep -l '\"version\"' *.go | wc -l)"
echo "deleted_at: $(grep -l 'deleted_at' *.go | wc -l)"

# Типы, поддержанные корзиной
grep -A12 'func.*RestoreItem' backend/internal/audit/service.go | grep 'case '

# Незакрытые решения серых зон
grep -c '\[default\]' .planning/gray-zones/GRAY-ZONES-DECISIONS-2026-07-03.md
```
