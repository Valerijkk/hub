### Что ищет агент в каждом файле

```
Корректность
  [ ] необработанные error, в том числе проглоченные `_ =`
  [ ] nil-разыменование, паника на пустом слайсе
  [ ] off-by-one, границы циклов и срезов
  [ ] игнорирование context cancellation

Безопасность
  [ ] отсутствие проверки владения ресурсом (IDOR)
  [ ] доверие пользовательскому вводу без валидации
  [ ] секреты и PII в логах
  [ ] SQL/шаблонные инъекции, path traversal

Данные
  [ ] транзакция без rollback, частичная запись
  [ ] N+1 запрос
  [ ] отсутствие optimistic lock там, где есть конкурентная правка
  [ ] hard delete там, где ТЗ требует корзину

Ресурсы
  [ ] незакрытые rows, файлы, тела ответов
  [ ] горутина без завершения, гонка данных
  [ ] запрос без лимита

Тесты (для *_test.go)
  [ ] assert-free тест
  [ ] тест на моке там, где guard в репозитории
  [ ] тест, который пройдёт и на сломанном коде
```

Для фронта дополнительно: утечки в `useEffect`, неверные зависимости
хуков, ключи и инвалидация TanStack Query, дублирование состояния между
zustand и query, `any`/`ts-ignore`, обработка loading/empty/error, a11y.

### Формат отчёта агента

`.planning/audits/total-2026-07/A<волна>-<агент>-<зона>.md`

```markdown
# W<N> агент <M> — <зона>

## Прочитанные файлы
| Файл | Строк | Находок | Вердикт |
|------|------:|--------:|---------|
| путь | 120 | 2 | замечания |
| путь | 45 | 0 | чисто |

Файлов в списке: N. Прочитано: N. Пропущено: 0.

## Находки
| ID | Severity | Файл:строка | Проблема | Почему это дефект | Как чинить |

## Чисто
Файлы без находок — с указанием, что именно проверялось.
```

**Жёсткое требование:** каждый файл из списка обязан быть строкой в
таблице «Прочитанные файлы». Отсутствие строки = файл не читали.
Находка без `файл:строка` невалидна и выбрасывается.

Severity: **P0** прод падает / дыра / потеря данных · **P1** ломает
сценарий · **P2** техдолг · **P3** косметика.

## Стадия C — перепроверка, волны 18–20, 15 агентов

**Ключевое правило: проверяет не тот, кто чинил.** Агент стадии C
не должен быть автором проверяемого фикса.

**Вход стадии C: 48 задач в статусе «На проверке».** Ни одна из них
не проверена независимо — статус означает «автор сказал, что сделал».

### W18 — мутационная проверка (5 агентов)

Для **каждого** фикса стадии B:

1. Сломать защиту в продакшн-коде — ровно ту, что описана в задаче
2. Показать красный тест
3. Восстановить, показать зелёный

Фикс без прошедшей мутации → задача возвращается в статус «Открыта»
с пометкой, что тест не ловит дефект.

Проверить отдельно: не стоит ли guard в репозитории при тесте только
на моке. Это самая частая ошибка прошлых волн.

### W19 — перекрёстная проверка (5 агентов)

- Находки P0/P1 из стадии A, **не** попавшие в задачи — почему
- Задачи, закрытые без evidence
- Комбинации: находка X + находка Y дают дефект тяжелее суммы
- Red team: цепочки атак обычным пользователем на текущем коде
