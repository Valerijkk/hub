```

TASK-002  ─┘

TASK-004  ───►  TASK-005   таблица Progress не согласуется
                           с невыверенным числом

```

TASK-001 и TASK-002 — реальные потери данных: сущность удаляется мягко,
а достать её продукт не умеет. Остальное — гигиена статуса и тестов.

## Легенда

**Приоритет**

| | |
|---|---|
| **P0** | Блокер: потеря данных, дыра в безопасности, прод не работает |
| **P1** | Важно: ломает сценарий или искажает статус проекта |
| **P2** | Можно отложить: техдолг, недогранулярность проверок |
| **P3** | Косметика |

**Статус**

`Открыта` → `В работе` → `На проверке` → `Закрыта`
либо `Отменена` с указанием причины.

Статус меняется **в том же коммите**, что и работа по задаче. Расхождение
таблицы с файлами задач — дефект планирования, а не мелочь.

## Что не сюда

| Что | Где |
|-----|-----|
| Крупный блок работ | `.planning/phases/NN-*/PLAN.md` (GSD) |
| Идея без срока | `ROADMAP.md`, секция `## Backlog`, нумерация `999.x` |
| Решение, ждущее владельца | [`../audits/planning-audit-2026-07/DECISIONS-PENDING.md`](../audits/planning-audit-2026-07/DECISIONS-PENDING.md) |
| Находка аудита без постановки | `.planning/audits/<аудит>/` |

Задача может реализовывать часть фазы и ссылаться на неё — но фазу
не заменяет.
