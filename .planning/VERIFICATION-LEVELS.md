# Четыре уровня проверки артефакта

> Применяется при приёмке фазы и при закрытии задачи из `backlog/`.
> Источник механизма — GSD Core (`gsd-verifier`), адаптировано под Hub.

Отчёт исполнителя не является доказательством. Источник истины — состояние
файлов. Отсюда четыре уровня: каждый следующий отвечает на вопрос, который
предыдущий не закрывает.

| Уровень | Вопрос | Чем проверяется |
|---------|--------|-----------------|
| 1 | Файл существует | `ls`, `git status` |
| 2 | В нём что-то есть по существу | размер, наличие ключевых конструкций, а не «файл на 3 строки» |
| 3 | Он подключён | импортируется **и** используется |
| 4 | Через него идут реальные данные | источник данных возвращает не пустоту и не заглушку |

## Вердикт по уровням

| Существует | По существу | Подключён | Вердикт |
|---|---|---|---|
| ✓ | ✓ | ✓ | ПРОВЕРЕНО |
| ✓ | ✓ | ✗ | **СИРОТА** — написано и не подключено |
| ✓ | ✗ | — | **ЗАГЛУШКА** |
| ✗ | — | — | ОТСУТСТВУЕТ |

**Большая часть незамеченных заглушек живёт на уровне 3.** Куски написаны,
каждый по отдельности выглядит готовым, а между собой не соединены. Проверка,
останавливающаяся на уровне 2, такую фазу принимает.

## Уровень 4 — когда обязателен

Только для артефактов, которые **отображают динамические данные**:
компоненты, страницы, дашборды, отчёты. Для утилит и конфигов не нужен.

Порядок:

```
1. Найти переменную, которую артефакт отображает.
2. Найти, чем она заполняется.
3. Проверить источник: реальный запрос или статическая заглушка.
4. Проверить место вызова: не передаётся ли пустой массив пропом.
```

Типовой промах — пункт 4. Компонент готов, запрос работает, а в месте
использования ему передают `[]`, потому что «пока так». На уровнях 1–3
всё зелёное.

## Осознанное отступление

Требование не выполнено, но реализовано иначе и это приемлемо — отступление
**фиксируется явно**, а не проходит молча:

```yaml
отступления:
  - требование: "<текст требования из плана>"
    причина: "<почему отступление приемлемо>"
    принял: "<кто>"
    дата: "<YYYY-MM-DD>"
```

Зафиксированное отступление считается **выполненным** при подсчёте. Не
зафиксированное — провалом, даже если на словах всё объяснимо.

Разница между «мы решили сделать иначе» и «не сделали» — наличие этой
записи. Без неё через месяц отличить одно от другого нельзя.

## Отложенное

Пункт, отложенный на более позднюю фазу, снимается с приёмки **только**
если эта фаза существует в `ROADMAP.md`. Отложенное «на потом» без
названной фазы — это невыполненное.

## Что этот протокол не заменяет

Прогон тестов. Уровни отвечают на вопрос «собрано ли то, что обещали», а
не «работает ли оно правильно». Артефакт может пройти все четыре уровня и
быть неверным по логике — это ловят тесты и ревью.
