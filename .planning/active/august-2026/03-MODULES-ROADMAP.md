## Группа A — модули вне августовского scope: не заявлять готовыми

`tracker` · `sprint` · `messenger` · `tms` · `calls` · `dashboards` ·
`search` · `notifications` · `ai-хаб`

За три волны аудита по ним нашлось меньше находок, чем по MVP-модулям, и
зафиксированные audit fixes закрыты. Это не означает, что какой-либо модуль
complete или stable: Hub остаётся незавершённым MVP, а готовность каждого
продуктового модуля требует отдельной founder-приёмки.

**В августовском scope для них нет отдельных работ.** Это лишь порядок
планирования и не предоставляет готовность или no-touch статус. При правках
соседних доменов по-прежнему нельзя просаживать покрытие ниже гейта 82%.

Две обещанные вещи из AI-хаба остаются в группе C и не реализованы.

## Группа B — MVP до продукта

Шесть модулей помечены «🧪 MVP (расширение в работе)». Задача трека —
довести до состояния, в котором пометку можно снять.

### Общий критерий выхода из MVP

Модуль перестаёт быть MVP, когда выполнены **все пять**:

```
1. Покрытие пакетным замером ≥82%
2. Все FR из docs/system_specification.md реализованы либо явно
   вынесены за скоуп решением владельца
3. Корзина 30 дней (NFR-11) там, где спека её требует
4. Оптимистичная блокировка (NFR-24) на изменяемых сущностях
5. Ни одной находки P0/P1 в последнем аудите
```

Пятый пункт — не «аудит не находил», а «прогнан свежий аудит по модулю».

## Группа C — новые модули

### C1. Wiki — модуль отсутствует полностью

| | |
|---|---|
| Приоритет | **P1 — строим** (решение владельца 2026-07-30) |
| Состояние | FR-WIKI-01…04 в спеке, кода ноль — начинаем с нуля |

**Развилка пройдена 2026-07-30: строим.** Решение в
[`DECISIONS-2026-07-30.md`](../../decisions/gray-zones/DECISIONS-2026-07-30.md) §1.

Объём — четыре требования спеки:

- **FR-WIKI-01** — spaces, иерархия страниц через `parent_id`, перемещение
  по дереву. Цикл (страница под своего потомка) → 422, глубина >10 → 422
- **FR-WIKI-02** — конкурентная правка через optimistic lock `version`,
  второй save → 409. Изображения через presigned upload, не base64
- **FR-WIKI-03** — удаление страницы с детьми: каскад **поддерева**
  в корзину 30 дней, восстановление возвращает поддерево. Space удаляется
  только пустым, иначе 422
- **FR-WIKI-04** — роли space read/write/admin, страницы наследуют права.
  Не-участник → 403 на любую страницу, включая прямую ссылку.
  У space всегда ≥1 admin, снятие последнего → 422

Это самый крупный новый модуль трека. Ставится **после** доводки MVP:
шесть незавершённых модулей важнее седьмого с нуля.

### C2. SSO — после ADR

| | |
|---|---|
| Приоритет | P2 — протокол выбран |
| Решение | **только OIDC**, LDAP отложен (2026-07-30) |

Протокол выбран — **OIDC**. LDAP/AD не делаем: одна модель данных
вместо двух, вдвое меньше краевых случаев. Добавится позже, если
появится конкретный клиент с требованием.

Объём: OIDC-провайдер, org-политика magic-link/sso/both,
JIT-provisioning, break-glass для входа при недоступном IdP.

Инварианты Magic Link из ТЗ сохраняются: SSO их дополняет, а не
заменяет.

## Порядок

```
Тестовый фреймворк (фазы 128-136)  ──►  ЭТОТ ТРЕК  ──►  Э1+Э2 границы

  внутри трека:
    B1 calendar  ─┐
    B2 intranet  ─┼─ параллельно, домены не пересекаются
    B3 accounting─┘
         ↓
    B4 crm · B5 hr · B6 bases
         ↓
    C3 AI MCP · C2 SSO (OIDC)
         ↓
    C1 wiki — крупнейший новый модуль, после доводки MVP
```

**Почему после фреймворка.** Доводка означает много новых тестов.
Писать их в старом фреймворке, зная, что он переезжает на Python, —
работа дважды.

**Почему wiki последняя в группе C.** Шесть незавершённых модулей
важнее седьмого с нуля: незакрытый MVP виден пользователю, а
отсутствующий модуль — нет.
