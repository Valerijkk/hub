# Бэклог — что предстоит

Задачи автоматизации: покрыть, стабилизировать, отрефакторить, разобрать.
Один файл на задачу плюс индекс в этом README.

## Формат

Файл `TASK-NNN-<короткий-слаг>.md` по [шаблону](TASK-TEMPLATE.md).
Индекс — таблица ниже, со ссылкой на файл.

| ID | Суть | Приоритет | Статус | Кому |
|----|------|-----------|--------|------|
| — | пусто | — | — | — |

## Статусы

| Статус | Значение |
|--------|----------|
| Открыта | Сформулирована, не начата |
| В работе | Взята, идёт выполнение |
| На проверке | Выполнена, ждёт ревью или прогона |
| Закрыта | Условия закрытия выполнены и подтверждены |
| Отменена | Не будет делаться, с причиной |

**Закрыта ставится только после подтверждения**, а не после «вроде
сделал». Условия закрытия записаны в самой задаче; если они не
выполнены — статус не меняется, сколько бы работы ни было проделано.

## Приоритеты

| P0 | Блокирует релиз или прячет дефект |
| P1 | Нужно в текущем цикле |
| P2 | Полезно, срока нет |

## Что сюда не кладётся

Найденный дефект продукта — в [`../bugs/`](../bugs/README.md). Разница:
задача закрывается выполнением, дефект — починкой продукта, и статусы у
них разные.

Идея без сформулированного результата — не задача. «Подумать про
покрытие модуля» невозможно закрыть: непонятно, когда сделано.
