# pro-qa-ai — продуктовая карта

> **Что:** AI-слой качества для тестового фреймворка
> **Версия:** `0.4.0-beta.3` · **Корень поставки:** `pro-qa-ai/`
> **Вход:** [START-HERE.md](START-HERE.md)

## Что это

Переносимая AI-прослойка для инженера автоматизации. Она **не заменяет**
тестовый фреймворк: изучает уже существующий, даёт моделям проверяемый
контекст и паттерны, ведёт агента по командам с проверяемым критерием
готовности.

Объект работы — **тестовый фреймворк**. Не продукт, который тестируют, и
не процесс его разработки.

## Границы

**Входит**

- Bootstrap и refresh контекста фреймворка с провенансом и честным `UNKNOWN`
- Пять ролей `test-*`: генерация кейсов, написание кода, ревью, отладка, документация
- Двенадцать команд `tf-*` за четырнадцатью скилами
- Стандарты: правила, декларативные records, практики тестов, практики кода, паттерны проекта,
  решения команды из реальных ревью, формат тест-кейсов
- Процессы: цикл работы, плейбуки, рецепты, фрагменты промптов 01–12
- Структурный валидатор, упаковщик, инвентарь контекста

**Не входит**

- Scaffold нового тестового фреймворка — работаем с тем, что есть
- Роли разработки продукта и процессы поставки — другой объект работы
- **Мутационное тестирование** — требует доступа к продуктовому коду,
  которого у автоматизатора нет. Осмысленность теста здесь разбирается
  чтением: назвать изменение поведения, которое обязано его уронить
  (см. [`standards/rules/40-verification-protocol.md`](standards/rules/40-verification-protocol.md))
- Автоматический скан закрытых мержреквестов — треды переносит человек
- Заявления об эффективности без парного замера

## Производственный статус

| Ворота | Статус |
|--------|--------|
| Структурная валидация | PASS, см. [VERSION.md](VERSION.md) |
| Portable package без профилей проекта | PASS |
| Тесты скриптов | PASS по clean-room protocol |
| Парное сравнение эффективности | **`NOT_RUN`** |
| Физическая установка в пустой репозиторий | не проводилась |
| Готовность к релизу | beta; GA после замера и подтверждения владельцем |

«Продакшен-вид» здесь означает: ясная идентичность, чистый вход,
воспроизводимая сборка, отсутствие выдуманных метрик. Это **не**
заявление «уже измерили ускорение».

Два нижних гейта открыты честно. Пока они открыты, пакет пригоден к
работе, но не к утверждениям о пользе.

## Происхождение

Пакет собран в монорепозитории Hub и живёт там рядом с продуктовым кодом
как эталон и источник переносимой сборки.

Hub-специфика — конкретный стек, внутренние регламенты, ограничения ТЗ —
в пакет **не входит**: она остаётся в `.cursor/` исходного репозитория.
Сюда перенесены только практики, применимые к любому тестовому
фреймворку.

История решений по составу — [CHANGELOG.md](CHANGELOG.md).
