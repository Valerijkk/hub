# Практики автоматизации — заполненный каталог

Переносимые практики с парами «плохо / хорошо». Заполнены заранее и
работают сразу после установки, без сбора контекста.

## Место в порядке источников

Единственная лестница приоритета — в [`standards/README.md`](../README.md).
Здесь она не пересказывается: пересказ расходится с оригиналом.

Практики отсюда — **третий** уровень. Решение команды из треда и факт из
профиля их перебивают: они написаны без знания конкретного проекта.

## Чем это отличается от соседних каталогов

| Каталог | Что внутри | Откуда берётся | Переносится |
|---|---|---|---|
| `practices/` | Общие практики автоматизации | Заполнено заранее | да |
| [`../patterns/`](../patterns/README.md) | Паттерны **этого** проекта | Выводятся из кода при `tf-init` | нет |
| [`../team-review/threads/`](../team-review/threads/README.md) | Решения **этой** команды | Переносит человек из ревью | нет |

Практика говорит «обычно так». Паттерн говорит «здесь принято так».
Тред говорит «здесь принято так, потому что вот что случилось».

## Как читать пары

У каждой практики два блока кода. **Плохой блок — не карикатура**: это
код, который выглядит нормально, проходит ревью по невнимательности и
регулярно встречается в реальных наборах.

Под каждой парой стоит вопрос «что сломается» — конкретное поведение
системы, при котором плохой вариант остаётся зелёным. Это и есть проверка
практики на осмысленность: если такого поведения не назвать, практика
превращается в предпочтение.

Примеры на Python с pytest как на самом распространённом сочетании. Суть
языконезависима — переносится на любой раннер.

## Что здесь не лежит

Практики **разработки продукта** — не сюда. Это издание про тестовый
фреймворк; роли разработки и их практики живут в отдельном издании Pro,
sibling-папке исходного репозитория.
