# Стандарты — чему следовать

Шесть каталогов, отвечающих на вопрос «как здесь правильно». Они
различаются **силой** и **происхождением**, и это важнее, чем кажется:
при конфликте выигрывает то, что ближе к вашей команде.

## Порядок при конфликте

```
1. team-review/             решения ЭТОЙ команды из реальных ревью
2. context/projects/<p>/    факты и паттерны ЭТОГО проекта
3. practices/               общие практики автоматизации
4. общие практики кодирования
```

Конфликт разрешается сверху вниз. **Три исключения**, которые команда
переопределить не может: [`rules/40`](rules/40-verification-protocol.md)
(что считается доказательством), [`rules/50`](rules/50-data-handling.md)
(секреты и недоверенные данные) и
[`rules/60`](rules/60-agency-and-egress.md) (полномочия и выход наружу).
Остальные правила профиль и треды перебивают.

Эта лестница — единственная. Все прочие места ссылаются сюда, а не
пересказывают: четыре пересказа расходятся, и ревьюер получает разный
ответ в зависимости от того, что открыл.

## Что где

| Каталог | Что внутри | Откуда берётся | Переносится |
|---------|------------|----------------|-------------|
| [`team-review/`](team-review/README.md) | Треды из мержреквестов и проверяемые правила `CHECK-*`, выросшие из них | Человек переносит вручную | нет |
| [`patterns/`](patterns/README.md) | Паттерны этого проекта с примерами из его кода | Выводятся при `tf-init` | нет |
| [`practices/`](practices/README.md) | Практики автоматизации с парами «плохо / хорошо» | Заполнено заранее | да |
| [`rules/`](rules/README.md) | Обязательные правила: качество, доказательства, данные | Заполнено заранее | да |
| [`code/`](code/README.md) | Практики кода самого фреймворка: слои, клиенты, фикстуры | Заполнено заранее | да |
| [`test-cases/`](test-cases/README.md) | Формат тест-кейса и три разобранных примера | Заполнено заранее | да |

## Граница practices и code

Оба каталога про качество, но про разные объекты:

| | Объект | Отвечает на вопрос |
|---|---|---|
| `practices/` | Сам тест | Что делает проверку настоящей |
| `code/` | Код вокруг теста | Как устроена инфраструктура под ним |

Фикстуры лежат на границе и принадлежат `code/`: это механизм. В
`practices/` остаётся то, что видно в теле теста — какие значения он
подаёт и почему.

Дублировать нельзя: копии расходятся молча, правят одну, вторая
продолжает учить старому.

## Как отличить одно от другого

Один и тот же совет может лежать в трёх местах, и разница в том, **чем
он подкреплён**:

```
practice   «обычно делают так»            — общий опыт
pattern    «здесь делают так»             — пример из вашего кода
thread     «здесь делают так, потому что» — разбор случая, который был
```

Тред сильнее паттерна, потому что содержит причину и границы. Паттерн
сильнее практики, потому что взят из вашего репозитория, а не из общих
представлений.
