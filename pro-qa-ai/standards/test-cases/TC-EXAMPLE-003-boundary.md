# TC-EXAMPLE-003 — Границы допустимой суммы заказа

## Описание

Проверяем поведение на краях диапазона сумм. Ошибка на единицу —
самая частая в проверках пределов, и середина диапазона её не ловит:
значение 500 проходит и при строгом сравнении, и при нестрогом, и при
сдвинутом на единицу.

## Требование

> Сумма заказа принимается в диапазоне от 1 до 1 000 000 включительно.
> Значение вне диапазона отклоняется с кодом 400 и указанием поля
> `amount` в теле ошибки.

`specs/orders.md` §2.2

## Предусловия

1. Существует пользователь с ролью `customer` и действительным токеном
2. Сервис заказов доступен

## Тестовые данные

Шесть значений вокруг двух границ. Каждое — представитель своего класса,
лишних нет.

| `amount` | Класс | Ожидание | Почему именно это |
|----------|-------|----------|-------------------|
| `0` | ниже минимума | 400 | Ноль — типичное значение по умолчанию, попадает часто |
| `1` | минимум | 201 | Нижняя граница включительно |
| `2` | минимум + 1 | 201 | Отделяет включительную границу от исключительной |
| `999999` | максимум − 1 | 201 | Подтверждает, что предел не сдвинут вниз |
| `1000000` | максимум | 201 | Верхняя граница включительно |
| `1000001` | максимум + 1 | 400 | Первое отклоняемое значение |

Значения из середины диапазона не включены намеренно: они проверяются
позитивным кейсом TC-EXAMPLE-001 и здесь ничего не добавляют.

## Шаги

| # | Действие | Ожидание на шаге |
|---|----------|------------------|
| 1 | Для каждого значения из таблицы выполнить `POST /orders` с этим `amount` | Код ответа совпадает с колонкой «Ожидание» |
| 2 | Для значений с ожиданием 400 прочитать тело ошибки | Поле `errors[].field` равно `amount` |
| 3 | Для значений с ожиданием 201 прочитать `amount` в теле | Совпадает с отправленным без округления |

## Ожидаемый результат

Все шесть значений обработаны согласно таблице: границы включительно
принимаются, соседние снаружи отклоняются с указанием поля `amount`.

Шаг 2 существен: код 400 возвращается и при отсутствии обязательного
поля, и при неверном типе. Без проверки поля в теле кейс не отличает
отказ по границе от отказа по другой причине.

## Постусловия

Заказы, созданные для значений с ожиданием 201 (четыре штуки), удаляются.

## Границы кейса

Не проверяет: тип значения (строка вместо числа), отрицательные суммы,
дробную часть за пределами точности, поведение при отсутствии поля
целиком — это отдельные классы валидации.
