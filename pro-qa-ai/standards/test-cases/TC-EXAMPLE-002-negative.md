# TC-EXAMPLE-002 — Отказ доступа к чужому заказу

## Описание

Проверяем, что заказ виден только его владельцу, и что система различает
две причины отказа: «не знаем, кто ты» и «знаем, но нельзя».

Различие существенно для клиента: на 401 он отправляет пользователя
авторизоваться, на 403 показывает сообщение об отсутствии прав. Если
система отвечает одинаково, интерфейс ведёт себя неверно в одном из двух
случаев.

## Требование

> Чтение заказа доступно только пользователю, который его создал. Запрос
> без действительного токена возвращает 401, запрос с действительным
> токеном другого пользователя — 403. Тело ответа при отказе не содержит
> данных заказа.

`specs/orders.md` §4.3

## Предусловия

1. Существует пользователь A с заказом в любом статусе
2. Существует пользователь B, не связанный с этим заказом
3. Токен пользователя B действителен и не истёк

## Тестовые данные

| Параметр | Значение | Почему именно это |
|----------|----------|-------------------|
| `order_id` | идентификатор заказа пользователя A | Существующий заказ; несуществующий даёт 404 и проверяется отдельно |
| токен B | действительный токен другого пользователя | Проверяем отказ по правам, а не по авторизации |
| токен отсутствует | заголовок не передаётся | Проверяем отказ по авторизации |

Заказ обязан **существовать**: на несуществующем 403 и 404 неразличимы, и
кейс перестал бы проверять права.

## Шаги

| # | Действие | Ожидание на шаге |
|---|----------|------------------|
| 1 | `GET /orders/{order_id}` с токеном пользователя B | Ответ 403 |
| 2 | Прочитать тело ответа шага 1 | Данных заказа нет: ни суммы, ни состава, ни владельца |
| 3 | `GET /orders/{order_id}` без заголовка авторизации | Ответ 401 |
| 4 | `GET /orders/{order_id}` с токеном пользователя A | Ответ 200 — контроль, что заказ читается вообще |

## Ожидаемый результат

Чужой пользователь получает 403, анонимный — 401, владелец — 200; тело
ответа при отказе не раскрывает содержимое заказа.

Шаг 4 обязателен: без него кейс проходит и в ситуации, когда заказ
недоступен вообще никому — например, если он удалён или сервис сломан.

## Постусловия

Нет. Кейс только читает.

## Границы кейса

Не проверяет: истёкший токен (отдельный кейс), заказ несуществующий
(404), доступ администратора, отзыв прав в процессе сессии.
