# Ошибки и диагностика падений

Падение обязано объяснять себя. Разбор, начинающийся с воспроизведения,
стоит в разы дороже.

## 1. Падение фреймворка отличимо от падения теста

Плохо: и то и другое — обычная ошибка утверждения.

Хорошо: свой тип ошибки для инфраструктуры.

```python
class FrameworkError(Exception):
    """Сломалась инфраструктура, а не проверяемое поведение."""
```

**Что сломается:** красный прогон читается как «продукт сломан», хотя не
поднялся стенд. Триаж уходит не туда, время тратится на продукт.

## 2. Сообщение содержит ожидание, факт и адрес

Плохо:

```python
assert response.status_code == 200
```

Хорошо:

```python
assert response.status_code == 200, (
    f"POST /orders вернул {response.status_code}, ожидали 200\n"
    f"request-id: {response.headers.get('x-request-id', 'нет')}\n"
    f"тело: {response.text[:300]}"
)
```

**Что сломается:** голое утверждение печатает «assert 500 == 200». Без
идентификатора запроса разработчик не найдёт след, и разбор начинается с
попытки повторить.

## 3. Контекст собирается при падении, а не всегда

Плохо: печатать состояние на каждом шаге — логи нечитаемы.

Хорошо: собрать снимок в момент падения — скриншот, HTML, последний URL,
логи консоли, сетевые запросы.

**Что сломается:** без снимка UI-падение разбирается вслепую: известно,
что элемент не найден, неизвестно, что было на экране.

## 4. Пустой обработчик запрещён

Плохо:

```python
try:
    api.cleanup(order)
except Exception:
    pass
```

Хорошо:

```python
try:
    api.cleanup(order)
except Exception as e:
    logger.warning("очистка заказа %s не удалась: %s", order.id, e)
```

**Что сломается:** очистка перестала работать месяц назад, окружение
забито, никто не знает. Проглоченная ошибка не исчезает, а откладывается.

## 5. Ошибка не теряет причину

Плохо: перевозбудить новую ошибку с текстом исходной — теряется тип и
трассировка.

Хорошо: сохранять исходное исключение как причину.

**Что сломается:** место возникновения потеряно, в отчёте виден только
верхний уровень.

## 6. Таймаут говорит, чего ждали

Плохо: `TimeoutError: timeout`

Хорошо: `TimeoutError: заказ 42 не перешёл в paid за 30 с; последний статус pending`

**Что сломается:** первый вариант не отличает «система медленная» от
«система застряла в другом состоянии», а это разные дефекты.

## Проверка себя

Прочитай текст своей ошибки глазами человека, который увидит её в CI
через неделю. Поймёт он, что произошло и куда идти? Нет — сообщение
неполное.
