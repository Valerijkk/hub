# Page/Component Objects — только при повторяемом UI-знании

Для маленького flow начинай с plain semantic locators прямо в тесте. Page Object
нужен, когда services/locators страницы повторяются и меняются вместе;
Component Object — для повторяемого самостоятельного widget. Объект моделирует
пользовательскую услугу, а не просто переименовывает `click`.

Это encouraged pattern Selenium и один из допустимых approaches Playwright, а
не обязательный слой для каждого URL. Giant `AppPage` и `BasePage` по умолчанию
запрещены как God objects.

## 1. Проверка остаётся в тесте

Плохо:

```python
class OrderPage:
    def check_total(self, expected):
        assert self.text("[data-testid=total]") == expected
```

Хорошо:

```python
class OrderPage:
    @property
    def total(self) -> str:
        return self.text("[data-testid=total]")

# в тесте
assert order_page.total == "1 500"
```

**Что сломается:** при падении `check_total` в отчёте видно имя метода, а
не ожидаемое и фактическое значение. Плюс страницу нельзя переиспользовать
там, где ожидается другое значение или отсутствие элемента.

## 2. Локаторы — по пользовательскому контракту

Плохо: `div.container > div:nth-child(3) > button.btn-primary`

Хорошо для Playwright: `page.get_by_role("button", name="Оформить")`.
Если доступного пользовательского контракта нет — явный стабильный
`data-testid`, а не DOM-chain.

**Что сломается:** поменяли вложенность или класс — тест падает при
работающей функциональности. Такие падения приучают чинить не разбираясь.

Role/name/label одновременно проверяют наблюдаемый пользователем контракт.
Тестовый атрибут — запасной явный контракт между разработкой и автоматизацией.

## 3. Component Object вместо огромной страницы

Повторяемый самостоятельный участок UI — header, modal, table row, editor —
становится Component Object, rooted в своём locator и композиционно включённым
в Page Object.

```python
class ProjectRow:
    def __init__(self, root):
        self.root = root

    def open(self):
        self.root.get_by_role("link").click()
```

Компонент не ищет глобально по `page` и не наследует бизнес-методы страницы.
Это локализует редизайн одной карточки и не создаёт монолитный `BasePage`.

## 4. Действие может вернуть детерминированный observable result

Плохо:

```python
def submit(self):
    self.click("[data-testid=submit]")
```

Хорошо:

```python
def submit(self) -> "ConfirmationPage":
    self.click("[data-testid=submit]")
    return ConfirmationPage(self.page)
```

**Что сломается:** тест сам создаёт следующую страницу и может ошибиться,
не дождавшись перехода. Возврат объекта фиксирует ожидаемый маршрут в
одном месте.

Destination object — удобная форма, не обязательный ritual. Возвращать его
можно только при детерминированном переходе. Если результат ветвится, действие
возвращает observable result, а решение остаётся в тесте.

## 5. Ожидание — внутри объекта и по состоянию

Плохо: пауза фиксированной длины после клика либо ожидание, поставленное
в теле теста.

Хорошо: метод страницы возвращает управление, когда страница готова, —
дождавшись появления элемента, текста, завершения запроса.

**Что сломается:** ожидание, размазанное по тестам, разъезжается: в одном
месте есть, в другом забыли, и флейк появляется там, где забыли. Пауза
плоха вдвойне: на медленной машине не хватит, на быстрой потратится
впустую. UI особенно чувствителен — анимации, догрузка, повторный рендер.

Почему пауза не заменяет ожидание условия нигде, не только в UI, —
[`../practices/determinism.md`](../practices/determinism.md) §1.

## 6. Страница не лезет в API и базу

Плохо: `OrderPage.create_order_via_api()` для подготовки состояния.

Хорошо: подготовка — сценарием через API, страница только отображает.

**Что сломается:** объект страницы становится всем сразу, и падение не
локализуется: непонятно, сломался UI или подготовка.

## Проверка себя

- Повторяется ли UI-знание настолько, что объект реально локализует изменение?
- Plain role/name locator сделал бы сценарий понятнее без дополнительного слоя?
- Assertion конкретного test oracle остался в тесте?
- Component ищет только внутри своего root?
