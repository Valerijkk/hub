# Конфигурация и окружения

Конфигурация отвечает на вопрос «где и с чем работаем». Всё, что зависит
от окружения, приходит отсюда — и никак иначе.

## 1. Значение из конфига, не из литерала

Плохо:

```python
wait_until(lambda: ..., timeout=5)
```

Хорошо:

```python
wait_until(lambda: ..., timeout=env.external_wait_timeout)
```

**Что сломается:** на стенде интеграции внешний сервис отвечает втрое
дольше, ночной прогон краснеет. Поставить большое значение везде — значит
замедлить все падения на ту же величину.

## 2. Отсутствие обязательного параметра — падение на старте

Плохо: значение по умолчанию для адреса стенда.

Хорошо: не задан — прогон не начинается, с понятным сообщением.

**Что сломается:** молчаливый дефолт направит прогон в чужое окружение. В
худшем случае тесты отработают по чужим данным и что-то в них изменят.

## 3. Секреты только из окружения

Плохо: токены и пароли в файле конфигурации в репозитории.

Хорошо: из переменных окружения или хранилища секретов; в репозитории —
только имена переменных и пример без значений.

**Что сломается:** секрет, попавший в историю, простым коммитом оттуда не
убирается.

## 4. Конфиг читается один раз и не мутирует

Плохо: тест меняет значение конфига под себя.

Хорошо: параметр передаётся явно тому, кому он нужен.

**Что сломается:** тест, изменивший общий конфиг, ломает соседей —
особенно при параллельном прогоне, где порядок непредсказуем.

## 5. Профиль окружения целиком, а не по кусочкам

Плохо: половина значений из одного окружения, половина из другого,
потому что переопределили только часть.

Хорошо: именованный профиль, переключаемый одним параметром.

**Что сломается:** смешанная конфигурация даёт прогон, который не
воспроизводится: адрес одного стенда, таймауты другого.

## 6. Фактическая конфигурация печатается в начале прогона

Плохо: неизвестно, с какими значениями шёл прогон.

Хорошо: в лог выводится окружение, адрес, таймауты, версия — **без
секретов**.

**Что сломается:** разбор падения из CI начинается с вопроса «против чего
это гоняли», и ответа нет.

## Проверка себя

Возьми лог прогона и ответь: **против какого окружения он шёл и с какими
таймаутами**. Не ответить — конфигурация непрозрачна, и разбор любого
падения будет начинаться с этого вопроса.
