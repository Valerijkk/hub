# Техники тест-дизайна

Как из бесконечного пространства входов выбрать конечный набор, ловящий
максимум дефектов. Шесть техник, каждая с признаком применимости.

## Зачем техники, если можно «придумать кейсы»

Придуманный набор покрывает то, что первым пришло в голову, а дыры
всплывают в проде. Проход по техникам делает пропуск **видимым**: техника
либо применена, либо помечена неприменимой с причиной.

## 1. Классы эквивалентности

**Когда:** вход делится на группы, внутри которых система ведёт себя
одинаково.

Пример — тип задачи из девяти допустимых значений:

```
валидный класс      любой из девяти → достаточно одного представителя
невалидный класс    всё остальное   → достаточно одного представителя
```

**Что даёт:** вместо перебора девяти значений — два теста. Экономия не
самоцель: короткий набор гоняют чаще.

**Ловушка:** классы выделены неверно, если внутри «одинакового» поведение
различается. Признак — один представитель проходит, другой из того же
класса падает.

## 2. Граничные значения

**Когда:** есть числовой, размерный или временной предел.

```
минимум − 1   отклоняется
минимум       принимается
минимум + 1   принимается
максимум − 1  принимается
максимум      принимается
максимум + 1  отклоняется
```

**Что даёт:** ловит ошибку на единицу — самую частую в проверках
пределов. Значение из середины проходит и при строгом сравнении, и при
нестрогом, и при сдвинутом.

**Ловушка:** проверять только одну сторону границы. Обе стороны каждой
границы, иначе сдвиг в одну сторону остаётся невидимым.

### Обязательное следствие: параметр-лимит

Техника выше — рекомендация. Из неё есть **обязательное** следствие: если у
кода есть параметр вида лимит, квота, бюджет, порог, размер окна — фикстуры
обязаны покрыть три точки:

```
N = лимит − 1     ниже порога, поведение обычное
N = лимит         на пороге — здесь чаще всего и ошибаются
N = лимит + 1     за порогом, поведение меняется
```

Правило не про аккуратность, а про конкретный класс дефекта: логика,
срабатывающая «при приближении к лимиту», живёт ровно в этой области, и
набор, проверяющий только «мало» и «очень много», её не задевает вообще.
Тесты зелёные, поведение на пороге не проверялось ни разу.

Один параметр — три фикстуры. Два независимых параметра — не девять
комбинаций, а три на каждый плюс одна совместная, если они влияют друг на
друга.

## 3. Таблица решений

**Когда:** результат зависит от нескольких условий совместно.

| Авторизован | Владелец | Заказ активен | Ожидание |
|---|---|---|---|
| нет | — | — | 401 |
| да | нет | — | 403 |
| да | да | нет | 409 |
| да | да | да | 200 |

**Что даёт:** видно комбинации, о которых забывают. Прочерк означает «не
проверяется, потому что не влияет» — и это тоже решение, записанное явно.

**Ловушка:** заполнять все комбинации механически. Строки, недостижимые
по логике системы, помечаются, а не тестируются.

## 4. Переходы состояний

**Когда:** у объекта есть жизненный цикл.

```
новый → оплачен → отправлен → доставлен
  ↓        ↓
отменён  возврат
```

Проверяются: разрешённые переходы, **запрещённые переходы**, действия в
конечных состояниях.

**Что даёт:** запрещённые переходы почти никогда не покрыты — а именно
они ломают данные. «Отменить доставленный», «оплатить отменённый».

**Ловушка:** покрыть только счастливый маршрут по цепочке. Он один, а
запрещённых переходов — десятки.

## 5. Попарное покрытие

**Когда:** много независимых параметров, полный перебор нереален.

Три параметра по четыре значения — 64 комбинации. Попарное покрытие даёт
16 и ловит дефекты, зависящие от **пары** параметров, — а таких
большинство.

**Что даёт:** сокращение прогона без потери находок на парах.

**Ловушка:** дефект, зависящий от тройки параметров, попарное покрытие не
поймает. Если такие известны — они добавляются явными комбинациями.

## 6. Предугадывание ошибок

**Когда:** есть опыт с этой системой или этим классом систем.

Типовые кандидаты: пустое значение, ноль, отрицательное, очень длинное,
спецсимволы, юникод, одновременный доступ, повтор запроса, разрыв связи
посередине.

**Что даёт:** ловит то, что не выводится из спецификации. Здесь особенно
полезны треды команды — они и есть накопленный опыт по этому продукту.

**Ловушка:** техника неформальна и не заменяет остальные пять. Она их
дополняет.

## Как применять

```
1. Пройти по всем шести техникам
2. Для каждой: применена → кейсы; неприменима → причина
3. Пропуск без причины = дыра, а не решение
```

Молчание неотличимо от забывчивости. Именно поэтому «неприменима»
пишется словами, а не оставляется пустым.

## Проверка себя

Возьми готовый набор кейсов и спроси про каждую технику: **применялась
она или была признана неприменимой**. Не можешь ответить — набор
придуман, а не спроектирован.
