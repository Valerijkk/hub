# Сьюты: как разделять и что где запускать

Тесты делятся не по слоям приложения, а по **цене прогона**. Разделение по
слоям выглядит логично, но отвечает не на тот вопрос: перед мержем нужно
знать не «это юнит или интеграция», а «сколько ждать и что здесь падает
из-за окружения».

## Маркер в имени файла, а не каталог

```
checkout.test.py                   быстрый — по умолчанию
checkout.integration.test.py       несколько модулей вместе
checkout.security.test.py          враждебный вход
checkout.slow.test.py              дольше ~5 секунд
```

Файл без маркера попадает в быстрый сьют. Это правильный дефолт:
забывчивость приводит к тому, что тест гоняется чаще, а не реже.

Почему суффикс, а не каталог:

| | Суффикс в имени | Отдельный каталог |
|---|---|---|
| Тест рядом с соседями по фиче | да | нет, уезжает в другое дерево |
| Смена сьюта | переименование | перемещение плюс правка импортов |
| Видно из списка файлов | да | только по пути |
| Выборка одной командой | по маске | по каталогу, тоже можно |

Главный довод — первый. Тест, уехавший в `tests/integration/`, теряет
соседство с тем, что проверяет, и его перестают замечать при правке фичи.

## Что в каком сьюте

| Сьют | Что туда | Чего там быть не должно |
|------|----------|-------------------------|
| Быстрый | Чистая логика, без сети и внешних процессов | Любое ожидание дольше секунды |
| Интеграционный | Несколько модулей вместе, реальная БД или очередь | Полный пользовательский сценарий через UI |
| Установочный | Настоящая установка и удаление в песочнице | Всё, что можно проверить дешевле |
| Безопасность | Враждебный вход, инъекции, обход проверок | Обычные негативные кейсы — они в быстром |
| Медленный | Дольше ~5 секунд либо тяжёлый по памяти | Тест, ставший медленным случайно |

Последняя строка важнее остальных. Медленный сьют — это место для тестов,
которые **обязаны** быть медленными: нагрузка, объёмные данные, реальные
задержки. Тест, попавший туда потому, что кто-то поставил паузу, —
не медленный, а сломанный, и переносить его сюда значит спрятать проблему.

## Что гоняется на каждом изменении

```
на мержреквесте     быстрый + интеграционный + безопасность
на главной ветке    всё, включая установочный и медленный
```

Смысл разделения — держать обратную связь на мержреквесте в минутах.
Установочный и медленный сьюты дают ценность, но не на каждом коммите: их
падение почти всегда про окружение, а не про изменение автора.

**Обратная сторона названа явно:** это осознанный риск. Дефект, который
ловится только установочным сьютом, будет найден после мержа, а не до.
Приемлемо, пока установочный сьют гоняется на главной ветке и его падение
разбирается сразу, а не копится.

## Форвард-совместимость

Тест на новой версии рантайма утверждает на **структурированном**: код
ошибки, поля, JSON. Совпадение текста сообщения при смене версии ломается
первым, и разбирать такое падение приходится вручную, хотя поведение не
менялось.

Подробнее — [`../practices/assertions.md`](../practices/assertions.md) §8.

## Проверка себя

- Каждый новый тест получил маркер сьюта либо осознанно остался быстрым?
- Ни один тест не попал в медленный сьют из-за паузы внутри?
- На мержреквесте гоняется то, что относится к изменению автора?
- Падение установочного сьюта на главной ветке разбирается, а не копится?
