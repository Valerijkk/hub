# Чистый код: понять и безопасно изменить

Чистота кода — не стиль и не количество паттернов. Код чистый, если инженер,
который не писал его, быстро отвечает на четыре вопроса:

1. Что этот код обещает?
2. От чего он зависит и какие побочные эффекты создаёт?
3. Где находится причина текущего поведения?
4. Какое минимальное изменение нужно и чем доказать, что соседнее не сломано?

## Когда применять

Всегда — к тестам, клиентам, фикстурам, Page/Component Objects, валидаторам и
скриптам. Конкретный приём выбирается по стоимости изменения, а не по моде.

## Когда НЕ применять буквально

Нельзя «улучшать чистоту» механическим дроблением, интерфейсом с одной
реализацией или переименованием без изменения понимания. Если после рефакторинга
нужно открыть больше файлов, чтобы увидеть одно поведение, локальность стала
хуже.

## BAD

```python
def process(data, api, cache, cfg):
    # нормализует, логинится, создаёт заказ, повторяет запрос и проверяет ответ
    ...
```

## Почему плохо

Имя не раскрывает результат, четыре вида ответственности смешаны, I/O скрыт.
Изменение retry может задеть нормализацию и oracle; падение не сообщает слой.

## GOOD

```python
request = normalize_order(raw_order)
order = orders.create(request, timeout=settings.order_timeout)
assert order.status == "new"
```

Механика клиента и чистое преобразование меняются независимо, а бизнес-oracle
виден в тесте. Для понимания сценария не надо переходить по цепочке helpers.

## Почему легче изменить

- имена описывают намерение и результат;
- зависимости переданы явно;
- side effect находится на границе;
- assertion остаётся рядом с требованием;
- изменение локально и имеет короткую проверку.

## Trade-offs

Три строки не обязаны стать тремя слоями и интерфейсами. Абстракция оправдана,
когда у неё есть стабильный контракт, повторяемая механика или вторая реализация.
В теле теста DAMP-читаемость важнее устранения небольшого повторения.

## Review checks

- Поведение понятно по public contract и тесту, без чтения реализации?
- У функции одна причина измениться?
- Side effects, time, random, network и state переданы явно?
- Ошибка говорит, какой слой и какое ожидание нарушены?
- Можно изменить одно правило без каскадной правки несвязанных файлов?
- Новый слой уменьшил, а не увеличил число переходов для понимания?
