# Утилиты, ожидания, сравнения

Хелпер экономит строки. Если он экономит понимание — он вредит.

## 1. Хелпер не прячет утверждение

Плохо:

```python
def assert_order_ok(order):
    assert order["status"] == "new"
    assert order["total"] > 0
    assert order["items"]
```

Хорошо:

```python
def test_new_order_starts_in_new_status(api, token):
    order = create_order(api, token, amount=100)
    assert order["status"] == "new"
```

**Что сломается:** сообщение «assert_order_ok упал» не говорит, какое из
трёх утверждений сработало. И тест, которому нужен другой статус,
хелпером воспользоваться не может.

## 2. Ожидание принимает предикат, а не знает про домен

Плохо: отдельная функция ожидания на каждый объект — заказ, пользователь,
платёж.

Хорошо:

```python
def wait_until(predicate, *, timeout, interval=0.2, message=""):
    ...

wait_until(lambda: api.get(order.id).status == "paid",
           timeout=env.payment_timeout,
           message=f"заказ {order.id} не оплачен")
```

**Что сломается:** на каждый новый объект пишется своё ожидание, и они
расходятся по таймаутам и интервалам. Одно параметризуемое даёт одно
поведение везде.

Поле `message` обязательно: без него падение выглядит как «timeout» без
указания, чего ждали.

## 3. Сравнение объектов — с понятной разницей

Плохо: сравнение двух больших словарей одним утверждением.

Хорошо: сравнение по значимым полям либо инструмент, показывающий
конкретное расхождение.

**Что сломается:** отчёт печатает два объекта по двести строк, и глазами
искать различие дороже, чем воспроизвести падение.

## 4. Утилита без побочных эффектов

Плохо: функция, которая заодно логинится, кеширует токен и правит
глобальный конфиг.

Хорошо: чистая функция, состояние передаётся явно.

**Что сломается:** порядок вызовов начинает влиять на результат. Такие
зависимости находят последними.

## 5. Обобщать на третьем повторе, не на первом

Два похожих куска — совпадение. Три — паттерн.

**Что сломается:** обобщение по двум случаям даёт хелпер с флагами,
обслуживающими два разных сценария в одном теле. Читать его тяжелее, чем
два прямолинейных куска.

## 6. Имя говорит, что вернётся

Плохо: `check_user(...)` — проверяет? возвращает? делает и то и другое?

Хорошо: `get_user(...)`, `create_user(...)`, `wait_for_user(...)`.

**Что сломается:** вызывающий не понимает, надо ли использовать
результат, и появляются вызовы на всякий случай без присваивания.

## Проверка себя

Открой хелпер и спроси: **сколько причин у него упасть**. Больше одной —
при падении придётся расследовать, какая сработала.
