# Проверяемые правила команды

Правило `CHECK-NNN` отвечает на вопрос **что проверять**. Тред, из
которого оно выросло, отвечает на **почему**.

Ревьюер применяет правило; тред открывает, когда надо понять причину или
объяснить автору, что замечание не вкусовщина.

| ID | Правило | Severity | Тред | Повторов |

## Порядок применения

Правила сортируются по колонке «Повторов»: сначала то, на чём команда
спотыкается чаще. Прилетевшее седьмой раз важнее разового — это
системная проблема, а не случай.

## Форма правила

По [CHECK-TEMPLATE.md](CHECK-TEMPLATE.md). Обязательны четыре части:

```
Правило        что должно выполняться, одним предложением
Как обнаружить проверяемый признак, где возможно — команда поиска
Границы        когда правило НЕ применяется
Тред           ссылка на разбор случая
```

**Границы обязательны.** Правило без них срабатывает там, где не должно,
и его обходят целиком вместо того, чтобы уточнить.

## Как правило появляется

```
тред в threads/inbox/
      ↓ tf-curate
обезличивание, выделение правила, проверка на дубль
      ↓
threads/approved/THREAD-NNN + checks/CHECK-NNN + строки в обоих реестрах
```

Дубль не создаётся: если такое замечание уже разобрано, растёт счётчик
повторов существующего правила. Дубли ломают сортировку по частоте, а
она и есть главная ценность счётчика.

## Как правило умирает

Правило со `status: superseded` остаётся в реестре с указанием, чем
заменено. Удалять нельзя: через полгода кто-то предложит то же самое, и
без записи спор начнётся заново.

Отменённое правило — тоже знание.
