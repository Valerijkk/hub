# THREAD-003 — Общая фикстура с изменяемым состоянием

## Контекст

Набор тестов на корзину. Автор вынес создание пользователя в фикстуру
уровня модуля, чтобы не создавать его в каждом тесте. Локально проходило,
в CI с параллельным прогоном начались плавающие падения.

## Код, вызвавший обсуждение

```python
@pytest.fixture(scope="module")
def user(api):
    return api.create_user()

def test_add_item(api, user):
    api.cart_add(user, item_id=1)
    assert len(api.cart_get(user)["items"]) == 1

def test_clear_cart(api, user):
    api.cart_add(user, item_id=2)
    api.cart_clear(user)
    assert api.cart_get(user)["items"] == []
```

## Тред

**Ревьюер:**
> Оба теста пишут в корзину одного пользователя. Порядок сейчас случайно
> удачный: если очистка отработает первой, второй тест увидит только свой
> товар и пройдёт. При параллельном прогоне увидит два и упадёт.

**Автор:**
> Создавать пользователя в каждом тесте дорого, это лишние 200 мс.

**Ревьюер:**
> Дороже разбирать плавающее падение раз в неделю. Если создание правда
> дорогое — оставь фикстуру модуля, но чисти состояние после каждого
> теста, тогда изоляция восстанавливается.

## Чем закончилось

Договорились: фикстура шире функции допустима **только** для неизменяемых
объектов. Всё, во что тест пишет, либо создаётся на тест, либо чистится
после него.

## Как стало

```python
@pytest.fixture(scope="module")
def user(api):
    return api.create_user()

@pytest.fixture(autouse=True)
def clean_cart(api, user):
    yield
    api.cart_clear(user)

def test_add_item(api, user):
    api.cart_add(user, item_id=1)
    assert len(api.cart_get(user)["items"]) == 1
```

## Почему так, а не иначе

Общее правило «тесты должны быть изолированы» не подсказывает, где
проходит граница. Здесь она сформулирована точно: **дорогое создание
переиспользовать можно, изменяемое состояние — нет**.

Отдельно про очистку: она стоит после `yield`, то есть выполняется и при
падении теста. Очистка последней строкой тела теста при падении ассерта
не сработает и оставит грязь следующему.

## Границы

Не относится к фикстурам, которые только читают: конфиг, справочники,
предзаполненные каталоги. Не относится к случаям, где проверяемое
требование — именно накопление состояния между шагами; там сценарий
должен быть одним тестом, а не несколькими.

## Что проверять

Фикстура со scope шире функции, в которую хотя бы один тест пишет.
Признак: объявление scope module, session или class рядом с объектом,
который передаётся в вызовы записи.
