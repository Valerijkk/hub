# THREAD-002 — Код ответа без тела не считается покрытием

## Контекст

Пачка API-тестов на новый эндпоинт выдачи списка заказов. Все зелёные,
покрытие по отчёту выросло. Через неделю на проде обнаружили, что ручка
возвращала пустой список для части пользователей — тесты не заметили.

## Код, вызвавший обсуждение

```python
def test_get_orders_returns_200(api, user_with_orders):
    response = api.get("/orders", user=user_with_orders)
    assert response.status_code == 200
```

## Тред

**Ревьюер:**
> Этот тест пройдёт, если ручка вернёт пустой массив, вернёт чужие заказы
> или вернёт заказы в другой структуре. Мы проверили, что сервер жив,
> а не что ручка работает.

**Автор:**
> Структуру проверяет контрактный тест по схеме, не хотел дублировать.

**Ревьюер:**
> Схема проверяет форму, а не содержимое. Что у пользователя с тремя
> заказами вернулись именно его три — схема не знает. Это и был баг.

## Чем закончилось

Тимлид зафиксировал как блокирующее правило после разбора инцидента.
Пересмотру в рабочем порядке не подлежит.

## Как стало

```python
def test_get_orders_returns_only_own_orders(api, user_with_orders, other_user):
    response = api.get("/orders", user=user_with_orders)

    assert response.status_code == 200
    returned_ids = {o["id"] for o in response.json()["items"]}
    assert returned_ids == {o.id for o in user_with_orders.orders}
    assert other_user.orders[0].id not in returned_ids
```

## Почему так, а не иначе

Общая практика «проверяй ответ» слишком расплывчата, чтобы что-то менять.
Здесь конкретный урок из инцидента: **код ответа не отличает работающую
ручку от сломанной**, а схема не отличает свои данные от чужих.

Отдельно: последняя строка проверяет, что чужого не вернулось. Утечка
чужих данных не ловится проверкой «мои есть» — только проверкой
«чужих нет».

## Границы

Не относится к тестам, где проверяемое требование и есть код ответа:
401 без токена, 404 на несуществующий идентификатор, 413 на превышение
размера. Там тело может быть не важно — но причина отказа в теле
проверяется, если она документирована.

## Что проверять

Тест API, в котором единственное обращение к ответу — это код статуса.
Признак: в теле теста нет ни разбора JSON, ни обращения к полям ответа.
