# Демо для руководителя — 15 минут

## Цель

Показать не «красивый промпт», а управляемый цикл:

1. AI получает факты конкретного тестового фреймворка.
2. Использует одобренные project patterns.
3. Работает в явных границах.
4. Возвращает evidence.
5. Эффект можно измерить относительно baseline.

## Подготовка

- Валидатор структуры даёт экзит-код `0`.
- Сгенерированный профиль проекта просмотрен владельцем фреймворка.
- Используются только синтетические или разрешённые данные.
- Если показывается реальный тред коллеги — он перенесён человеком,
  обезличен и одобрен.
- Метрики замера до прогона остаются `NOT_RUN` и такими и показываются.

## Сценарий

### 0–2 мин — проблема

Показать голый фрагмент из `workflows/prompts/`: без контекста проекта он
не знает реальных путей, команд, фикстур и принятого стиля.

### 2–5 мин — bootstrap

Показать вызов:

```text
/bootstrap-test-context
project_root=<repo>
test_roots=<tests>
profile=<name>
```

Открыть собранное:

- `CONTEXT-MANIFEST.yaml`;
- `TEST-ARCHITECTURE.md`;
- `COMMANDS.md` со статусом `not-run`;
- `SOURCE-MAP.md`;
- `PATTERN-INDEX.md`.

Акцент: сбор идёт только на чтение, не ходит в мержреквесты, сеть и
секреты и не запускает найденные команды просто потому, что нашёл их.

### 5–7 мин — знания коллег

Открыть `standards/team-review/threads/THREAD-TEMPLATE.md`. Объяснить:

- человек вручную вставляет код как был, реплику коллеги и чем кончилось;
- `tf-curate` не выдумывает пропущенное;
- область по умолчанию — только этот проект;
- нормативным становится правило `CHECK-NNN`, а не сырой тред.

Реального разрешённого примера нет — показать шаблон. Не подменять его
искусственным «успехом»: демо на выдуманном кейсе разваливается на
первом же вопросе.

### 7–10 мин — production recipe

Выбрать `workflows/recipes/review-ai-test-code.md` или `generate-api-tests.md`.
Показать:

- результат, ради которого рецепт существует;
- разрешённые файлы и инструменты;
- ссылки на контекст и паттерны;
- форма выхода;
- планка доказательства и критерий готовности;
- условия остановки и запроса разрешения.

Выбор модели пакет не делает — его задаёт среда запуска. В тексте
промпта нет идентификаторов моделей: они устаревают быстрее документов.

### 10–12 мин — проверки

```powershell
py -3 -B .\pro-qa-ai\scripts\validate_toolkit.py `
  --root .\pro-qa-ai

py -3 -B -m unittest discover `
  -s .\pro-qa-ai\scripts\tests `
  -p "test_*.py" -v
```

Показать фактический экзит-код и вывод. Скриншот вчерашнего PASS не
показывать: смысл демо в том, что проверка идёт при зрителях.

### 12–15 мин — измерение и решение

Открыть `standards/practices/coverage.md` и [`ROI-METRICS.md`](ROI-METRICS.md).
Объяснить парный замер и ворота решения.

Сказать прямо: замер **не прогонялся**, статус `NOT_RUN`. Это сильнее
любой цифры, которую нечем подтвердить.

## Вопросы, к которым быть готовым

**Это заменяет ревьюера?** Нет. Слой убирает поток повторяющихся
замечаний, чтобы на ревью говорили о содержательном. Решения с высокой
ценой ошибки остаются за человеком.

**Куда уходят наши исходники?** Никуда автоматически. Работа с сетью и
провайдером подчиняется политике данных
([`rules/50`](../standards/rules/50-data-handling.md)); материал проекта
не попадает в переносимый пакет без разрешения — это проверяет
упаковщик.

**Почему не обещаем ускорение в разы?** Потому что множитель зависит от
проекта, модели, задач и качества исходного процесса. Утверждать его
можно только после парного пилота.

**Что произойдёт при смене модели?** Ничего в пакете: он модель не
называет. Меняется среда запуска, после чего замер прогоняется заново.

## Успешное демо

- Руководитель понял, что слой управляет контекстом и проверяемостью, а
  не формулировками промптов.
- Каждый показанный PASS получен при зрителях.
- Не показаны секреты, закрытый код без разрешения и выдуманные метрики.
- Сформулировано следующее решение: объём пилота, владелец, дата,
  критерии приёмки.
