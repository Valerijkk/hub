# Playbook: документация фреймворка в синхроне

> Два режима: событийный (после каждого значимого изменения) и плановый (периодическая ревизия). Оба — через test-documenter; правда всегда в коде, доки догоняют.

Команда: `tf-refresh` для обновления карт контекста.

## Событийный режим (основной)

```
триггер: смержен diff, меняющий тестовый фреймворк
  (новый домен/сьют, реорганизация, смена раннера/флагов, новые фикстуры,
   изменение конвенций, автоматизация TC-пакета)
│
1. test-documenter (templates/docs-sync.md)
│    вход: diff + отчёты агентов по нему
│    обновляет затронутые зоны по своей таблице §2, точечно
│
2. Если изменение затрагивает КАНОН (конвенции, структура, команды):
│    дополнительно skills/refresh-test-context.md
│    (templates/context-refresh.md)
│    → context/projects/<profile>/ синхронизирован с новой реальностью
│
└─ 3. Сводка в артефакт изменения (PR/тикет): какие доки обновлены
```

Правило DoD: изменение фреймворка без обновления доков не закрывается — «код смержили, доки потом» превращает доки в архив вранья.

## Плановый режим (ревизия)

```
периодичность: раз в milestone / крупную волну (настраивается проектом)
│
1. Верификация фактов всех доков зоны ответственности:
│    команды — прогнать, пути — проглобить, числа — пересчитать
│    (это режим работы test-documenter §3.3, применённый ко ВСЕМУ, а не к diff)
│
2. Расхождения: док прав/код прав? → каждое расхождение — решение:
│    правится док ИЛИ заводится тикет на код (документатор код не чинит)
│
3. skills/refresh-test-context.md для активного profile
│
└─ 4. Ревизионный отчёт: проверено / исправлено / тикеты
```

## Карта «изменение → док» (дефолтная, проект дополняет)

| Изменение | Обновить |
|-----------|----------|
| Новый домен/сьют тестов | `TEST-ARCHITECTURE.md` § Test topology |
| Новая фабрика/фикстура/хелпер | Гайд уровня, `TEST-ARCHITECTURE.md` § Framework components, `TEST-DATA.md` |
| Смена команд/флагов запуска | `COMMANDS.md`, `CI-PIPELINE.md`, CI-доки проекта |
| Изменение конвенции нейминга | `TEST-ARCHITECTURE.md` § Organization, `TRACEABILITY.md`, changelog фреймворка |
| Автоматизирован TC-пакет | TC-каталог (TC ↔ тест), матрица покрытия |
| Прогон coverage | Coverage-док проекта |
| Новый антипаттерн из дебага | Evidence в profile; card только через отдельные `curate-review-feedback` → `curate-pattern-cards` gates |
