## Фабрики и билдеры

1. Напиши фабрику {{сущность}} по active profile `TEST-DATA.md` и approved card: валидные дефолты всех полей, override отдельных полей, возврат готового объекта; минимально валидный экземпляр — базовый случай.
2. Построй билдер связного графа {{сущности}}: создаёт родителя с детьми и валидными связями за один вызов, возвращает хэндлы на каждый узел для ассертов, уникальные ключи для параллельного прогона.
3. Отрефактори раздутые Arrange в {{файл}} (по 30+ строк установки полей) в вызовы фабрики с override только релевантных кейсу полей — покажи дифф до/после для одного теста.
4. Спроектируй набор именованных фабрик состояний {{сущность}}: `active`, `expired`, `blocked`, `pending` — каждая делает override валидного базового, невалидность выражена явно, а не отдельной кривой фабрикой.
5. Напиши фабрику невалидных {{сущность}} для негативных тестов: по одному «сломанному» полю на вариант (превышение длины, неверный формат, null обязательного) — каждый вариант тестирует ровно одно нарушение.
6. Добавь в фабрику {{сущность}} детерминированную генерацию уникальных полей (email/slug/имя) с префиксом имени теста — коллизии в параллельном прогоне исключены по построению.
7. Проверь фабрики {{модуль}} на «валидность по умолчанию»: объект из фабрики без override проходит все валидации системы; если нет — фабрика создаёт заведомо битые данные, скрывая баги.

15. Найди в {{сьют}} общие мутируемые фикстуры (один объект правится несколькими тестами) — переведи на per-test создание или явно заморозь (immutable), докажи порядконезависимость параллельным прогоном.

## Моки и стабы

19. Напиши in-memory fake репозитория {{интерфейс}}: рабочая упрощённая реализация с консистентным поведением (уникальность, фильтры, ошибки как у реального) — для быстрых юнитов вместо мока с ручными ответами.
20. Проверь согласованность fake {{зависимость}} с реальной реализацией: прогони один сценарный сьют против обеих, расхождения поведения — списком (каждое = риск «зелёный юнит, красный прод»).
21. Настрой мок внешнего API {{API}} с полным спектром ответов: 2xx-контракт, 4xx-ошибки, 5xx, 429+Retry-After, таймаут, оборванное соединение, невалидный JSON — негативные тесты против мока-отличника бесполезны.

23. Напиши записывающий мок (spy) для {{зависимость}}: реальное поведение + запись аргументов вызовов — для проверки «что именно ушло во внешнюю систему» без подмены логики.
