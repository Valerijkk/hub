## Извлечение требований

1. Прочитай спеку {{спека}} и выпиши все атомарные требования: каждое «должен/если-то/не может» — отдельной строкой с ID (R1, R2...) и дословной цитатой. Неоднозначности — отдельным списком вопросов.
2. Из документа {{спека}} извлеки все неявные контракты: лимиты, форматы, дефолты, роли, статусные модели. Для каждого укажи раздел-источник.
3. Сравни требования {{спека}} с текущим набором тест-кейсов {{TC-набор}}: какие требования не покрыты ни одним кейсом? Выведи матрицу R×TC с дырами.
4. Найди противоречия внутри спеки {{спека}}: пары утверждений, которые не могут быть истинны одновременно. Каждой паре — цитаты и вопрос владельцу.
5. Для user story «{{story}}» сформулируй acceptance criteria в формате Given/When/Then — не более 7, каждый проверяем автотестом.
6. Выпиши из {{спека}} все числовые ограничения (длины, диапазоны, лимиты, таймауты) таблицей: поле | min | max | что при нарушении | источник.
7. Разбей фичу {{фича}} на поведенческие инварианты: что ОБЯЗАНО оставаться истинным при любом сценарии. Каждый инвариант — кандидат в property-based тест.
8. Из описания бага {{баг}} восстанови нарушенное требование: чего не хватало в спеке или в кейсах, что баг прошёл? Предложи недостающий кейс.
9. Составь глоссарий сущностей и состояний фичи {{фича}} из спеки: сущность | состояния | допустимые переходы | кто инициирует.
10. Для эндпоинта/функции {{цель}} перечисли все внешние зависимости (БД, API, часы, файлы) — каждая даст класс негативных кейсов «зависимость отказала».

15. Для числового входа {{поле}} построй классы: отрицательное, ноль, граница, за границей, дробное (если int), нечисловая строка, переполнение типа, экспоненциальная запись.

## Переходы состояний

28. Построй диаграмму состояний сущности {{сущность}} из спеки: состояния, события, guard-условия. Выведи кейсы на каждый валидный переход и на каждый ЗАПРЕЩЁННЫЙ (попытка перехода → ошибка, состояние не изменилось).
29. Для statechart {{сущность}} составь маршруты покрытия: каждый переход минимум раз (transition coverage), затем каждая пара смежных переходов (2-switch) для критичных состояний.
30. Спроектируй кейсы «возврата»: из каждого состояния {{сущность}} — можно ли вернуться в предыдущее, что с накопленными данными при возврате?
31. Найди «дыры» statechart: события, для которых в некоторых состояниях поведение не определено спекой. Каждая дыра — вопрос владельцу + кейс на текущее поведение.
32. Кейсы конкурентных переходов {{сущность}}: два актора одновременно переводят в разные состояния — что победит, что увидит второй, консистентен ли результат?

## Специфичные области

51. Спроектируй кейсы для поиска {{фича}}: пустой запрос, один символ, опечатки, регистр, спецсимволы/кавычки, очень длинный запрос, нерелевантные результаты, пагинация выдачи, права на результаты (видит только своё).
52. Кейсы для нотификаций {{фича}}: событие → кому/когда/канал, отписка, батчинг дублей, недоступный канал, шаблон с отсутствующей переменной, гонка «событие отменено до отправки».
53. Кейсы для импорта данных {{фича}}: валидный файл, частично валидный (что с валидными строками?), дубли внутри файла, дубли с БД, обрыв на середине, повторный импорт того же файла, кодировки.
54. Кейсы для экспорта {{фича}}: пустой набор, максимальный объём, спецсимволы в данных (CSV-инъекция!), права на экспортируемое, конкурентное изменение данных во время экспорта.
55. Кейсы для кэширования {{фича}}: первый запрос (miss), повторный (hit), инвалидация по изменению, TTL истёк, кэш недоступен (fallback к источнику), гонка обновления кэша.
56. Кейсы для фоновых задач {{фича}}: успешное выполнение, ретрай после падения, максимум ретраев исчерпан (DLQ?), дубль задачи, задача-зомби после рестарта воркера, порядок зависимых задач.
57. Кейсы миграции данных {{миграция}}: пустая БД, типовые данные, легаси-аномалии (null там, где «не бывает»), объём прода, повторный запуск (идемпотентность), откат.
58. Кейсы для мультитенантности {{фича}}: изоляция данных тенантов (чтение/запись/поиск/экспорт), лимиты на тенанта, один пользователь в двух тенантах.
59. Кейсы для фича-флагов {{флаг}}: вкл/выкл, переключение на живой сессии, комбинация с другими флагами, удаление флага (мёртвый код?).
60. Кейсы локализации {{фича}}: переключение языка, отсутствующий ключ перевода, длинные немецкие строки в UI, RTL, форматы дат/чисел/валют локали.
61. Кейсы таймзон {{фича}}: пользователь и сервер в разных TZ, DST-переход во время операции, «сегодня» на границе суток двух TZ, сравнение дат из разных источников.
62. Кейсы прав и ролей {{фича}}: каждая роль × каждая операция (denial-полнота), смена роли на живой сессии, наследование прав, «последний админ» уходит.
63. Кейсы версионирования API {{фича}}: старый клиент → новый сервер, новый клиент → старый сервер, deprecated-поле, неизвестное поле в запросе.
64. Кейсы для webhooks исходящих {{фича}}: подпись, ретраи при 5xx получателя, порядок доставки, отписка, мёртвый получатель (circuit breaker?).
