## Компонентные тесты

1. Напиши компонентные тесты {{компонент}} через пользовательские действия (клик/ввод/сабмит), ассерты на видимый результат; селекторы — accessible queries (role/label/text), не CSS-классы.
2. Тесты формы {{компонент}}: заполнение → сабмит → успех; каждая клиентская валидация (пустое, невалидный формат, лимит длины) → сообщение об ошибке у ПОЛЯ; серверная ошибка → отображение без потери введённого.
3. Тесты состояний {{компонент}}: loading (спиннер/скелетон), empty (пустой список с CTA), error (сообщение + retry), success — по одному тесту на состояние с ассертом отсутствия соседних состояний.
4. Тесты доступности {{компонент}}: навигация клавиатурой (tab-порядок, Enter/Escape/стрелки), фокус-ловушка в модалке, aria-атрибуты интерактивных элементов, видимость фокуса.
5. Тесты условного рендера {{компонент}}: каждая роль/право → видимые и СКРЫТЫЕ элементы (запрещённая кнопка отсутствует в DOM, не просто disabled — по спеке).
6. Тесты списка {{компонент}}: рендер N элементов, пустой список, один элемент, обновление элемента без полного ререндера (стабильные key!), удаление из середины.
7. Тесты интерактивной таблицы {{компонент}}: сортировка по колонкам, выделение строк, пагинация/виртуализация, resize/переупорядочивание колонок (если есть) — с ассертами на данные, не на пиксели.
8. Тесты drag-and-drop {{компонент}}: перенос валидный, в запрещённую зону, отмена (Escape/дроп вне зоны), клавиатурная альтернатива, состояние после отмены = исходному.
9. Тесты дебаунса/тротлинга {{компонент}} (поиск, автосейв): быстрый ввод → один запрос после паузы (фейк-таймеры), ввод во время запроса → отмена устаревшего, индикация «сохраняется/сохранено».
10. Тесты модалки/дровера {{компонент}}: открытие/закрытие всеми путями (кнопка, Escape, оверлей, сабмит), фокус в модалку и обратно, скролл фона заблокирован, несохранённые данные — предупреждение по спеке.
11. Тесты хука/состояния {{хук}}: начальное состояние, каждый переход, конкурентные вызовы, cleanup при анмаунте (отписки, отмена запросов), стабильность ссылок (мемоизация) там, где контракт.
12. Тесты error boundary {{модуль}}: падение дочернего рендера → fallback вместо белого экрана, остальное приложение живо, retry восстанавливает, ошибка отправлена в мониторинг (мок).
13. Тесты интернационализации {{компонент}}: смена локали на лету, отсутствующий ключ (fallback, не пустота), плюрализация, длинные строки не ломают лейаут (ассерт на overflow-контейнер).
14. Мок API для компонентных тестов {{компонент}} по канону проекта (MSW-класс): успех/ошибка/медленный ответ, ассерты на тело исходящего запроса, независимость моков между тестами.

## E2E: структура и Page Objects

15. Спроектируй Page Object для {{страница}} по канону проекта: локаторы одним блоком, действия — методами уровня пользователя (`login(user)`, не `fillEmailInput`), ассерты — вне PO (в спеке) или отдельными expect-хелперами — по конвенции проекта.
16. Отрефактори спеку {{файл}} на Page Objects: вынеси прямые локаторы, устрани дублирование шагов; спека после — читается как сценарий пользователя без единого селектора.
17. Напиши фикстуру авторизации для E2E: логин через API (не UI-форму), инъекция сессии в контекст, кэш сессии между тестами одного пользователя, изоляция между разными.
18. Спроектируй стратегию тестовых данных E2E-сьюта: каждый тест создаёт своё через API-сетап (не UI и не общий сид), уникальные имена с префиксом теста, cleanup после — политика по канону.
19. Организуй E2E-сьют {{фича}} по правилу независимости: любой тест запускается один и в любом порядке; общие предусловия — в фикстуры, не в «тест 1 создаёт для теста 2».

## E2E: сценарии

20. Напиши smoke E2E критичного пути {{продукт}}: {{N}} сценариев ≤{{T}} минут суммарно — вход, ключевое действие каждого модуля, выход; это гейт каждого PR.
21. Напиши E2E {{флоу}} полного цикла: от входа до наблюдаемого бизнес-результата, ассерты на каждом шаге (не только в конце), auto-wait вместо sleep, устойчивые локаторы.
22. E2E многопользовательского сценария {{флоу}}: два контекста браузера (A действует — B видит), реалтайм-обновления с таймаут-ожиданием, конфликты одновременных действий по спеке.
23. E2E прерываний {{флоу}}: перезагрузка страницы на каждом шаге → состояние восстановлено/понятная точка продолжения; потеря сети (offline-эмуляция) на середине → поведение по спеке.
24. E2E прав доступа {{фича}}: роль {{роль}} проходит свой сценарий; запрещённые элементы недоступны И прямые URL запрещённых страниц → редирект/403-экран.
25. E2E навигации: диплинки на каждый экран {{фича}} (с auth-редиректом на логин и возвратом), кнопка «назад» не ломает состояние, несуществующий маршрут → 404-экран.
26. E2E форм с загрузкой файлов {{флоу}}: выбор файла, прогресс, отмена на середине, невалидный тип/размер — сообщение, успешная загрузка отражается в UI.
27. E2E платёжного/критичного флоу {{флоу}} с тестовым контуром провайдера: успех, отказ, 3DS/редирект-возврат, таймаут провайдера, повторный сабмит не создаёт дубль.
28. E2E email-звеньев {{флоу}} (регистрация/сброс пароля): перехват письма тестовым SMTP/API-ящиком, переход по ссылке, истёкшая/повторная ссылка.

## Ожидания и стабильность

29. Замени в спеках {{файл}} все жёсткие sleep на встроенные ожидания (auto-wait/expect с таймаутом): каждому sleep — какое условие он маскировал, ожидание этого условия явно.
30. Стабилизируй локаторы {{файл}}: CSS-классы и XPath по вёрстке → role/label/data-testid по канону; testid добавляй в код компонента, если семантического якоря нет.
31. Найди в спеке {{файл}} ожидания «первого попавшегося» (клик по first()/nth(0) без гарантии порядка) — замени на однозначные локаторы.
32. Разбери флаки E2E {{тест}} по трейсу/видео: точный шаг падения, что было на экране, какое ожидание не сработало; классифицируй (гонка данных/анимация/сеть/селектор) и почини причину, не симптом.
33. Добавь в конфиг E2E диагностику падений: trace/screenshot/video на retry-прогоне, вложение в CI-артефакты, request-логи браузера — без включения на зелёных прогонах (объём).
34. Проверь E2E-сьют на устойчивость к анимациям: отключение анимаций в тестовом окружении включено, ожидания не зависят от длительности переходов.

## Визуальная регрессия

35. Настрой визуальные снапшоты для {{компонент/страница}}: стабильные состояния (загрузка завершена, анимации выключены, дата/рандом заморожены), маски на динамические зоны, пороги диффа, процесс обновления эталонов через ревью.
36. Составь список экранов для визуальной регрессии {{продукт}}: критичные по вёрстке (дашборды, печатные формы, email-шаблоны) — против полноэкранного снапшота всего подряд (шум).

## Кроссбраузерность и вьюпорты

38. Напиши адаптивные проверки {{страница}}: ключевые элементы доступны на {{вьюпорты}}, нет горизонтального скролла, интерактивные элементы достижимы (не перекрыты).

## Диагностика сьюта

39. Проведи аудит E2E-сьюта {{продукт}}: длительность каждой спеки, флаки-частота за {{период}}, дубли покрытия (два теста одного флоу), тесты не-критичных путей (кандидаты на понижение уровня) — таблицей с рекомендациями.
40. Найди в E2E {{сьют}} проверки, которым не нужен браузер (валидация API-ответов, расчёты) — перенеси на уровень ниже со ссылкой на правило минимального уровня (A3).
41. Посчитай стоимость E2E-сьюта: время прогона × частота × инфраструктура против пойманных багов за {{период}} — рекомендации что оставить в PR-гейте, что в ночной прогон.
42. Ревью параллелизации E2E: шардирование настроено, тесты не делят пользователей/данные, время полного прогона при {{N}} воркерах, узкие места (последовательные фикстуры).

## Доступность (a11y) — углублённо

46. Проведи a11y-аудит {{страница}}: автоматический скан (axe-класс) + ручные проверки, которые скан не ловит — логичный порядок фокуса, осмысленные лейблы, контраст, роль каждого кастомного контрола.
47. Тесты клавиатурной навигации {{флоу}}: весь сценарий проходится без мыши, tab-порядок логичен, фокус виден, нет ловушек фокуса (кроме модалок), Escape/Enter/стрелки работают по WAI-ARIA-паттернам.
48. Тесты скринридера {{компонент}}: динамические изменения объявляются (aria-live), состояния (expanded/selected/invalid) озвучиваются, декоративное скрыто (aria-hidden), формы связаны label↔input.
49. Тесты контраста и масштабирования {{страница}}: контраст текста/контролов ≥ норм, зум 200% не ломает лейаут и не прячет контент, работа при уменьшенной анимации (prefers-reduced-motion).
50. Тесты форм на доступность {{компонент}}: ошибки связаны с полями (aria-describedby), обязательность объявлена, автозаполнение (autocomplete-атрибуты), группировка (fieldset/legend).

## Мобильные и адаптивные

51. Тесты тач-взаимодействий {{компонент}}: тап, свайп, long-press, pinch (если есть), достаточный размер тач-целей, отсутствие hover-зависимой функциональности без тач-альтернативы.
52. Тесты адаптивного лейаута {{страница}} на {{вьюпорты}}: перестроение сетки, бургер-меню на узких, отсутствие горизонтального скролла, читаемость без зума, sticky-элементы не перекрывают контент.
53. Тесты мобильных жестов навигации {{флоу}}: свайп назад, pull-to-refresh (если есть), скролл длинных списков (виртуализация), поведение при повороте экрана (сохранение состояния).
54. Тесты мобильной клавиатуры {{форма}}: правильный тип клавиатуры по полю (email/number/tel), поле не перекрыто клавиатурой, «Готово»/«Далее» работают, автокоррекция где уместна.

## Реалтайм и коллаборация

55. Тесты реалтайм-обновлений {{фича}}: изменение в контексте A видно в контексте B в пределах {{T}}, отписка при уходе со страницы, реконнект после потери соединения добирает пропущенное.
56. Тесты совместного редактирования {{фича}}: конкурентные правки двух пользователей (merge/last-write/CRDT по спеке), индикация присутствия/курсоров, конфликт разрешается предсказуемо.
57. Тесты уведомлений в UI {{фича}}: событие → тост/бейдж/звук по настройкам, батчинг, отметка прочитанным синхронизируется между вкладками, недоставленные при офлайне.
58. Тесты синхронизации между вкладками {{фича}}: логин/логаут в одной вкладке отражается в других, общее состояние (корзина/черновик) консистентно, конфликт вкладок.

## Клиентское состояние и данные

59. Тесты оптимистичных обновлений {{компонент}}: мгновенное отражение действия, откат при ошибке сервера с восстановлением UI и уведомлением, отсутствие «мигания» при успехе.
60. Тесты кэша клиента {{фича}} (react-query/apollo-класс): stale-while-revalidate, инвалидация после проверки утверждения, дедупликация параллельных запросов, поведение при навигации туда-обратно.
61. Тесты сохранения черновика/формы {{компонент}}: автосохранение (дебаунс), восстановление после перезагрузки/краша, очистка после сабмита, конфликт с серверной версией.
62. Тесты офлайн-режима {{фича}}: действия в офлайне ставятся в очередь, индикация состояния, синхронизация при восстановлении, разрешение конфликтов офлайн-изменений.
63. Тесты пагинации/бесконечного скролла в UI {{компонент}}: подгрузка при скролле, индикатор загрузки, конец списка, пустое состояние, сохранение позиции при возврате, отсутствие дублей элементов.

## Аналитика и трекинг

64. Тесты аналитических событий {{флоу}}: ключевые действия отправляют события с правильными параметрами (мок трекера), нет двойной отправки, PII не утекает в аналитику, события не блокируют UX при недоступном трекере.
65. Тесты consent/приватности {{фича}}: трекинг не идёт до согласия, отзыв согласия останавливает, необходимые (не-маркетинговые) работают всегда по политике.

## Производительность UI

66. Тесты производительности рендера {{компонент}}: нет лишних ре-рендеров (профилировщик), большие списки виртуализированы, тяжёлые вычисления мемоизированы/вынесены, отсутствие layout thrashing.
67. Тесты метрик загрузки {{страница}}: LCP/CLS/INP в пределах бюджета (Lighthouse-класс в CI), нет сдвигов лейаута при загрузке (зарезервированное место), критичный контент первым.
68. Тесты бандла {{продукт}}: размер в бюджете, код-сплиттинг по роутам, тяжёлые зависимости ленивые, регрессионный порог размера бандла в CI.

## Диагностика и стабильность (расширение)

69. Разбери flaky E2E {{тест}} по трейсу: точный шаг и состояние экрана при падении, класс (гонка данных/анимация/сеть/селектор/тайминг), фикс причины; см. 07 #17 для дерева классов.
70. Найди в E2E {{сьют}} тесты, зависящие от конкретных тестовых данных сида (а не создающие своё) — переведи на самодостаточный API-сетап.
71. Аудит селекторов {{сьют}}: CSS/XPath по вёрстке → role/label/testid; список хрупких с предложением якоря (добавить testid в компонент, где нет семантики).
72. Аудит времени E2E-сьюта {{продукт}}: длительность каждой спеки, топ-медленные с причиной, кандидаты на параллелизацию/понижение уровня/удаление дублей.
73. Проверь E2E {{сьют}} на независимость: прогон в случайном порядке и параллельно — общие пользователи/данные всплывут; изолируй.
74. Найди в компонентных тестах {{модуль}} проверки внутреннего состояния/пропсов вместо пользовательского поведения — перепиши на действия+видимый результат.
