## Репозитории и SQL

8. Напиши интеграционные тесты репозитория {{репозиторий}}: CRUD-цикл каждой сущности с реальной {{БД}}, ассерты через независимое чтение (не через тот же метод, что писал).
9. Протестируй SQL-запросы {{репозиторий}} с краевыми данными: null-колонки, пустые строки vs null, максимальные длины, unicode, спецсимволы, экранирование LIKE-паттернов (% и _ в пользовательском вводе).
10. Тесты пагинации {{репозиторий}}: пустой результат, ровно одна страница, граница страниц (без дублей и пропусков при переходе), за последней страницей, стабильность порядка при одинаковых значениях сортировки.
11. Тесты конкурентности {{репозиторий}}: два параллельных обновления одной записи — оптимистическая блокировка срабатывает (version-конфликт), при потере — фиксируешь текущее фактическое поведение и заводишь вопрос владельцу.
12. Тесты уникальных ограничений {{сущность}}: дубль по каждому unique-индексу → типизированная ошибка (не голый SQL-код), регистрозависимость уникальности, конкурентная вставка дублей.
13. Тесты каскадов и внешних ключей {{сущность}}: удаление родителя (каскад или запрет — по спеке), сирота невозможна, soft-delete не рвёт связи живых.
14. Тесты транзакционности {{операция}}: ошибка на шаге N из M → откат ВСЕГО (проверь каждую таблицу), успех → всё зафиксировано, вложенные транзакции/savepoints по канону проекта.
15. Тесты индексов и планов (для критичных запросов {{запрос}}): EXPLAIN на объёме {{N}} строк — нет seq scan на больших таблицах; тест-предохранитель от деградации плана после миграций.
16. Тесты миграции {{миграция}}: применение на снапшоте с легаси-аномалиями ({{аномалии}}), идемпотентность повторного применения, down-миграция (если канон требует), время на проде-объёме.
17. Тесты маппинга ORM {{сущность}}: каждое поле сущности round-trip через БД (записал→прочитал→равно), включая enum, JSON-колонки, таймстемпы с таймзонами, точность decimal.
18. Тесты soft-delete {{сущность}}: удалённое не видно в списках/поиске/связях, восстановление, hard-delete по политике, уникальность с учётом удалённых (можно ли создать дубль удалённого?).

## Очереди и события

19. Тесты публикации событий {{модуль}}: операция → событие в {{очередь}} с правильной схемой и ключом маршрутизации; ошибка публикации → поведение по спеке (откат операции? outbox?).
20. Тесты консьюмера {{консьюмер}}: валидное сообщение → обработка + ack; невалидное → [DLQ | ack с логом | nack] по спеке; ошибка обработки → ретрай с backoff; дубль сообщения → идемпотентность.
21. Тест порядка событий {{флоу}}: события одного агрегата обрабатываются по порядку (или спека явно допускает out-of-order — тогда тест на устойчивость к перестановке).
22. Тест реконнекта консьюмера: обрыв соединения с {{очередь}} → переподключение → дообработка накопленного, без потерь и без двойной обработки подтверждённого.
23. Тест outbox-паттерна {{модуль}}: запись+событие атомарны (падение между ними невозможно по построению), релей доставляет после сбоя, порядок сохранён.
24. Тесты graceful shutdown воркера {{воркер}}: сигнал остановки посреди обработки → текущее сообщение дообрабатывается или возвращается в очередь (по спеке), новых не берёт, укладывается в таймаут {{T}}.
25. Нагрузочный мини-тест очереди {{очередь}} в интеграционном контуре: {{N}} сообщений пачкой — все обработаны ровно раз, время в пределах {{T}}, память воркера стабильна.

## GraphQL / gRPC / WebSocket

61. Тесты GraphQL-резолверов {{схема}}: запрос каждого поля, вложенные резолверы (N+1 через dataloader — счётчик запросов!), права на уровне поля, частичные ошибки (data+errors), лимит глубины/сложности запроса.
62. Тесты GraphQL-мутаций {{схема}}: валидация аргументов, оптимистичный ответ, ошибки в формате схемы, идемпотентность, права; интроспекция отключена в проде (тест-предохранитель).
63. Тесты gRPC-сервиса {{сервис}}: unary happy/error (status codes, не HTTP), стриминг (client/server/bidi) — старт, поток, завершение, отмена контекста посреди стрима, дедлайны, метадата/trailers.
64. Тесты WebSocket {{канал}}: установка соединения с auth, подписка/отписка, доставка сообщений по порядку, реконнект с добором пропущенного, membership/RBAC на подписку (без проверки — дыра безопасности), закрытие с кодом.
65. Тесты обратного давления (backpressure) стрима {{сервис}}: медленный потребитель не роняет продюсера (буфер/дроп/блок по спеке), быстрый продюсер не переполняет память.

## Наблюдаемость как контракт

66. Тесты трассировки {{флоу}}: span создаётся на границах, trace-id пробрасывается через все слои и во внешние вызовы, ошибка помечает span; трассировка — контракт, тестируется как контракт.
67. Тесты метрик {{модуль}}: ключевые счётчики/гистограммы инкрементируются на нужных событиях (успех/ошибка/latency), лейблы корректны и не кардинально-взрывные, метрика ошибок растёт при ошибке.
68. Тесты структурного лога {{модуль}}: критичные события логируются с нужным уровнем и контекстом (request-id, module), секреты/PII замаскированы, ошибка логируется один раз (не на каждом слое — log-and-return антипаттерн).
69. Тесты health/readiness {{сервис}}: healthy при живых зависимостях, unhealthy при отказе критичной (readiness убирает из балансировки), liveness не зависит от внешних (иначе каскадный рестарт).

## Чистая архитектура и границы

70. Тесты сквозного сценария {{флоу}} через реальные адаптеры (порты БД/очереди), но замоканный внешний мир: каждая граница модуля проверена с двух сторон, быстрее полного E2E.

83. Сгенерируй чек-лист ревью интеграционного теста: реальные зависимости на границах, изоляция данных, ассерты всех затронутых хранилищ, cleanup, нет псевдоинтеграционности — как PR-темплейт.
84. Сгенерируй README «как поднять тестовое окружение локально» для {{продукт}}: exact commands из active profile `COMMANDS.md`, порядок сервисов, типовые проблемы и решения.
85. Сгенерируй матрицу «модуль × внешняя система × класс теста (успех/ошибка/таймаут/реконнект)» для {{продукт}} — навигатор покрытия интеграционных точек с отметкой дыр.
