# tf-gate — гейт перед сдачей

## Когда

- Работа над тестами закончена, перед передачей на ревью
- Перед мержем
- После правок по замечаниям ревью — повторно

**Не для этого:** оценка качества тестов — `tf-review`. Гейт проверяет,
что работа пригодна к ревью, а не что она хорошая.

## Смысл разделения

```
tf-gate    механически проверяемое: собирается, проходит, чисто
tf-review  содержательное: проверяет ли тест то, что заявляет
```

Отдавать на ревью работу, не прошедшую гейт, — тратить время ревьюера на
то, что находит команда за минуту.

## Шаги

Точные команды берутся из `context/COMMANDS.md` активного профиля.
Выдуманная команда — находка против исполнителя.

### 1. Сборка и статический анализ

Проект собирается, статический анализатор молчит. Не собирается —
остальные шаги бессмысленны, гейт останавливается здесь.

### 2. Целевые тесты

Затронутые тесты проходят. Прикладывается вывод, а не слово «зелёный».

### 3. Регрессия затронутого контура

Прогоняется не только новый тест, но и контур вокруг него. Зелёный новый
тест при красном соседнем означает, что работа не сделана.

Объём контура определяется заранее и записывается — «затронутые тесты»
без списка каждый понимает по-своему.

### 4. Стабильность нового

Новый тест прогоняется **десять раз подряд**. Хотя бы одно падение —
FAIL: это найденный флейк, а не «бывает».

### 5. Чувствительность

Каждый новый и изменённый тест имеет вердикт по
[`rules/40`](../../rules/40-verification-protocol.md). Нет вердикта —
FAIL, независимо от того, насколько тест выглядит правильным.

### 6. Стиль и следы генерации

Линтер проходит. Прогоняется `tf-antiai` — признаки из
[`practices/anti-ai.md`](../../practices/anti-ai.md).

### 7. Чистота рабочего дерева

В дифе нет: профилей покрытия, отчётов прогона, временных файлов,
локальных настроек, артефактов сборки.

Признак: файлы, которых нет в задаче, но есть в дифе. Каждый такой —
объяснить или убрать.

### 8. Секреты

В изменённых файлах нет токенов, паролей, строк подключения, реальных
персональных данных. Проверяется поиском по дифу, а не по памяти.

Найдено — гейт останавливается, и это не «поправлю потом»: секрет,
попавший в историю, оттуда простым коммитом не убирается.

### 9. Документация

Менялось поведение, способ запуска или конвенция — соответствующая карта
в `context/` обновлена в этой же сессии. Расхождение обнаружится через
месяц и обойдётся дороже.

## Отчёт

```
ГЕЙТ: PASS | FAIL

| # | Шаг | Результат | Доказательство |
|---|-----|-----------|----------------|
| 1 | Сборка | PASS | <команда> → exit 0 |
| 2 | Целевые тесты | PASS | <команда> → N passed |
| 3 | Регрессия | PASS | <контур> → N passed |
| 4 | Стабильность | PASS | 10/10 зелёных |
| 5 | Чувствительность | PASS | <вердикт по каждому тесту> |
| 6 | Стиль и анти-AI | PASS | <вывод> |
| 7 | Чистота дерева | PASS | в дифе только файлы задачи |
| 8 | Секреты | PASS | поиск по дифу пуст |
| 9 | Документация | N/A: поведение не менялось | — |

FAIL: <шаг и что именно не так>
```

## Правила

- **Один FAIL блокирует сдачу.** Не «девять из десяти прошло».
- **N/A только с причиной.** Пропущенный шаг неотличим от пройденного.
- **Доказательство обязательно.** PASS без команды или вывода не
  засчитывается — это тот же L0, что и «я проверил».
- **Гейт не чинит.** Нашёл FAIL — вернул исполнителю с указанием шага.

## Что НЕ делаю

- Не оцениваю качество тестов — это `tf-review`
- Не правлю найденное
- Не пропускаю шаг, потому что «очевидно пройдёт»
- Не ставлю PASS по памяти о прошлом прогоне

## Что дальше

PASS — работа идёт на `tf-review`.
FAIL — возврат исполнителю с указанием конкретного шага и доказательства.
