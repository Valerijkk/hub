# tf-cover — покрыть тестами

## Когда

- Пришли новые или изменённые ручки, модуль, требования
- Нужно добрать покрытие по уже существующему функционалу
- Карта покрытия (`tf-status`) показала непокрытое

**Не для этого:** упал существующий тест — это `tf-triage`. Отревьюить
чужие тесты — `tf-review`.

## Вход

Список в любом виде: спека, диф, ссылка на контракт, просто перечисление
ручек. Уточняющие вопросы — только если без ответа покрытие будет
неверным, а не для проформы.

## Процедура

### 1. Свежесть контекста

Проверить `context/` против текущего состояния репозитория. Устарел —
сначала `tf-refresh`, потом сюда.

Работа на устаревшем контексте даёт тесты по чужим паттернам, и это
обнаружится на ревью, а не сейчас.

### 2. Контракт каждой ручки

Выяснить и записать до единой строки кода:

```
метод и путь
параметры: обязательность, типы, границы
тело запроса
ВСЕ коды ответа со схемами
требуемые права
побочные эффекты
идемпотентность
ограничения размера и частоты
```

Источник — спека или контракт. **Не выдумывать коды ответа.** Нет в
контракте 409 — тест на 409 проверяет несуществующее требование и
закрепляет поведение, которого никто не обещал. Чего в контракте нет —
в раздел «Вопросы», не в тесты.

### 3. Матрица покрытия — ДО первого кейса

Строки — требования, колонки — обязательные классы из
[`rules/20`](../standards/rules/20-test-quality.md):

| R | happy | валидация | denial | not found / конфликт | отказ завис. | идемпот. | границы |
|---|-------|-----------|--------|----------------------|--------------|----------|---------|
| R1 | plan | plan | plan | N/A: нет состояния | ? | plan | plan |

Каждая ячейка получает **одно из трёх** значений:

| Значение | Смысл |
|---|---|
| `plan` | Кейс будет написан |
| `N/A: <причина>` | Класс неприменим к этому требованию |
| `?` | Не решается без ответа документации → в «Вопросы» |

**Пустых ячеек не остаётся.** Пустая ячейка — это незамеченная дыра, а
не «пока не думали».

Матрица показывается человеку **до** написания тестов. Спорить о полноте
покрытия дешевле на таблице, чем на готовом коде.

Подробности формы — [`agents/test-case-generator.md`](../agents/test-case-generator.md) §2.1.

### 4. Написание

Строго по паттернам и неймингу активного профиля. Новый паттерн вводится
только если существующие не подходят, с явным обоснованием — а не по
привычке из другого проекта.

Существующие фикстуры переиспользуются. Дублирование фикстуры — находка
ревью, а не мелочь.

Рецепты под тип работы:
[`design-test-cases`](../workflows/recipes/design-test-cases.md),
[`generate-unit-tests`](../workflows/recipes/generate-unit-tests.md),
[`generate-api-tests`](../workflows/recipes/generate-api-tests.md),
[`generate-ui-e2e`](../workflows/recipes/generate-ui-e2e.md).

### 5. Прогон

Целевые тесты запускаются и проходят. Красный тест дальше не идёт.

### 6. Проверка утверждения — обязательна

Каждый новый тест проверяется прогоном по
[`rules/40`](../standards/rules/40-verification-protocol.md) §Доказательство
осмысленности утверждения:

```
сломать один управляемый вход (фикстура, стаб, тестовые данные)
  → тест обязан покраснеть
вернуть вход
  → тест обязан позеленеть
записать оба результата
```

Продуктовый код при этом **не трогается**: его в этом репозитории нет.
Вердикт `УТВЕРЖДЕНИЕ_ЕСТЬ` — уровень L2. Нет управляемого входа →
`НЕПРИМЕНИМО` с причиной и структурное обоснование вместо прогона.

Тест, который невозможно уронить, не проверяет ничего — сколько бы строк
ни выполнял.

### 7. Гейт TC

Если набор кейсов формализован — прогнать `tf-verify`
([`test-verification`](test-verification.md)). Он разбирает
значения матрицы: обоснованный `N/A` принимается, `?` уходит в вопросы,
а не в дыры покрытия.

## Отчёт

```
ПОКРЫТО: <ручки или модуль>
ТЕСТОВ: <n>, файлы: <пути>
МАТРИЦА: <n> ячеек, из них plan <n>, N/A <n>, ? <n>
НЕ ПОКРЫТО: <случай> — <причина: нет в контракте / нужен стенд /
            решение команды>
ЧУВСТВИТЕЛЬНОСТЬ: <вердикт по каждому новому тесту>
ПРОГОН: <команда> → <результат>
ВОПРОСЫ: <что осталось неясным в контракте>
```

## Стоп-условия

Остановиться и спросить, не выдумывать:

- Контракт неизвестен и не выводится из доступных источников
- Нужен стенд, доступ или данные, которых нет — зафиксировать, не имитировать
- Требование противоречит другому требованию

## Что НЕ делаю

- Не пишу тесты до матрицы покрытия
- Не покрываю только успешный путь
- Не выдумываю коды ответа и поведение, которых нет в контракте
- Не завожу новый паттерн, не проверив существующие
- Не сдаю тест без вердикта осмысленности утверждения
- Не трогаю продуктовый код — его здесь нет
