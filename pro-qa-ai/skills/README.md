# skills/ — процедуры

Скил — пошаговая процедура с проверяемым результатом. Не роль (это
[агенты](../agents/README.md)), а процесс: прогнал шаги → получил отчёт с
вердиктом. Запускает человек, агент или CI.

Один скил — **один файл** в этой папке, без вложенных каталогов.

## Что чем запускается

Двенадцать команд `tf-*` за четырнадцатью файлами: две команды
разворачиваются в пару скилов.

| Команда | Скил | Назначение |
|---------|------|------------|
| `tf-init` | [tf-init](tf-init.md) → [bootstrap-test-context](bootstrap-test-context.md) | Первый запуск: изучить репозиторий, наполнить контекст |
| `tf-refresh` | [refresh-test-context](refresh-test-context.md) | Инкрементально обновить профиль после изменений в репозитории |
| `tf-status` | [tf-status](tf-status.md) | Где я: свежесть контекста, покрытие, что дальше |
| `tf-cases` | [tf-cases](tf-cases.md) | Спроектировать кейсы из требований техниками тест-дизайна |
| `tf-cover` | [tf-cover](tf-cover.md) | Покрыть тестами ручки, модуль, требования |
| `tf-triage` | [tf-triage](tf-triage.md) | Упал тест: `code`, `test`, `infra`, `flaky`, `stop` |
| `tf-gate` | [tf-gate](tf-gate.md) | Гейт перед сдачей: сборка, тесты, стабильность, чистота, секреты |
| `tf-review` | [tf-review](tf-review.md) | Ревью тестового кода до мержа |
| `tf-verify` | [test-verification](test-verification.md) | Верификация кейсов против документации до автоматизации |
| `tf-naming` | [naming-check](naming-check.md) | Аудит имён файлов и кейсов против канона профиля |
| `tf-antiai` | [anti-ai-check](anti-ai-check.md) | Скан качества сгенерированного кода; кандидаты, не вердикт |
| `tf-curate` | [curate-review-feedback](curate-review-feedback.md) → [curate-pattern-cards](curate-pattern-cards.md) | Тред коллеги → правило `CHECK-NNN` → карточка паттерна |

Полные контракты команд — [`../COMMANDS.md`](../COMMANDS.md).

## Почему `tf-curate` — два скила

Это два разных гейта доверия, и слияние их сломало бы главную гарантию:

1. `curate-review-feedback` обезличивает тред и выделяет правило.
   Карточек паттернов **не создаёт**.
2. `curate-pattern-cards` читает **только** одобренное человеком и
   создаёт карточку.

Между ними стоит человек. Один скил на оба шага означал бы, что вставка
сырого треда автоматически рождает канон.

## Форма файла

Семь секций, **фиксированный порядок и фиксированные названия**.
Проверяется валидатором: расхождение — ошибка, а не стиль.

```
---
name: <slug>          совпадает с именем файла
description: <что делает — когда запускать — когда НЕ запускать>
---

# /<name>

> Одна строка: что на входе → что на выходе.

## Когда запускать      маркеры + «Не запускать: → куда вместо этого»
## Вход                 что нужно, откуда взять, что делать если нет
## Шаги                 нумерованные, с командами
## Формат отчёта        точный шаблон в блоке
## Критерий готовности  чеклист `- [ ]`
## Вердикт              таблица PASS / PARTIAL / FAIL / NOT_RUN
## Что дальше           маршрут после завершения
```

Необязательные `Контекст`, `Стоп-условия`, `Границы` вставляются между
семью обязательными; их взаимный порядок контрактом не задан. Одно
ограничение жёсткое: `Контекст` и `Стоп-условия` стоят **до** «Шагов» —
их читают до первого шага, а не после последнего. Скило-специфичное —
уровнем `###` внутри «Шагов».

### Почему именно эти семь

| Секция | Что ломается без неё |
|--------|----------------------|
| Когда запускать | Скил зовут не на ту задачу; хуже — зовут вместо соседнего |
| Вход | Запуск на неполных данных, результат выглядит настоящим |
| Формат отчёта | Каждый прогон отдаёт свою форму, сравнить два невозможно |
| Критерий готовности | «Готово» решается самооценкой, а не проверкой |
| Вердикт | Нет разницы между «проверено и чисто» и «не проверялось» |
| Что дальше | Цепочка рвётся: человек знает результат, но не следующий шаг |

Четыре значения вердикта неслучайны. `NOT_RUN` — законный результат и
обязан отличаться от `PASS`: без этого различия непройденная проверка
выглядит пройденной, и именно на этом строится большинство ложной
уверенности.

Имя в `name:` обязано совпадать с именем файла — проверяет валидатор.

### Бюджет размера

| Ярус | Порог | Что попадает |
|------|-------|--------------|
| Обычный | **38 КБ** | Большинство скилов и правил |
| Большой | **54 КБ** | Полный каталог, нужный целиком на каждом запуске |
| Потолок | **90 КБ** | Выше не бывает ни при каком обосновании |

Файл, загруженный в агента, расходует его внимание **до** начала работы.
Проверяет валидатор (`size_budget`); исключение требует записанной
причины, иначе оно и есть способ обойти правило.

Не влезает — это признак, что файл описывает две темы. Делить, а не
сокращать: скил, из которого вырезали «почему так», уложится в порог и
станет бесполезным.

## Обязательства скила

Действуют для всех четырнадцати:

1. Читать `context/projects/<profile>/` вместо угадывания путей.
   Профиля нет — `tf-init`, а не догадка.
2. Завершаться доказательством и честным вердиктом. `NOT_RUN` — законный
   результат; выдуманное `PASS` — нет.
3. Не менять исходный код без явного шага и разрешения.
4. Применять [rules/40](../standards/rules/40-verification-protocol.md) по
   уровню риска, [rules/50](../standards/rules/50-data-handling.md) ко
   всему прочитанному и вставленному, [rules/60](../standards/rules/60-agency-and-egress.md)
   ко всему, что скил делает сам: сеть, установки, запись вне корней.
5. Заканчивать «Что дальше» следующим шагом
   [цикла](../workflows/playbooks/phase-loop.md), а не списком ссылок на
   правила. Список — это отказ выбрать; цепочка на нём и рвётся.
6. Ссылаться на процедуру из [rules](../standards/rules/),
   [практик](../standards/practices/) и [ролей](../agents/README.md), а не
   пересказывать её. Копия расходится с оригиналом при первой же правке и
   стоит токенов дважды; проверяет валидатор (`duplication`).
