# Разобранные треды — вход ревью

Треды, прошедшие обезличивание и разбор. **Это первый источник для
`tf-review`**, до общих практик автоматизации и кодирования.

| Тред | Правило | Severity | Суть |
|------|---------|----------|------|
| [THREAD-001](THREAD-001-timeout-in-config.md) | CHECK-001 | major | Таймаут ожидания внешнего ответа — из конфига окружения, не литералом |
| [THREAD-002](THREAD-002-status-code-only.md) | CHECK-002 | blocker | Код ответа без проверки тела не считается покрытием ручки |
| [THREAD-003](THREAD-003-shared-fixture-state.md) | CHECK-003 | blocker | Фикстура шире функции — только для неизменяемого |

## Как читать

Тред отвечает на вопрос **почему**, правило `CHECK-NNN` — на вопрос
**что проверять**. Ревьюер применяет правило; тред открывает, когда надо
понять причину или объяснить автору, почему замечание не вкусовщина.

Каждый тред обязан иметь раздел «Границы». Правило без границ начинает
срабатывать там, где не должно, и его обходят целиком вместо того, чтобы
уточнить.

## Поле seen_count

Счётчик повторов замечания в реальных ревью. Прилетевшее третий раз
важнее разового: это системная проблема, а не случай. При повторе
счётчик растёт, дубль не создаётся.

В раунде ревью правила сортируются по нему: сначала то, на чём команда
спотыкается чаще.

## Что здесь не лежит

Сырые треды — в [`../inbox/`](../../inbox/README.md), в ревью они не
участвуют: не обезличены и не разобраны.

Общие практики тестирования — в [`rules/20-test-quality.md`](../../../rules/20-test-quality.md)
и карточках [`patterns/approved/`](../../../patterns/approved/README.md).
Здесь только то, чего нет в общих практиках: решения этой команды и их
причины.
