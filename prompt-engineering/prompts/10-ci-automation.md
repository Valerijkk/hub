## Проектирование пайплайна

1. Спроектируй тестовый пайплайн {{продукт}} по стадиям: быстрые гейты первыми (линт, юниты), дорогие последними (E2E), fail-fast на дешёвых — по фактам стека из PROJECT-CONTEXT/TESTFRAMEWORK-MAP.
2. Раздели прогоны по триггерам: на каждый PR — смоук+юниты+diff-coverage (быстро); на merge в основную — полный; ночью — E2E-full+нагрузка+mutation. Обоснуй, что где.
3. Спроектируй gate-модель: какие джобы блокируют мерж (required), какие информируют (optional), какие можно перезапустить; чёткий критерий «зелёный PR».
4. Оцени текущий пайплайн {{пайплайн}} на узкие места: критический путь по времени, последовательное там, где можно параллельно, дублирующая работа между джобами (пересборка), холодные кэши.
5. Спроектируй матрицу прогона {{джоба}}: версии рантайма/браузеры/ОС из реального использования — полный набор на merge, сокращённый на PR; обоснуй сокращение.

## Скорость и параллелизация

6. Ускорь пайплайн {{пайплайн}} ({{время}}): распараллель независимые стадии, шардируй медленный сьют {{сьют}} по {{N}} воркерам, кэшируй зависимости/сборки, вынеси не-блокирующее в async — оцени выигрыш каждого.
7. Настрой шардирование {{сьют}} на {{N}} воркеров: балансировка по времени тестов (не по количеству), изоляция данных между шардами, сбор результатов, стабильность распределения.
8. Настрой кэширование в {{CI}}: зависимости, артефакты сборки, docker-слои — ключи кэша корректны (инвалидация при смене lock-файла), нет отравления кэша между ветками.
9. Настрой умный отбор тестов (test impact analysis): для PR прогоняй только тесты, затронутые изменениями + смоук, полный набор — на merge; безопасный fallback на полный при неопределённости.
10. Раздели сборку и прогон {{джоба}}: собрать один раз, переиспользовать артефакт в параллельных тест-джобах вместо пересборки в каждой.

## Стабильность CI

11. Настрой политику ретраев в {{CI}} осознанно: авторетрай только на инфра-ошибки (сеть/таймаут поднятия сервиса), НЕ на падения тестов (это маскирует flaky); каждый ретрай логируется и метрицируется.
12. Настрой карантин flaky в CI: помеченные тесты идут в non-blocking джобу с алертом на протухание карантина, основной гейт остаётся зелёным — но карантин виден, а не забыт.
13. Настрой сбор диагностики падений {{джоба}}: логи, трейсы/скриншоты/видео (E2E), дампы состояния — в артефакты, только на падениях (объём), доступны без повторного прогона.
14. Добавь healthcheck сервисов перед тест-стадией {{джоба}}: тесты стартуют только когда {{БД/очередь/сервисы}} реально готовы (не «подождать 10 сек»), внятная ошибка при недоступности.
15. Настрой таймауты на всех уровнях {{пайплайн}}: тест, сьют, джоба — зависший тест не держит пайплайн часами; таймаут джобы > суммы разумных таймаутов сьютов.
16. Проверь детерминизм CI-окружения {{пайплайн}}: фиксированные версии образов/зависимостей, замороженная таймзона/локаль, отсутствие сети к внешним сервисам в юнит/интеграционных стадиях.

## Гейты качества

17. Настрой composite quality gate {{пайплайн}}: сборка + юниты + интеграция + смоук E2E + линт + diff-coverage + security scan — останавливается на первой FAIL, после фикса перезапуск с упавшей стадии.
18. Настрой diff-coverage гейт в {{CI}}: покрытие нового кода ≥{{порог}}, отчёт комментарием в PR, старый долг не блокирует.
19. Настрой gate на запрещённые паттерны в diff (anti-AI/security из skills/): .only, sleep в тестах, http.DefaultClient, секреты, TODO без тикета — греп-фильтр, блокирует мерж.
20. Настрой gate размера/атомарности PR: предупреждение при diff > {{N}} строк или смешении фичи с рефакторингом — мягкий сигнал ревьюеру, не жёсткий блок.
21. Проверь, что gate не обходится: required-джобы нельзя пропустить, ветки защищены, зелёный статус не ставится вручную, force-push в основную запрещён.

## Отчётность

22. Настрой публикацию результатов тестов {{CI}} в читаемом виде: сводка pass/fail/skip, упавшие с логами первыми, тренд к прошлому прогону, ссылки на артефакты — комментарием в PR или дашбордом.
23. Настрой отчёт покрытия в PR: дельта к базовой линии, непокрытые строки нового кода inline-комментариями, ссылка на полный отчёт.
24. Настрой сбор метрик пайплайна {{пайплайн}}: время каждой стадии, флаки-частота, доля перезапусков, время «зелёный PR» — тренды для оптимизации, не разовый замер.
25. Настрой алерты: красная основная ветка → немедленно команде, рост флаки-частоты выше {{порог}} → еженедельно, деградация времени пайплайна → месячно.
26. Сгенерируй еженедельный health-отчёт CI: стабильность (флаки/ретраи), скорость (тренд времени), надёжность гейтов (пойманные баги vs убежавшие) — для ретро команды.

## Инструментальная генерация

27. Сгенерируй конфиг джобы {{джоба}} для {{CI}} по фактам проекта: сервисы, команды из PROJECT-CONTEXT §4, кэши, таймауты, артефакты — без выдуманных шагов.
28. Сгенерируй матрицу-конфиг для кроссбраузерного/кроссверсионного прогона {{сьют}} в {{CI}}: экономная матрица (не декартов взрыв), fail-fast: false для полной картины.
29. Напиши локальный скрипт-эквивалент CI-гейта: разработчик прогоняет то же, что CI, до пуша — те же команды, тот же порядок, fail на первой ошибке; синхронизирован с конфигом CI.
30. Настрой pre-commit/pre-push хуки по канону проекта: быстрые проверки (линт, форматирование, затронутые юниты) локально, тяжёлое — в CI; не дублируй весь CI в хук (замедлит коммиты).

## Диагностика и аудит

31. Проведи аудит пайплайна {{пайплайн}}: время по стадиям (диаграмма), критический путь, flaky-джобы, холодные кэши, дублирующая работа, необоснованные ретраи — с оценкой выигрыша каждого фикса.
32. Разбери, почему {{джоба}} нестабильна в CI: инфра (ресурсы/сеть/поднятие сервисов) vs тесты (flaky) vs окружение (недетерминизм) — по логам последних {{N}} прогонов, каждой категории свой фикс.
33. Найди в пайплайне {{пайплайн}} «зелёный, но бесполезный»: стадии, которые всегда проходят и никогда не ловили баг (закомментированные ассерты? allow_failure? пустой прогон?) — на проверку реальной работы.
34. Проверь скорость обратной связи {{пайплайн}}: сколько разработчик ждёт до первого сигнала о поломке (должно быть минуты, не полчаса) — вынеси быстрые гейты вперёд.
35. Проверь стоимость пайплайна {{пайплайн}}: минуты×частота×параллелизм — где переплачиваем (полный E2E на каждый коммит вместо merge?), баланс скорость/покрытие/цена.

## Специальные пайплайны

36. Спроектируй пайплайн для монорепо {{продукт}}: прогон только затронутых пакетов + их зависимых, кэш по пакетам, параллельность независимых — не «весь репо на каждый PR».
37. Настрой прогон миграций БД в CI: применение на чистой схеме + на снапшоте прод-структуры, откат (если канон), проверка отсутствия блокирующих long-lock миграций.
38. Настрой contract-testing стадию между {{сервис A}} и {{сервис B}} в CI: ожидания потребителя проверяются на провайдере, несовместимость блокирует мерж любой из сторон.
39. Настрой стадию проверки детерминизма: прогон критичного сьюта дважды/в случайном порядке — расхождение результатов ловит flaky до мержа, а не в проде.
40. Настрой канареечную/smoke-стадию после деплоя: критичный путь на реальном окружении, автооткат при провале — гейт между «задеплоено» и «работает».

## Тестовые окружения

45. Спроектируй эфемерные тестовые окружения {{продукт}}: окружение на PR (поднимается/сносится автоматически), изоляция между PR, реалистичность (близко к проду), стоимость под контролем.
46. Настрой поднятие зависимостей для тестов в CI {{джоба}}: сервисы ({{список}}) через compose/services, healthcheck перед стартом тестов, правильные версии (совпадают с продом), сеть между контейнерами.
47. Проверь паритет тестового окружения с продом {{продукт}}: версии рантайма/БД/зависимостей, конфиги, ресурсы — расхождения списком (каждое = потенциальный «зелёный тест, красный прод»).

49. Оптимизируй время поднятия окружения {{джоба}}: предсобранные образы с зависимостями, переиспользование между джобами, параллельный старт независимых сервисов.

## Артефакты и трассируемость

50. Настрой сбор и хранение артефактов {{пайплайн}}: результаты тестов (JUnit XML), покрытие, трейсы/скриншоты падений, логи — доступны из PR, retention-политика.
51. Настрой связь коммит↔тесты↔результат {{продукт}}: по любому падению видно коммит, изменения, лог, артефакты — трассируемость для дебага без воспроизведения.
52. Настрой публикацию тест-результатов в читаемом формате {{CI}}: нативный test-report UI, история прохождения теста, тренд флаки — не грепать сырой лог.
53. Настрой аннотации в PR {{CI}}: падения тестов как inline-аннотации в diff, непокрытые строки, security-находки — прямо в коде ревью.

## Прогрессивные и специализированные пайплайны

54. Настрой merge queue {{продукт}}: PR тестируется в очереди против актуальной основной перед мержем (ловит семантические конфликты зелёных по отдельности PR), автооткат из очереди при падении.
55. Настрой прогрессивную доставку с тестами {{продукт}}: canary/blue-green, smoke на новой версии, автопродвижение при зелёном / автооткат при красном, метрики как гейт.
56. Настрой nightly-пайплайн {{продукт}}: полный E2E, нагрузка, mutation, security-скан, кроссбраузер — тяжёлое, что не тянет каждый PR; отчёт утром команде.
57. Настрой release-пайплайн {{продукт}}: полная регрессия, security/perf гейты, генерация release notes из тестов, sign-off чеклист, тег/артефакт только после зелёного.
58. Настрой пайплайн для hotfix {{продукт}}: сокращённый быстрый гейт (смоук+затронутое) для срочности, но обязательная регрессия затронутого домена — скорость без потери страховки.
59. Настрой contract-testing в CI между {{сервисы}}: изменение контракта провайдера прогоняет тесты всех потребителей, breaking change блокирует до согласования.

## Диагностика и оптимизация (расширение)

60. Построй waterfall-диаграмму пайплайна {{пайплайн}}: время каждой стадии, что на критическом пути, что параллелится, где простои ожидания — визуальная база оптимизации.
61. Найди дублирующую работу в {{пайплайн}}: пересборка в каждой джобе, повторная установка зависимостей, одни тесты в нескольких стадиях — устрани.
62. Проанализируй эффективность кэша {{CI}}: hit rate, размер, время восстановления vs пересборки, отравление между ветками — настрой ключи.
63. Найди «медленный хвост» {{сьют}} в CI: 5% тестов, съедающих 50% времени — параллелить/оптимизировать/понизить уровень/вынести в nightly.
64. Проанализируй стоимость CI {{продукт}}: минуты × частота × параллелизм × тариф — где переплата (полный E2E на draft-PR?), баланс скорость/цена/покрытие.
65. Проверь feedback loop {{пайплайн}}: время до первого сигнала о поломке — минуты (быстрые гейты вперёд) или разработчик ждёт полчаса до провала на последней стадии?

## Надёжность инфраструктуры тестов

66. Проведи аудит нестабильности инфраструктуры {{пайплайн}}: падения не из-за кода (сеть/ресурсы/поднятие сервисов/лимиты) — отдели от flaky тестов, каждой категории свой фикс.
67. Настрой мониторинг здоровья CI {{продукт}}: доля инфра-падений, время очереди джоб, доступность раннеров — инфраструктура тоже требует наблюдения.
68. Настрой graceful обработку инфра-сбоев {{пайплайн}}: авторетрай ТОЛЬКО инфра-ошибок (не тестов), внятное различение «тест упал» vs «раннер упал», алерт на рост инфра-сбоев.
69. Проверь изоляцию параллельных прогонов {{CI}}: джобы/шарды не делят порты/данные/файлы/кэш-ключи — конфликты параллельности маскируются под flaky.

## Продвинутое

83. Настрой test impact analysis {{продукт}}: карта код→тесты, на PR только затронутые+смоук, полный на merge, безопасный fallback — сокращение времени без потери страховки.
84. Настрой quarantine-автоматизацию {{продукт}}: автодетект flaky по истории (падает нестабильно) → авто-карантин с тикетом → non-blocking прогон → алерт на протухание.
85. Настрой авто-бисект в CI для регрессий {{продукт}}: при падении на основной автоматический bisect диапазона → виновный коммит в отчёте — ускорение root-cause.
