# Развёрнутые эталоны промптов (по мастер-шаблону)

> По одному полностью развёрнутому промпту на каждую из 12 категорий. Каждый — это `#1` соответствующего файла, раскрытый по [`../agents/templates/_MASTER-PROMPT-TEMPLATE.md`](../agents/templates/_MASTER-PROMPT-TEMPLATE.md): роль/задача → контекст → формат → техники → параметры → условия+верификация.
>
> **Как пользоваться:** библиотека `prompts/*.md` — это слоты `[ЧТО]`. Берёшь однострочник, оборачиваешь в скелет по профилю своей категории (хедер «Разворачивание по мастер-шаблону» в начале каждого файла) — получаешь такой же развёрнутый промпт. Ниже — 12 готовых образцов результата.
>
> `{{слоты}}` заполняются из `context/` или руками. Профили категорий сведены в таблицу в конце файла.

## 01 — Дизайн тест-кейсов (разворот `01 #1`)

```markdown
[РОЛЬ И ЗАДАЧА]
Ты — test-case-generator, эксперт по тест-анализу и техникам проектирования кейсов.
Мне нужно извлечь из спеки полный список атомарных требований как фундамент для
последующей генерации тест-кейсов — без самих кейсов на этом шаге.

[КОНТЕКСТ]
- Проект-контекст: загрузи prompt-engineering/context/PROJECT-CONTEXT.md §6 (карта доков).
- Вход: спецификация {{спека}} (разделы {{разделы}}).
- Границы: только извлечение требований; кейсы и код НЕ пишем.
- Кто использует результат: следующий шаг — дизайн TC по этим требованиям (01 #23/#40).
- Уровень детализации: каждое требование атомарно, с ID и дословной цитатой источника.

[ФОРМАТ ОТВЕТА]
1. Резюме: сколько требований, какие разделы покрыты.
2. Список R1..Rn: ID | цитата «...» | раздел-источник.
3. Неявные контракты (лимиты/форматы/роли/дефолты) отдельным блоком.
4. Риски: неоднозначные места спеки.
5. Следующий шаг: передать список в дизайн кейсов.

[ЦЕПОЧКА РАССУЖДЕНИЙ]
Покажи, как отделял атомарные требования от составных и где нашёл неявные контракты.

[ПАРАМЕТРЫ ГЕНЕРАЦИИ]
Temperature 0.2 (извлечение фактов, не творчество).

[ДОПОЛНИТЕЛЬНЫЕ УСЛОВИЯ]
- Всё неоднозначное → в «Вопросы к документации», НЕ в требования (запрет догадок).
- Верификация rules/40: этап 2 (каждое «должен/если-то» стало строкой), этап 3
  (каждая цитата сверена с источником), этап 6 (нет выдуманных требований).
  Приложи компактный блок верификации.
```
