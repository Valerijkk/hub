## Базовый контракт эндпоинта

1. Напиши полный тест-сьют эндпоинта {{метод}} {{эндпоинт}} по чек-набору A9: happy path со схемой ответа, валидация каждого поля, 401/403, 404, конфликт, формат ошибок — по канонам проекта из context/.
2. Тест happy path {{эндпоинт}}: валидный запрос → правильный статус + ассерт СХЕМЫ ответа (типы, обязательные поля), не полное сравнение JSON (новые поля не должны ломать тест).
3. Тесты валидации {{эндпоинт}}: по кейсу на каждое правило из спеки — отсутствие обязательного поля, неверный тип, превышение длины, невалидный формат (email/UUID/дата), неизвестное поле (игнор или 400 — по спеке).
4. Тест контракта ошибок {{API}}: каждая ошибка отвечает единым форматом ({{формат}}): машинный код, человекочитаемое сообщение, request-id; сообщение не содержит стектрейсов и внутренних путей.
5. Тесты Content-Type {{эндпоинт}}: отсутствует, неверный, с charset, multipart вместо json → поведение по спеке; ответ всегда с правильным Content-Type.
6. Тесты метода {{эндпоинт}}: неподдерживаемые HTTP-методы → 405 с Allow-заголовком; HEAD/OPTIONS по спеке.
7. Тесты размера тела {{эндпоинт}}: тело на границе лимита, лимит+1 → 413 (запрос отклонён ДО парсинга, память не течёт), пустое тело там, где ожидается объект.
8. Тесты кодировок {{эндпоинт}}: unicode во всех строковых полях (эмодзи, CJK, RTL), экранированные последовательности, null-байты → корректное сохранение или явный отказ.

## Аутентификация и авторизация

9. Тесты аутентификации {{эндпоинт}}: без токена → 401; истёкший → 401 с кодом «expired»; невалидная подпись → 401; токен другого типа (refresh вместо access) → 401; корректный → 200.
10. Тесты авторизации {{ресурс}}: матрица роль × операция — все запрещённые комбинации → 403 (или 404 по политике скрытия), тело ответа не раскрывает существование ресурса.
11. Denial-сьют владения {{ресурс}}: создай от пользователя A, попробуй прочитать/изменить/удалить/найти поиском от B → отказ каждому пути доступа, включая списки и экспорт.
12. Тесты эскалации: пользователь меняет свою роль/чужой ресурс через массовое присвоение (mass assignment) — поля role/owner/id в теле запроса игнорируются или 400.
13. Тесты сессии: операция с отозванным токеном (логаут/смена пароля) → 401; параллельные сессии по политике; токен после смены прав отражает новые права не позже {{T}}.
14. Тесты rate limiting {{эндпоинт}}: под лимитом свободно, лимит+1 → 429 с Retry-After, окно скользит корректно, лимиты раздельны по [пользователю|IP|ключу], превышение не роняет соседние эндпоинты.
15. Тесты API-ключей (если есть): невалидный/отозванный/чужого скоупа ключ, ключ в query vs header (по спеке), ротация без даунтайма.

## CRUD-семантика

16. Тесты создания {{ресурс}}: 201 с Location/телом созданного, дубль уникального → 409, создание с клиентским ID (если допустимо) → идемпотентность повтора.
17. Тесты чтения {{ресурс}}: существующий, несуществующий → 404, удалённый (soft) → 404 или спец-статус по спеке, чужой → 403/404.
18. Тесты обновления {{ресурс}}: полный PUT против частичного PATCH — семантика по спеке (PUT затирает не переданные? PATCH с null очищает поле или игнорирует?), обновление readonly-полей → игнор/400.
19. Тесты конкурентного обновления {{ресурс}}: If-Match/version в запросе — устаревшая версия → 409/412, повтор с актуальной → успех; без версии — политика по спеке (last-write-wins должен быть ЯВНЫМ решением).
20. Тесты удаления {{ресурс}}: 204, повторное удаление → [404 | 204 идемпотентно] по спеке, удаление с зависимостями → каскад/запрет по спеке, восстановление (если корзина).
21. Тесты идемпотентности {{операция}} с Idempotency-Key: повтор с тем же ключом → тот же результат без дублирования эффекта, другой ключ → новая операция, повтор незавершённой → корректное ожидание/статус.

## Списки, фильтры, пагинация

22. Тесты пагинации {{эндпоинт}} по канону проекта [offset/limit | cursor]: пустая коллекция, одна страница, границы страниц без дублей/пропусков, за пределом, невалидные параметры (отрицательные, следующая после несуществующего курсора), максимальный page size и size+1.
23. Тесты сортировки {{эндпоинт}}: каждое сортируемое поле asc/desc, стабильность при равных значениях (вторичный ключ), невалидное поле сортировки → 400, дефолтный порядок задокументированный.
24. Тесты фильтров {{эндпоинт}}: каждый фильтр по отдельности, комбинации (AND/OR-семантика по спеке), пустой результат, невалидные значения фильтра, фильтр по полю с null.
25. Тесты поиска {{эндпоинт}}: регистронезависимость, частичное совпадение, спецсимволы/кавычки в запросе (инъекции в поисковый движок!), права на результаты (только своё/доступное).
26. Тест N+1 на списке {{эндпоинт}}: ответ на {{N}} элементов делает O(1) запросов к БД (перехвати счётчик запросов), время ответа не растёт линейно от вложенных связей.

## Вложенные ресурсы и связи

27. Тесты вложенного маршрута {{/родитель/{id}/дети}}: несуществующий родитель → 404 (до проверки детей), чужой родитель → 403/404, ребёнок другого родителя по прямому ID → не доступен через чужой путь.
28. Тесты связывания {{ресурс A}} ↔ {{ресурс B}}: создание связи, дубль связи, связь с несуществующим/чужим, удаление связи (сами ресурсы живы), лимит связей.
29. Тесты include/expand {{эндпоинт}}: запрошенные связи в ответе, незапрошенные отсутствуют, невалидный include → 400, глубина expand ограничена, права проверяются и на включённые ресурсы.

## Вебхуки и колбэки

30. Тесты приёма вебхука {{эндпоинт}}: валидная подпись → обработка, невалидная/отсутствующая → отказ ДО парсинга тела, replay-атака (старый timestamp) → отказ, дубль события → идемпотентность.
31. Тесты отправки вебхуков {{фича}}: событие → доставка с подписью, получатель 5xx → ретраи с backoff, окончательный отказ → [DLQ/алерт] по спеке, тело не содержит лишних данных (минимизация).
32. Тест порядка вебхуков: события одного объекта доставляются по порядку или несут sequence-номер для восстановления порядка получателем — по спеке.

## Файлы через API

33. Тесты загрузки {{эндпоинт}}: валидный файл, неверный тип с правильным расширением (magic bytes!), размер на границе и сверх, пустой файл, имя с path traversal/unicode, параллельная загрузка.
34. Тесты скачивания {{эндпоинт}}: правильные Content-Type/Disposition, range-запросы (если поддержаны), чужой файл → 403/404, удалённый → 404, presigned-ссылки истекают.

## Версии и совместимость

35. Тесты обратной совместимости {{API}} v{{N}}: запросы формата предыдущей версии → работают; снапшот-контракт схемы ответов — падение теста при удалении/переименовании поля (добавление — ок).
36. Тесты deprecated-полей {{эндпоинт}}: поле ещё отдаётся (до даты {{дата}}), помечено в схеме, использование логируется/метрика растёт.
37. Тест эволюции enum: неизвестное клиенту значение enum в ответе → клиентский контракт это допускает (тест на «неизвестное значение не 500-ит потребителя», если проект контролирует клиентов).

## Заголовки, кэширование, согласование контента

51. Тесты кэш-заголовков {{эндпоинт}}: ETag/Last-Modified в ответе, условный запрос If-None-Match → 304, инвалидация при изменении ресурса, Cache-Control соответствует чувствительности данных (приватное не кэшируется прокси).
52. Тесты сжатия {{эндпоинт}}: Accept-Encoding gzip/br → сжатый ответ, отсутствие заголовка → несжатый, корректный Content-Length/Encoding, нет сжатия ниже порога размера.
53. Тесты согласования контента {{эндпоинт}}: Accept: application/json vs xml (по спеке), неподдерживаемый → 406, дефолт при отсутствии Accept.
54. Тесты CORS {{API}}: разрешённые origin проходят preflight, запрещённые отклоняются, credentials-режим корректен, заголовки не разрешают лишнего (wildcard с credentials — находка).
55. Тесты security-заголовков ответа {{API}}: наличие и корректность HSTS, X-Content-Type-Options, CSP (где применимо), отсутствие раскрывающих заголовков (Server/X-Powered-By с версиями).

## Асинхронные и долгие операции

56. Тесты асинхронного эндпоинта {{эндпоинт}} (202 + polling/callback): 202 с location статуса, статус-эндпоинт отражает прогресс, финальный результат/ошибка, повторный запрос idempotency-key не создаёт вторую задачу.
57. Тесты long-polling/SSE {{эндпоинт}}: соединение держится, события приходят, heartbeat/keep-alive, корректное закрытие, реконнект с Last-Event-ID добирает пропущенное.
58. Тесты batch-эндпоинта {{эндпоинт}}: смешанный батч (часть валидна, часть нет) → per-item статусы, лимит размера батча, атомарность батча по спеке (всё-или-ничего vs частичный успех), порядок ответов.
59. Тесты streaming-ответа {{эндпоинт}} (chunked/NDJSON): элементы приходят потоком (не буферизуются целиком), обрыв на середине, ошибка посреди потока, backpressure медленного клиента.

## Локализация и форматы

60. Тесты локализации ответов {{эндпоинт}}: Accept-Language меняет язык сообщений/ошибок, fallback на дефолт при неподдерживаемом языке, форматы дат/чисел/валют по локали.
61. Тесты форматов дат в API {{эндпоинт}}: приём/отдача ISO 8601 с таймзоной, невалидный формат → 400, разные TZ во входе нормализуются, граничные даты.
62. Тесты числовой точности API {{эндпоинт}}: деньги/decimal не теряют точность (строка vs float в JSON по спеке), большие числа не переполняются, округление предсказуемо.

## Надёжность и деградация

63. Тесты graceful degradation {{эндпоинт}}: некритичная зависимость (рекомендации/обогащение) недоступна → основной ответ отдаётся с частичными данными/флагом, не 500.
64. Тесты таймаут-бюджета {{эндпоинт}}: суммарный дедлайн запроса распределён по downstream-вызовам, превышение → 504/частичный ответ по спеке, ресурсы освобождены.
65. Тесты circuit breaker {{эндпоинт}}: серия ошибок downstream → размыкание (быстрый отказ вместо ожидания), полуоткрытое состояние проверяет восстановление, замыкание после успехов.
66. Тесты приоритизации/quota {{API}}: разные тиры клиентов имеют разные лимиты, исчерпание квоты одного не влияет на других, служебный трафик приоритетен.
