# context/ — факты о проекте

> Единственное место, где живёт проектная специфика. Всё остальное в тулките — обезличенное. Заполняется скилом [context-intake](../skills/context-intake/SKILL.md), обновляется при изменениях фреймворка.

## Файлы

| Файл | Что содержит | Кто читает |
|------|--------------|------------|
| [PROJECT-CONTEXT.md](PROJECT-CONTEXT.md) | Стек, структура репо, команды сборки/тестов, CI | все агенты |
| [TESTFRAMEWORK-MAP.md](TESTFRAMEWORK-MAP.md) | Карта тестового фреймворка: слои, домены, раннеры, пути | reviewer, generator, debugger |
| [NAMING-CONVENTIONS.md](NAMING-CONVENTIONS.md) | Правила именования тестовых функций, файлов, кейсов | reviewer, naming-check |
| [PATTERNS-LIBRARY.md](PATTERNS-LIBRARY.md) | Эталонные паттерны и антипаттерны тестов проекта (реальные примеры) | reviewer, generator |

## Правила работы с контекстом

1. **Агент, встретивший незаполненный `{{placeholder}}` или `TODO(intake)` — останавливается** и требует прогнать `context-intake`. Гадать запрещено.
2. **Факты, не имеющие источника в коде — запрещены.** Каждый заполненный блок должен указывать источник (`путь/к/файлу`, команда, docs).
3. **Ревизия раз в milestone** или после реорганизации тестового фреймворка: `context-intake` в режиме refresh.
4. Контекст-доки — не свалка: только то, что агентам нужно для решений. Остальное — в docs проекта.

## Жизненный цикл

```
Копирование тулкита → context-intake (полный скан) → работа агентов
        ↑                                                   │
        └────────── context-intake --refresh ←── фреймворк изменился
```
