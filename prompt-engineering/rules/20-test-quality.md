# 20 — Минимальные требования к качеству теста

> Планка, ниже которой тест не проходит ревью. Развёрнутые паттерны — `context/PATTERNS-LIBRARY.md` Часть A; здесь — только обязательный минимум в форме проверяемых правил.

## Обязательно (нарушение = HIGH/CRITICAL находка)

1. **Тест может упасть.** Инверсия проверяемого условия в коде роняет тест. Всегда-зелёный тест — CRITICAL.
2. **Тест проверяет контракт из документации/спеки**, не текущее поведение кода («казино-тест»: скопировал фактический вывод в ассерт не сверив со спекой).
3. **Изоляция:** свои данные с уникальными ключами; прогон в параллель и в любом порядке — зелёный.
4. **Детерминизм:** без sleep-синхронизации, без time.Now() в логике ожиданий, без сети в юнитах, без зависимости от локали/таймзоны машины.
5. **Cleanup гарантирован** механизмом раннера (t.Cleanup/afterEach/fixtures), выполняется и при падении.
6. **Один Act на тест** (сценарные e2e-флоу — осознанное исключение).
7. **Ассерты наблюдаемого результата**, не внутренностей реализации; количество verify-вызовов — только для контрактных взаимодействий.
8. **Негативный минимум фичи:** невалидный вход + denial (чужой ресурс/роль) + отказ зависимости. Отсутствие класса — явная причина в PR.
9. **`.only`/`.skip`/Skip** — только с комментарием-причиной и тикетом; `.only` в мерж не попадает никогда.
10. **Флаги канона** (детектор гонок, -count=1, workers из TESTFRAMEWORK-MAP §4) — тест написан так, что проходит под ними.

## Требуется (нарушение = MEDIUM)

11. Структура AAA с визуальным разделением фаз.
12. Данные говорят о кейсе (`blocked-user@test`, не `a@b.c`); магические числа — именованы.
13. Нет дубля существующего теста (вход+состояние+ожидание совпадают).
14. Нет overspecification: ассерты только на релевантное кейсу.
15. Общие хелперы/фабрики переиспользуются, не копипастятся.
16. Табличный тест — без if-логики внутри строк.
17. Сообщения ассертов информативны там, где раннер не показывает diff.

## Рекомендовано (нарушение = LOW)

18. Тест читается сверху вниз без прыжков по файлу (фикстуры — рядом или именованы понятно).
19. Комментарии объясняют ПОЧЕМУ (неочевидный сетап, воспроизведение бага №), не ЧТО.
20. Время выполнения юнита — миллисекунды; медленный юнит — кандидат на пересмотр уровня.

## Definition of Done теста

```
- [ ] Падает при инверсии условия (проверено или очевидно из структуры)
- [ ] Зелёный изолированно и в полном сьюте под флагами канона
- [ ] Название по канону (rules/10 или context/NAMING-CONVENTIONS)
- [ ] Привязка к TC/REQ, если канон требует
- [ ] Лог прогона приложен к PR
```
