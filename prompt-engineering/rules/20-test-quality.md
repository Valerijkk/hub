# 20 — Минимальная планка качества теста

> Нижняя граница ревью автотестов. Project-specific паттерны живут в
> [`context/projects/<profile>/`](../context/projects/README.md) и
> [`patterns/approved/`](../patterns/approved/README.md). **Severity** назначается в
> [`rules/30`](30-severity-policy.md), не здесь.

## Приоритет

Документы project profile (`TEST-ARCHITECTURE.md`, `CI-PIPELINE.md`,
`TRACEABILITY.md`, `SOURCE-MAP.md`) и approved pattern cards перекрывают общие
правила этого файла. Framework-specific механика (cleanup hooks, parallel flags,
синтаксис skip раннера) берётся из активного profile — не изобретать флаги
проекта из этого документа.

## Базовые требования

Каждый пункт ниже — **поведенческий**. Нарушения становятся findings только с
evidence и impact по [`rules/30`](30-severity-policy.md) и confidence по
[`rules/40`](40-verification-protocol.md).

### Поведенческая чувствительность

Тест **обязан падать**, когда поведение под тестом инвертировано или удалено.
Always-green тесты, которые никогда не ассертят заявленный контракт — дефекты
качества; severity масштабируется по риску (см. rules/30).

Ассерты должны соответствовать **документированному контракту** (спека, API doc,
формальный TC), а не некритично скопированному production-выводу («casino test»).

### Изоляция и детерминизм

- Собственные данные с уникальными ключами; параллельный и random-order прогон
  остаётся зелёным.
- Без синхронизации по таймингу (`sleep`, busy-wait), если раннер даёт
  детерминированные waits или hooks.
- Без скрытых внешних зависимостей в unit-level тестах (сеть, clock, locale),
  пока profile не задаёт integration boundary.
- Expected-значения не должны зависеть от timezone или locale машины, если кейс
  явно не тестирует локализацию.

### Границы, негативы, авторизация

Для каждой поверхности фичи покрывать минимум:

- невалидный или out-of-range вход;
- denial (чужой ресурс, отсутствующая роль, отозванная сессия);
- отказ зависимости или timeout, где контракт определяет поведение.

Отсутствие целого класса требует явного rationale в изменении (риск принят,
покрыто elsewhere, out of scope).

### Cleanup

Ресурсы, созданные в setup, освобождаются через teardown-механизм раннера
(`Cleanup`, `afterEach`, fixture scope, compose down — по profile). Teardown
выполняется даже при падении теста.

### Трассируемость

Когда profile требует связи с TC или требованием, каждый автотест, реализующий
формальный кейс, несёт ID по
[`TRACEABILITY.md`](../context/templates/TRACEABILITY.md) активного profile.

### Осмысленные ассерты

- Ассертить **наблюдаемые исходы** (HTTP status, возвращённая ошибка,
  persisted state, emitted event), а не private fields или call counts, пока
  контракт не есть само взаимодействие.
- Предпочитать минимальный набор ассертов, который всё ещё падает на регрессии;
  избегать overspecification, не связанной с кейсом.
- Сообщения ассертов должны различать expected vs actual, если раннер скрывает
  diffs.

### Гигиена сьюта

- `.only`, focused runs или постоянные skips в merge-bound diffs требуют
  документированной причины и ссылки на трекер; focused runs не должны
  попадать в ship.
- Без дублирующего покрытия: тот же вход, состояние и ожидаемый исход, что у
  существующего теста.

## Рекомендуемое (не блокирует, пока project canon не повысит)

- Видимое разделение Arrange / Act / Assert.
- Fixture-данные, читаемые как сценарий (`blocked-user@example`, не `a@b.c`).
- Shared factories вместо copy-pasted setup.
- Table-driven кейсы без условной логики внутри строк.
- Комментарии объясняют **почему** (неочевидный setup, воспроизведение бага),
  а не **что** уже сказано кодом.
- Unit-level тесты завершаются быстро; хроническая медленность — признак
  неверного уровня теста.

## Definition of Done (один тест)

```
- [ ] Падает при инверсии ассертируемого поведения (проверено или структурно очевидно)
- [ ] Зелёный изолированно и в полном сьюте под CI-флагами profile
- [ ] Имя следует canon profile (rules/10 или profile TEST-ARCHITECTURE/TRACEABILITY)
- [ ] Ссылка TC/REQ есть, когда TRACEABILITY profile требует
- [ ] Run log приложен к PR, когда profile или gate требует
```
