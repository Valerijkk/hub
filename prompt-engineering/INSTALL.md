# Установка тулкита в новый проект

> Тулкит полностью обезличен. Перенос = копирование папки + заполнение контекста. Никаких зависимостей, скриптов и пакетов — только Markdown.

## Шаг 1. Скопировать папку

```
cp -r prompt-engineering/ <новый-проект>/prompt-engineering/
```

Что чистить после копирования: ничего. Все проектные факты живут в `context/*.md` — они шаблоны с `{{placeholder}}` до первого запуска `context-intake`.

## Шаг 2. Прогнать context-intake

Открой [skills/context-intake/SKILL.md](skills/context-intake/SKILL.md) и выполни его шаги (сам или отдай AI-агенту одним промптом):

```
Прочитай prompt-engineering/skills/context-intake/SKILL.md и выполни все его шаги
для текущего репозитория. Заполни все четыре файла в prompt-engineering/context/
фактами из кода. Ничего не выдумывай: если факт не найден — пометь TODO(intake).
```

Результат: `context/PROJECT-CONTEXT.md`, `context/TESTFRAMEWORK-MAP.md`, `context/NAMING-CONVENTIONS.md`, `context/PATTERNS-LIBRARY.md` заполнены фактами проекта.

## Шаг 3. Подключить агентов

Файлы `agents/*.md` — готовые системные промпты. Варианты подключения:

| Инструмент | Как |
|-----------|-----|
| Cursor | Скопировать в `.cursor/agents/` (frontmatter уже совместим) |
| Claude Code | Скопировать в `.claude/agents/` проекта |
| Любой чат-LLM | Вставить содержимое файла первым сообщением как system prompt |
| CI-бот | Содержимое файла = system, шаблон из `agents/templates/` = user prompt |

## Шаг 4. Проверить пайплайн на одном сценарии

Smoke-тест внедрения — один цикл каждым агентом:

1. `test-code-reviewer` + шаблон [agents/templates/review-request.md](agents/templates/review-request.md) на последнем diff с тестами.
2. `test-case-generator` + шаблон [agents/templates/test-case-generation.md](agents/templates/test-case-generation.md) на одной задокументированной фиче.
3. Скил `naming-check` на одной папке тестов.
4. Скил `anti-ai-check` на всём репозитории.

Если агент отвечает «контекст не заполнен» — вернись к шагу 2: он читает `context/` и нашёл там незаполненные `{{placeholder}}` или `TODO(intake)`.

## Шаг 5. (Опционально) Интеграция с регламентом проекта

Если в проекте есть свой регламент AI-команды (правила Cursor, CLAUDE.md, AGENTS.md) — добавь туда ссылку на тулкит и правило: «работа с тестами — только через агентов/промпты `prompt-engineering/`». Типовой способ: отдельное правило `.cursor/rules/<NN>-prompt-engineering.mdc` с картой тулкита и обязательными воротами.

## Обновление тулкита

Тулкит — файлы, версионируй git-ом. При переносе новой версии в проект: перезаписывай всё **кроме** `context/*.md` (они содержат заполненные факты проекта). Если структура context-шаблонов изменилась — прогони `context-intake` заново поверх.

- [ ] `context/*.md` заполнены, нет незаполненных `{{...}}` вне примеров
- [ ] Агенты подключены в AI-инструмент
- [ ] Smoke-тест 4 сценариев пройден
- [ ] Ссылка из регламента проекта добавлена
