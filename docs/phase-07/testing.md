# Фаза 7: Доработка и расширенные возможности -- Тестовая документация

## Обзор

Тестовая документация покрывает все 32 требования фазы 7. Тест-кейсы следуют конвенции именования `TC-{REQ_ID}-{NN}`, принятой в предыдущих фазах проекта.

Всего: **70 тест-кейсов** для подсистем Scrum, GitHub, звонков, UI и API/Ops.

---

## Scrum (SCRM-01..05, KANB-02, KANB-03)

### TC-SCRM-01-01: Создание спринта

**Предусловия:**
- Пользователь аутентифицирован и имеет роль Developer+ в проекте
- Проект существует

**Шаги:**
1. POST /api/projects/:projectId/sprints с body: `{"name": "Sprint 1", "goal": "MVP", "start_date": "2026-03-18", "end_date": "2026-03-29"}`
2. GET /api/projects/:projectId/sprints

**Ожидаемый результат:**
- Ответ 201 Created с объектом спринта (id, name, status="planning")
- Спринт отображается в списке спринтов проекта

---

### TC-SCRM-01-02: Запуск спринта

**Предусловия:**
- Спринт со статусом "planning" существует
- Нет активного спринта в проекте

**Шаги:**
1. POST /api/projects/:projectId/sprints/:sprintId/start

**Ожидаемый результат:**
- Статус спринта изменен на "active"
- Ответ 200 OK с обновленным объектом спринта

---

### TC-SCRM-01-03: Запуск спринта при наличии активного -- отклонение

**Предусловия:**
- В проекте уже есть активный спринт

**Шаги:**
1. POST /api/projects/:projectId/sprints/:sprintId/start для другого спринта

**Ожидаемый результат:**
- Ответ 400 Bad Request с сообщением об уже активном спринте
- Статус спринта остается "planning"

---

### TC-SCRM-01-04: Добавление задач в спринт из бэклога

**Предусловия:**
- Спринт существует
- Задачи без спринта (бэклог) существуют

**Шаги:**
1. POST /api/projects/:projectId/sprints/:sprintId/issues с body: `{"issue_ids": ["uuid1", "uuid2"]}`

**Ожидаемый результат:**
- Ответ 204 No Content
- Задачи привязаны к спринту

### TC-SCRM-02-01: Burndown chart

**Предусловия:**

**Шаги:**

**Ожидаемый результат:**
- Ответ содержит массив дней с полями: date, ideal, remaining
- ideal -- линейная интерполяция от total до 0
