# Фаза 5: Голосовые звонки -- Бизнес-документация

## Обзор модуля

Модуль голосовых звонков предоставляет аудиозвонки с демонстрацией экрана для проведения стендапов, демо и спонтанных обсуждений внутри команды. Звонки привязаны к каналам мессенджера: пользователь начинает звонок из канала, другие участники канала видят уведомление и могут присоединиться. Поддерживается до 50 участников одновременно.

Ключевые особенности:
- **Только аудио** -- вебкамеры осознанно исключены для снижения нагрузки на сеть и приватности
- **Демонстрация экрана** -- участники могут показывать свой экран или конкретное окно, поддерживается несколько демонстраций одновременно
- **Эфемерный чат** -- текстовый чат внутри звонка, который автоматически удаляется после завершения
- **Интеграция с мессенджером** -- события начала/окончания звонка отображаются в канале в реальном времени

## Покрываемые требования

### CALL-01: Аудиозвонки и демонстрация экрана

**Описание функции:**
Пользователь может начать или присоединиться к аудиозвонку с демонстрацией экрана (без вебкамер) в канале мессенджера. Максимальное количество участников -- 50 человек. Звонок создается из интерфейса канала нажатием кнопки "Начать звонок".

**Пользовательский сценарий:**
1. Пользователь находится в канале мессенджера (например, #daily-standup)
2. Нажимает кнопку "Начать звонок" в заголовке канала
3. Система создает комнату на сервере LiveKit и возвращает токен доступа
4. Браузер подключается к LiveKit через WebRTC (аудио автоматически включено, видео отключено)
5. В канале появляется уведомление о начале звонка
6. Другие участники канала видят кнопку "Присоединиться" и могут войти в звонок
7. При присоединении каждый получает свой JWT-токен и подключается к той же комнате
8. При выходе или завершении звонка участник отключается от комнаты

**Граничные условия:**
- Только один активный звонок на канал -- попытка создать второй возвращает ошибку
- Звонок автоматически завершается, когда последний участник покидает комнату (через LiveKit empty_timeout)
- При обрыве соединения LiveKit обрабатывает reconnect автоматически
- Если LiveKit-сервер недоступен, создание звонка завершается ошибкой с понятным сообщением

### CALL-03: Управление звонком

**Описание функции:**
Во время звонка участники имеют доступ к элементам управления: включение/выключение микрофона, поднятие руки, выбор экрана или окна для демонстрации, запуск нескольких демонстраций экрана одновременно.

**Пользовательский сценарий -- Mute/Unmute:**
1. Пользователь находится в активном звонке
2. Нажимает кнопку микрофона на панели управления
3. Микрофон отключается, иконка меняется на "микрофон выключен"
4. Другие участники видят индикатор mute рядом с именем пользователя
5. Повторное нажатие включает микрофон обратно

**Пользовательский сценарий -- Поднятие руки:**
1. Пользователь нажимает кнопку "Поднять руку" на панели управления
2. Система обновляет метаданные участника в LiveKit (hand_raised: true)
3. Все участники видят иконку поднятой руки рядом с именем пользователя в списке
4. Повторное нажатие опускает руку (hand_raised: false)

**Пользовательский сценарий -- Демонстрация экрана:**
1. Пользователь нажимает кнопку "Демонстрация экрана"
2. Браузер показывает системный диалог выбора экрана/окна/вкладки
3. После выбора экран отображается всем участникам в области демонстрации
4. Несколько участников могут демонстрировать экран одновременно -- все отображаются в сетке
5. Нажатие "Остановить демонстрацию" прекращает трансляцию

**Граничные условия:**
- Участник может демонстрировать только один экран за раз
- При отклонении системного диалога выбора экрана ничего не происходит
- Метаданные поднятия руки сбрасываются при переподключении участника

### CALL-06: Эфемерный чат звонка

**Описание функции:**
Во время активного звонка участники могут обмениваться текстовыми сообщениями в чате, привязанном к звонку. Чат существует только во время звонка и автоматически удаляется после его завершения. Это позволяет делиться ссылками, заметками и короткими комментариями, не прерывая голосовое общение.

**Пользовательский сценарий:**
1. Пользователь находится в активном звонке
2. Открывает панель чата звонка
3. Вводит текстовое сообщение (до 2000 символов) и отправляет
4. Сообщение появляется у всех участников звонка в реальном времени через NATS/WebSocket
5. Участники могут прокручивать историю сообщений (последние 50 по умолчанию, до 200)
6. После завершения звонка (событие room_finished от LiveKit) все сообщения чата удаляются из MongoDB

**Граничные условия:**
- Сообщения ограничены 2000 символами (отсечка на уровне репозитория)
- Чат доступен только участникам активного звонка
- При попытке отправить сообщение в завершённый звонок -- ошибка "звонок уже завершён"
- Если MongoDB не сконфигурирован, чат недоступен (chatRepo == nil)
- Удаление чата происходит асинхронно при обработке webhook room_finished

## Интеграция с мессенджером

Модуль звонков интегрирован с мессенджером через NATS-события и WebSocket-мост:

| Событие | NATS Subject | WS Room | Описание |
|---------|-------------|---------|----------|
| Звонок начат | `calls.channel.{channelID}.started` | `channel:{channelID}` | Уведомление в канале о начале звонка |
| Участник присоединился | `calls.channel.{channelID}.joined` | `channel:{channelID}` | Обновление списка участников |
| Участник вышел | `calls.channel.{channelID}.left` | `channel:{channelID}` | Обновление списка участников |
| Звонок завершён | `calls.channel.{channelID}.ended` | `channel:{channelID}` | Уведомление в канале о завершении |
| Сообщение чата | `calls.chat.{callID}` | `call:{callID}` | Доставка сообщения участникам звонка |

События звонков используют префикс `call.` (call.started, call.ended, call.joined, call.left) для отличия от обычных событий мессенджера.

## Ограничения

| Ограничение | Причина | Альтернатива |
|------------|---------|-------------|
| Без вебкамер | Осознанное ограничение: голос + screen share покрывают 90% потребностей стендапов и демо | Нет планов |
| Без записи | Требует LiveKit Egress, хранилище для записей, UI управления | Phase 7 (CALL-04, CALL-05) |
| Без запланированных звонков | Требует отдельный модуль расписания, повторяющиеся события | Phase 7 (CALL-02) |
| Без TURN-сервера | Для внутренних сетей прямое UDP-соединение достаточно | Настройка TURN при необходимости |
| Максимум 50 участников | Лимит LiveKit SFU для аудио + screen share на одном сервере | Достаточно для целевой аудитории 10-50 человек |

## Глоссарий

| Термин | Определение |
|--------|-----------|
| **Комната (Room)** | Виртуальное пространство на сервере LiveKit, в котором происходит звонок. Имя формируется как `call-{UUID}`. Создается при начале звонка, удаляется при завершении. |
| **Участник (Participant)** | Пользователь Hub, подключённый к комнате LiveKit. Идентифицируется по user ID. Каждый участник получает индивидуальный JWT-токен для подключения. |
| **Демонстрация экрана (Screen Share)** | Трансляция содержимого экрана, окна или вкладки браузера другим участникам через WebRTC. Несколько участников могут демонстрировать одновременно. |
| **Поднятие руки (Raise Hand)** | Функция, позволяющая участнику привлечь внимание без прерывания говорящего. Реализована через метаданные участника в LiveKit (JSON: `{hand_raised: true/false}`). |
| **Эфемерный чат (Ephemeral Chat)** | Текстовый чат, привязанный к звонку. Сообщения хранятся в MongoDB (коллекция `call_chat_messages`) и автоматически удаляются при завершении звонка. |
| **SFU (Selective Forwarding Unit)** | Архитектура LiveKit, при которой сервер принимает медиапотоки от каждого участника и пересылает их остальным без перекодирования. Обеспечивает масштабируемость до 50 участников. |
| **WebRTC** | Технология peer-to-peer аудио/видео связи в браузере. LiveKit использует WebRTC для передачи аудио и screen share между клиентами через SFU-сервер. |
| **JWT-токен LiveKit** | Подписанный токен доступа, содержащий VideoGrant с правом присоединения к конкретной комнате. Генерируется бэкендом Hub при создании/присоединении к звонку. Действителен 24 часа. |
