# Мессенджер -- Бизнес-документация

## Обзор модуля

Мессенджер -- модуль платформы Hub, обеспечивающий текстовое общение внутри команды. Модуль поддерживает личные чаты, групповые чаты, публичные и приватные каналы, а также автоматически создаваемые каналы проектов. Мессенджер предоставляет полноценные треды, реакции, форматирование текста, голосовые сообщения, пересылку, закрепление и закладки.

### Целевые пользователи

- **Разработчики и тестировщики** -- ежедневное общение в каналах проекта, обсуждение задач в тредах, обмен кодом с форматированием
- **Менеджеры проектов** -- координация через каналы, отслеживание статусов через присутствие, оперативная связь через DM
- **Администраторы** -- создание read-only каналов для CI/CD уведомлений, управление каналами и участниками

### Связь с другими модулями

| Модуль | Интеграция |
|--------|-----------|
| **Проекты** | При создании проекта автоматически создаётся канал #project-{key}, все участники проекта добавляются |
| **Трекер задач** | Уведомления о событиях трекера приходят в каналы проекта |
| **Файловое хранилище** | Вложения к сообщениям и голосовые сообщения хранятся в SeaweedFS |
| **Уведомления** | @упоминания в сообщениях генерируют уведомления |

## Функциональность

### MSG-01: Личные сообщения и групповые чаты

Пользователи могут вести переписку один на один (DM -- Direct Message) или в групповых чатах с несколькими участниками.

**Личные сообщения (DM):**
- Создание через API-эндпоинт `POST /api/messenger/dm` с указанием целевого пользователя
- Дедупликация: при повторной попытке создать DM с тем же пользователем возвращается существующий канал
- Механизм дедупликации: ID обоих пользователей сортируются и соединяются через дефис, образуя уникальный ключ `dm_key`
- Нельзя создать DM с самим собой -- система возвращает ошибку

**Групповые чаты:**
- Создание через `POST /api/messenger/channels` с типом `group` и списком участников `member_ids`
- Создатель автоматически получает роль `owner`
- Дополнительные участники получают роль `member`

### MSG-02: Публичные и приватные каналы

Каналы делятся на два типа доступа:

**Публичные каналы (public):**
- Любой аутентифицированный пользователь может присоединиться через `POST /api/messenger/channels/:channelId/join`
- Видны в общем списке каналов
- Пример использования: общие обсуждения, тематические каналы (#backend, #frontend)

**Приватные каналы (private):**
- Присоединиться можно только по приглашению
- При попытке самостоятельного присоединения система возвращает ошибку "канал приватный, требуется приглашение"
- Приглашение выполняется admin/owner через `POST /api/messenger/channels/:channelId/members`
- Пример использования: обсуждение конфиденциальных вопросов, каналы руководства

### MSG-03: Автоканалы проекта

При создании нового проекта в системе автоматически создаётся публичный канал с именем `#project-{key}`, где `{key}` -- ключ проекта в нижнем регистре.

**Механизм работы:**
1. Модуль проектов публикует NATS-событие `project.created` при создании проекта
2. AutoChannelService мессенджера подписан на это событие
3. При получении события создаётся публичный канал, привязанный к проекту
4. Все текущие участники проекта автоматически добавляются в канал
5. Создатель проекта получает роль `owner` в канале

**Пример:** Создание проекта с ключом `HUB` приведёт к созданию канала `#project-hub`.

### MSG-04: Каналы только для чтения (Read-only)

Каналы могут быть помечены как `is_readonly = true`. В таких каналах:

- **Owner и admin** -- могут отправлять сообщения
- **Обычные участники (member)** -- могут только читать сообщения; при попытке отправки получают ошибку "канал доступен только для чтения"

**Сценарии использования:**
- Канал CI/CD уведомлений (`#hub-ci`) -- бот публикует результаты сборок, участники читают
- Канал объявлений -- администрация публикует новости
- Канал автоматических отчётов

### MSG-05: Треды (ответы в ветках)

Ответ на любое сообщение открывает тред -- ветку обсуждения, привязанную к родительскому сообщению.

**Механизм:**
- При отправке сообщения с указанием `thread_id` (ID родительского сообщения) сообщение становится ответом в треде
- На родительском сообщении автоматически инкрементируется `reply_count`
- При удалении ответа `reply_count` декрементируется
- Получение ответов в треде: `GET /api/messenger/channels/:channelId/messages/:messageId/replies` с курсорной пагинацией

**Отображение в интерфейсе:**
- На родительском сообщении показывается счётчик ответов
- При клике открывается боковая панель ThreadPanel со списком ответов и полем ввода

### MSG-06: Реакции

Пользователи могут ставить emoji-реакции на сообщения. Реакция работает как toggle (переключатель):

- Первый клик добавляет реакцию
- Повторный клик того же пользователя на тот же emoji -- удаляет реакцию
- Каждая реакция содержит emoji и список пользователей, которые её поставили
- API-эндпоинт: `POST /api/messenger/channels/:channelId/messages/:messageId/reactions` с телом `{"emoji": "..."}` (до 32 символов)
- Ответ содержит поле `added: true/false`

**Интерфейс:**
- ReactionPicker -- Popover с сеткой популярных emoji
- Под сообщением отображаются все реакции с количеством

### MSG-07: Форматирование текста

Сообщения поддерживают rich-text форматирование через Plate JSON (на базе Slate):

| Формат | Описание |
|--------|----------|
| **Жирный** | Выделение ключевых слов |
| *Курсив* | Смысловые акценты |
| `Код` | Inline-код, моноширинный шрифт |
| Списки | Нумерованные и маркированные |
| Ссылки | Кликабельные URL |

**Хранение:**
- `content_json` -- Plate JSON структура (для рендеринга в UI)
- `content_text` -- plain text извлечение (для полнотекстового поиска и уведомлений)

**Редактор:**
- MessageComposer на базе Plate editor
- Enter для отправки, Shift+Enter для новой строки

### MSG-08: Редактирование и удаление сообщений

**Редактирование:**
- Автор может редактировать свои сообщения через `PUT /api/messenger/channels/:channelId/messages/:messageId`
- При редактировании устанавливается поле `edited_at` (timestamp)
- В интерфейсе отредактированные сообщения помечаются меткой "(изменено)"
- Чужие сообщения редактировать нельзя -- ошибка "можно редактировать только свои сообщения"

**Удаление:**
- Мягкое удаление (soft delete) -- устанавливается `deleted_at`, сообщение не отображается
- Автор может удалить своё сообщение
- Owner/admin канала может удалить любое сообщение
- Обычный пользователь не может удалить чужое сообщение -- ошибка "нет прав на удаление"
- При удалении ответа в треде `reply_count` родителя декрементируется

### MSG-09: Пересылка, закрепление, закладки

**Пересылка (Forward):**
- Сообщение можно переслать в другой канал через `POST /api/messenger/channels/:channelId/messages/:messageId/forward`
- Создаётся копия сообщения в целевом канале с указанием `forwarded_from_id` (ссылка на оригинал)
- Требуется membership в целевом канале
- Контент и вложения копируются из оригинала

**Закрепление (Pin):**
- Toggle-операция: `POST /api/messenger/channels/:channelId/messages/:messageId/pin`
- Первый вызов закрепляет, повторный -- открепляет
- Список закреплённых: `GET /api/messenger/channels/:channelId/pins`
- В интерфейсе доступна кнопка в заголовке чата для просмотра закреплённых

**Закладки (Bookmarks):**
- Персональные закладки на уровне пользователя (не канала)
- Добавление: `POST /api/messenger/bookmarks` с `message_id` и `channel_id`
- Список: `GET /api/messenger/bookmarks`
- Удаление: `DELETE /api/messenger/bookmarks/:bookmarkId`
- В интерфейсе доступны через кнопку в заголовке списка каналов (Dialog)

### MSG-10: Голосовые сообщения

Пользователи могут записывать и отправлять голосовые сообщения:

**Запись:**
- Используется MediaRecorder API браузера
- Формат: Opus/WebM
- Максимальная длительность: 5 минут
- Кнопка записи в MessageComposer

**Хранение и отправка:**
- Аудиофайл загружается в SeaweedFS (S3-совместимое хранилище)
- В сообщение записываются `voice_url` (ссылка на файл) и `voice_duration_ms` (длительность в миллисекундах)

**Воспроизведение:**
- В MessageItem отображается аудиоплеер с кнопкой play/pause и индикатором длительности

### MSG-12: Поиск по сообщениям

Модуль поддерживает полнотекстовый поиск по сообщениям:

**Поиск по каналу:**
- `GET /api/messenger/search?query=текст&channel_id=ID` -- поиск ограничен конкретным каналом

**Глобальный поиск:**
- `GET /api/messenger/search?query=текст` -- поиск по всем каналам (без channel_id)

**Технические детали:**
- Поиск выполняется через MongoDB text index на поле `content_text`
- Удалённые сообщения (`deleted_at != null`) исключаются из результатов
- Максимум 20 результатов по умолчанию (настраивается параметром `limit`, максимум 100)
- Результаты сортируются по дате создания (от новых к старым)

**Интерфейс:**
- SearchDialog -- диалоговое окно с полем ввода и переключателем области поиска (канал/глобально)

### MSG-13: Статусы присутствия

Система отслеживает статус онлайн-присутствия каждого пользователя:

| Статус | Условие | Индикатор |
|--------|---------|-----------|
| **online** | Heartbeat менее 5 минут назад | Зелёный кружок |
| **away** | Heartbeat от 5 минут до 90 секунд давности (после cleanup) | Жёлтый кружок |
| **offline** | Нет heartbeat или запись удалена | Серый кружок |

**Механизм:**
- Клиент отправляет heartbeat каждые 25 секунд через `POST /api/messenger/presence/heartbeat`
- Фронтенд опрашивает статусы каждые 30 секунд через `GET /api/messenger/presence?user_ids=id1,id2`
- Фоновая горутина каждые 60 секунд удаляет устаревшие записи (старше 90 секунд)

**Кастомный текст статуса:**
- Пользователь может установить текстовый статус через `PUT /api/messenger/presence/status`
- Статус хранится 24 часа, затем автоматически удаляется
- Пустой текст сбрасывает кастомный статус

## Ограничения

| Ограничение | Обоснование |
|-------------|-------------|
| Нет статусов доставки (delivered/read) | Осознанное решение, как в Slack -- только счётчики непрочитанных |
| Нет видеосообщений | Избыточно для v1; голосовые сообщения покрывают потребность |
| MSG-11 (превью ссылок) отложен на Phase 7 | Требует OG meta парсинга и интеграции с трекером/TMS |
| Нет End-to-End шифрования | Внутренний инструмент, E2EE избыточен для self-hosted решения |
| Поиск ограничен text index | Для команды 10-50 человек MongoDB text index достаточен без Elasticsearch |

## Глоссарий

| Термин | Описание |
|--------|----------|
| **DM (Direct Message)** | Личное сообщение между двумя пользователями |
| **dm_key** | Уникальный ключ DM-канала из отсортированных ID пользователей |
| **Тред** | Ветка обсуждения, привязанная к конкретному сообщению |
| **Plate JSON** | Формат rich-text данных на базе Slate editor |
| **content_text** | Plain text версия сообщения для поиска и уведомлений |
| **Heartbeat** | Периодический сигнал от клиента для отслеживания онлайн-статуса |
| **Soft delete** | Мягкое удаление -- запись помечается как удалённая, но не удаляется физически |
| **Read-only канал** | Канал, в котором писать могут только owner/admin |
| **Auto-channel** | Канал, автоматически создаваемый при создании проекта |
| **Forward** | Пересылка сообщения в другой канал (создаётся копия) |
| **Pin** | Закрепление сообщения на уровне канала (видно всем участникам) |
| **Bookmark** | Персональная закладка на сообщение (видна только пользователю) |
| **Presence** | Система отслеживания онлайн-статуса пользователей |
| **Unread count** | Приблизительный счётчик непрочитанных сообщений для канала |
