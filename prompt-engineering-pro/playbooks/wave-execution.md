# Playbook: Wave Execution — маршрутизация моделей в волне

## Цель

Обвязка вокруг оркестрации волны: **какая модель на каком слоте** и что
записать в evidence о выборе.

Сама волна — разрез, проверка пересечений, делегирование, сборка, приёмка —
живёт в двух других местах и здесь не дублируется:

| Что нужно | Где |
|---|---|
| Инвариант, смерть слота, частичный результат | [`../extracts/wave-protocol.md`](../extracts/wave-protocol.md) |
| Пошаговая процедура запуска | [`../skills/wave-orchestrate/SKILL.md`](../skills/wave-orchestrate/SKILL.md) |
| Контракт одного слота | [`../agents/templates/wave-delegate.md`](../agents/templates/wave-delegate.md) |
| Базовый контракт делегирования | [`../extracts/master-delegate.md`](../extracts/master-delegate.md) |

Раньше этот плейбук повторял шаги скила почти дословно. Две копии одной
процедуры расходятся молча: правят одну, вторая продолжает учить старому.
Оставлено только то, чего нет больше нигде.

## Выбор модели на слот

1. Взять фактический каталог доступных моделей — **на момент запуска**,
   не по памяти и не по маркетинговому имени.
2. Сопоставить класс работы слота с записью каталога по
   [`model-routing.md`](../../prompt-engineering/playbooks/model-routing.md)
   в Standard. Маршрутизация одна на оба издания.
3. Записать решение: слот, выбранная запись, основание.
4. При недоступности — записать fallback: что запрашивали, что получили,
   почему замена допустима для этого класса работы.

## Что попадает в evidence волны

| Поле | Зачем |
|---|---|
| Выбранная модель на слот | Без него результат волны невоспроизводим |
| Основание выбора | Отличает решение от привычки |
| Fallback, если он был | Иначе подмена модели выглядит как исходный план |
| Отказ каталога | Объясняет провал слота, не связанный с задачей |

Волна, где половина слотов отработала на одной модели, а половина на другой
без записи, не сравнима сама с собой при повторе.

## Чек-лист маршрутизации

- [ ] Каталог снят на момент запуска, а не взят из прошлой сессии
- [ ] У каждого слота записана модель и основание
- [ ] Fallback отражён в evidence, а не только в чате
- [ ] Параллелизм по умолчанию ≤ 4 слотов; больше — только с явной картой
      непересекающихся файлов

## Антипаттерны

| Антипаттерн | Почему плохо |
|---|---|
| Модель выбрана по памяти | Каталог меняется; вчерашняя запись может быть недоступна |
| Модель выбрана по имени, звучащему солиднее | Имя не свойство; основание — класс работы |
| Runtime fallback не отражён в evidence | Результат приписывается модели, которая его не давала |
| Одна модель на все слоты «чтобы проще» | Дешёвые сопоставительные слоты съедают бюджет дорогих |

## DoD слоя

У каждого слота волны в evidence есть модель, основание и fallback, если он
случился. Повтор волны через месяц воспроизводит тот же разрез моделей или
явно показывает, что каталог изменился.
