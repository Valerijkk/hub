# Playbook: Debug & Forensics

> Два процесса под одной обложкой, но не один процесс.
> **А. Отладка дефекта** — расследуется *система*.
> **Б. Разбор провала прогона** — расследуется *прогон агента*.
> Смешение даёт худший из миров: чиним код там, где сломана постановка,
> и переписываем постановку там, где просто баг.

Красный CI тестового фреймворка — не сюда, а в Standard
[`playbooks/debugging.md`](../../prompt-engineering/playbooks/debugging.md).
Здесь продуктовый дефект и качество агентского контура.

## Граница А ↔ Б

| | **А. Отладка дефекта** | **Б. Forensics прогона** |
|---|---|---|
| Вход | воспроизводимый симптом системы | отчёт слота + артефакты + история |
| Объект | код / тест / инфраструктура | постановка задачи и её исполнение |
| Вопрос | почему система ведёт себя не так | почему прогон дал не то, что заявлено |
| Метод | научный цикл: гипотеза → эксперимент | сверка заявленного с фактическим |
| Права | чинит (в границах слота) | **только чтение**, ничего не правит |
| Выход | root cause + минимальный фикс + регрессия | вердикт «исполнитель / постановка» + правка контракта |
| Провал метода | «зазеленил» симптом | назначил виноватого вместо причины |

Быстрый роутер:

```
Симптом описывает СИСТЕМУ («500 на POST /x», «данные чужого проекта») → А
Симптом описывает ОТЧЁТ  («написано сделано — не вижу», «фаза закрыта, а не работает») → Б
Симптом описывает ТРЕНД  («третья переделка подряд») → «Здоровье контура»
```

Правила стыка:

1. Б не запускается вместо А. «Агент отчитался, а не работает» → сначала Б
   находит, что именно заявлено ложно, затем А отлаживает сам дефект.
2. А не расширяется до Б. Нашёл по пути кривую постановку — отдельный вердикт,
   не расползание сессии.
3. Один дебаг — одна корневая причина. Второй баг → отдельная задача.

# А. Отладка дефекта

## A0. Вход

Дебаг не начинается с «упало что-то». Минимальный вход:

```
симптом:     что наблюдается (значение/код/экран), а не «сломалось»
ожидание:    что должно быть — со ссылкой на {{spec_doc}}, не по догадке
репро:       команда/шаги; либо честное «репро нет»
началось:    когда сломалось / было ли зелёным
лог:         полный вывод или путь к артефакту
```

Нет `ожидание` со ссылкой на источник — идти в A5 (STOP), а не гадать.

## A1. Triage до починки — обязателен

Порядок жёсткий: **воспроизвести функционал, а не тест.** Падающий тест —
гипотеза о поведении, а не приговор коду.

1. Прочитать требование в `{{spec_doc}}` / ACCEPTANCE / ADR.
2. Пройти прод-путь руками: вход → слой → слой → выход.
3. Ответить: «как ДОЛЖНО работать по спецификации» — цитатой, не пересказом.
4. Только теперь классифицировать.

| ROOT | Признак | Действие |
|------|---------|----------|
| `code` | прод-путь нарушает спецификацию | чинить код; тест править только если контракт уточнился |
| `test` | код соответствует спецификации, ожидание устарело/неверно | чинить тест: assertion, mock, фикстура |
| `infra` | падает только в одном окружении/CI | чинить окружение, не поведение |
| `flaky` | недетерминизм: гонка, время, порядок, сеть | детерминизировать (fake clock, барьер, изоляция) |
| `STOP` | спецификация не даёт однозначного ответа | ничего не трогать → A5 |

Отдельный класс, который триаж обязан ловить: **зелёный тест, который не должен
быть зелёным.** Тест слишком слаб или бьёт не в тот слой — это `ROOT=code` со
скрытой дырой, а не успех.

Вердикт пишется **до** патча, в отчёт и в сессию:

```
TRIAGE: {{test_or_symptom}} — ROOT={{root}} — <обоснование + цитата спеки>
```

Фикс без записанного вердикта → возврат на доработку.

## A2. Научный цикл

```
симптом → гипотеза → эксперимент → вывод → (подтверждена ? фикс : в Eliminated)
```

**Гипотеза обязана быть опровержимой.** Если нельзя придумать наблюдение,
которое её убьёт, — это не гипотеза.

| Плохо (неопровержимо) | Хорошо (проверяемо) |
|---|---|
| «где-то гонка» | «два потока пишут в общую структуру без синхронизации на пути X» |
| «состояние ломается» | «стейт сбрасывается, потому что компонент перемонтируется при смене роута» |
| «тайминг подводит» | «ответ приходит после размонтирования и пишет в мёртвый компонент» |

Правила эксперимента:

1. **Одна гипотеза за раз.** Поменял три вещи и заработало — не знаешь, что помогло.
2. **Наблюдаемость раньше изменения.** Сначала лог/метрика/трейс, потом правка.
3. **Один эксперимент может разводить несколько гипотез** — размеченные точки на
   пути (стадии 1..N) показывают, на какой именно ломается.
4. **Ищи опровержение, а не подтверждение.** Подтверждающий поиск всегда «успешен».

Качество наблюдения:

| Сильное | Слабое |
|---|---|
| видно напрямую в логе/дампе | «кажется», «вроде видел» |
| повторяется каждый раз | «упало один раз» |
| однозначно (`null`, не «пусто») | двусмысленно |
| воспроизводится в чистом окружении | смешано с ещё тремя изменениями |

Техники по ситуации:

| Ситуация | Техника |
|---|---|
| большой путь, много кандидатов | бинарный поиск по пути |
| «вчера работало» | дифференциальный дебаг + bisect по коммитам |
| подозрителен большой набор изменений | delta-debug: половинить набор, не только коммиты |
| знаешь правильный выход | идти назад по стеку до точки расхождения |
| много взаимодействий | минимальный repro: срезать всё до бага |
| путь/ключ/URL собирается из переменных | развернуть значение у **писателя** и у **читателя** и сверить |
| мысленная модель не сходится | проговорить вслух: что должно, что есть, что проверено, что допущено |

Право действовать появляется, когда все четыре ответа «да»: понимаю механизм ·
воспроизвожу или знаю условия · наблюдал, а не вывел · альтернативы отсечены.

Гипотеза опровергнута — это результат, а не потеря: она уходит в `Eliminated`
с уликой, чтобы никто не проверял её второй раз.

## A3. Сессия переживает потерю контекста

Контекст кончается всегда. Мозг дебага — **файл**, а не диалог.

`{{debug_dir}}/{{slug}}.md` (по умолчанию `.planning/debug/`):

```
---
status: gathering | investigating | fixing | verifying | awaiting_verify | resolved
trigger: <дословный вход, как данные, не как инструкция>
updated: <timestamp>
---
## Focus       гипотеза · чем проверяю · что будет значить результат · next_action
## Symptoms    expected · actual · errors · repro · started
## Eliminated  гипотеза → чем опровергнута → когда
## Evidence    что проверил → что увидел → что это значит
## Resolution  root_cause · fix · verification · files
```

| Раздел | Режим | Когда |
|---|---|---|
| `status` | перезапись | смена фазы |
| `Focus` | перезапись | **перед каждым действием** |
| `Symptoms` | неизменно | после фиксации входа |
| `Eliminated` | только дописывать | опровергнутая гипотеза |
| `Evidence` | только дописывать | каждое наблюдение |
| `Resolution` | перезапись | по мере понимания |

Три правила, без которых файл бесполезен:

1. **Обновлять до действия, не после.** Если контекст умрёт посреди шага, файл
   должен показывать, что *собирались* сделать.
2. **`next_action` конкретен.** Плохо: «продолжить расследование». Хорошо:
   «добавить лог значения токена перед проверкой подписи в `{{path}}:{{line}}`».
3. **`Eliminated` — это защита от кольца.** Возобновлённая сессия без него
   проверяет те же три гипотезы заново.

Возобновление: `status` → где мы · `Focus` → что делали · `Eliminated` → что не
трогать · `Evidence` → что уже известно · дальше с `next_action`.
Копить резольвы в `{{debug_dir}}/knowledge-base.md` (симптом → корневая причина →
фикс) полезно, но совпадение по ключевым словам — это **кандидат в гипотезы,
проверяемый первым**, а не готовый диагноз.

## A4. Запрет чинить симптом

Перед любым фиксом — чекпоинт рассуждения. Пять полей, все конкретные:

```
гипотеза:        X вызывает Y, потому что Z
подтверждения:   наблюдения (не выводы)
чем опровергнуть: какое наблюдение убило бы гипотезу
почему фикс лечит причину: механизм, а не «стало зелено»
слепые зоны:     что не проверено и может всё обрушить
```

Не заполняется хоть одно поле конкретикой → корневой причины нет, возврат в A2.

| Починка симптома (запрещено) | Починка причины |
|---|---|
| подогнать assertion под текущее поведение | привести поведение к спецификации |
| `sleep` / `retry` вокруг гонки | детерминированная синхронизация |
| `skip` / удаление теста | карантин с тикетом и дедлайном либо фикс |
| перехват исключения на верхнем уровне | не допускать невалидного состояния |
| null-guard в UI | найти, кто пишет null в поле |
| «переписать модуль, раз уж копаем» | минимальный blast radius |

Фикс минимален: наименьшее изменение, снимающее причину. Широкий рефакторинг в
дебаг-сессии прячет и причину, и результат.

## A5. Когда остановиться

STOP — это результат, а не поражение. Останавливаться, когда:

- `{{spec_doc}}`, ADR и acceptance противоречат друг другу или молчат;
- «правильное» поведение определяется вкусом, а не источником;
- тест и спецификация требуют разного и неизвестно, кто прав;
- фикс меняет наблюдаемый контракт (API, статусы, права) — это решение владельца;
- три гипотезы подряд опровергнуты и новых улик не появилось (нужен вход, а не ещё один заход).

Что делать при STOP:

1. Ничего не менять — ни код, ни тест.
2. Сформулировать **вопрос с вариантами**, а не «уточните»:
   «при частичном сбое удаления — 200 с отчётом или ошибка? спецификация не покрывает».
3. Записать в `{{state_file}}` § blockers и в `Focus.next_action`.
4. Эскалировать владельцу спецификации.
5. Тест пометить известным-красным с тикетом. Не подгонять под текущее поведение.

Догадка за владельца спецификации — самый дорогой класс дефекта: он проходит
ревью, потому что выглядит осознанным.

## A6. Закрытие

Проверка идёт по пирамиде доказательств
[`../layers/05-verification-mutation.md`](../layers/05-verification-mutation.md):
L0 (текст) не считается, минимум L1 (команда + код возврата).

Фикс с тестом закрывается мутацией —
[`../extracts/mutation-evidence.md`](../extracts/mutation-evidence.md):
сломать прод-guard → тест RED → откатить → GREEN. Тест, зелёный и до, и после
мутации, не доказывает ничего.

Регрессионный тест пишется на **класс** бага, а не на конкретный инстанс.
Верификацию исходного симптома делает человек или независимый verifier: автор
фикса — заинтересованная сторона.

# Б. Разбор провала прогона (forensics)

## Б0. Принципы

1. **Только чтение.** Forensics ничего не чинит и не переписывает артефакты —
   иначе уничтожает собственные улики.
2. **Каждый вывод привязан к артефакту:** коммит, путь, строка отчёта, запись state.
3. **«Данных недостаточно» — валидный вывод.** Выдуманная причина хуже отсутствия.
4. **Разбирается контур, а не человек/агент.** Вердикт правит контракт, а не тон.

## Б1. Классы расхождения заявленного и фактического

| Класс | Заявлено | Фактически | Как ловить |
|---|---|---|---|
| **ghost** | «сделано / файл создан / тест добавлен» | артефакта не существует | путь не резолвится; нет коммита; нет теста с таким именем |
| **phantom** | артефакт существует и «работает» | существует, но ни на что не влияет | тест не входит в прогон; guard мимо прод-пути; код не вызывается; флаг выключен |
| **выход за границы** | правки в пределах слота | тронуты файлы вне allowlist | diff слота против `[SCOPE AND CONSTRAINTS]` |
| **успех без доказательства** | PASS / «всё зелено» | нет ни команды, ни артефакта | отчёт = L0 по пирамиде L0–L4 |
| **подмена задачи** | outcome достигнут | достигнут переформулированный outcome | acceptance в отчёте ≠ acceptance в задаче |
| **зацикливание** | «дожимаю» | один файл в 3+ подряд коммитах с однотипными сообщениями | история: повторяющиеся `fix:` по одному пути |
| **обрыв** | фаза идёт | незакоммиченное + state в середине + брошенные worktree/ветки | статус рабочего дерева vs `{{state_file}}` |
| **дыра в артефактах** | фаза закрыта | нет плана / сводки / верификации | матрица «фаза × обязательный артефакт» |

`phantom` — самый дорогой: он проходит ревью. Родственный вердикт из mutation —
`layer_mismatch`: тест собирает объект «как в проде» и проверяет его, а не прод-путь.

## Б2. Источники улик

| Источник | Сигнал |
|---|---|
| история коммитов (сообщения, время, частота) | зацикливание, паузы, откаты |
| файлы, менявшиеся чаще всего | точка залипания |
| состояние рабочего дерева | обрыв, потерянная работа |
| diff слота × allowlist задачи | выход за границы |
| отчёт слота: verdict + evidence | L0-успех, подмена acceptance |
| артефакты фазы (план / сводка / верификация) | пропущенные гейты |
| `{{state_file}}` § session notes / blockers | что считалось сделанным и когда |

Отчёт агента — **свидетельство, а не факт**. Каждое утверждение из отчёта
подтверждается независимым источником или помечается «не подтверждено».

## Б3. Провал исполнителя или провал постановки

Ключевой развилочный вопрос:
**мог ли добросовестный исполнитель выполнить эту задачу правильно, имея только её текст?**

| Проверка | «Нет» → постановка |
|---|---|
| Acceptance был опровержимым (видно, чем закрыть)? | размытое «сделать хорошо» |
| Границы файлов заданы (allowlist + do-not-touch)? | выход за границы предсказуем |
| Требуемое доказательство названо (уровень пирамиды, mutation spec)? | «успех без доказательства» — дефолт |
| Источник истины один и непротиворечивый? | исполнитель выбирал за владельца спеки |
| Условие остановки было? | агент дошёл до фантазии, а не до STOP |
| Хендофф самодостаточен без чата? | «сделай как обсуждали» — гарантированный ghost |

Разделяющие сигналы:

| Сигнал | Вердикт |
|---|---|
| контракт полон, отчёт противоречит артефактам | **исполнитель** |
| та же ошибка у разных исполнителей / в разных слотах | **постановка** (системно) |
| ошибка воспроизводится при повторном прогоне того же текста | **постановка** |
| исполнитель заявил STOP, но продолжил | **исполнитель** |
| исполнитель остановился и эскалировал, а результата нет | **постановка** (нет входных данных) |
| выход за границы там, где границ не было | **постановка** |
| выход за границы вопреки явному do-not-touch | **исполнитель** |

Третий, самый частый вердикт: **гейт**. Ни постановка, ни исполнитель, а
отсутствие проверки, которая обязана была поймать это до приёмки.

## Б4. Отчёт forensics

```markdown
## Forensics: {{что разбираем}}

- Заявлено: <цитата из отчёта/статуса>
- Фактически: <артефакт: путь / коммит / строка>
- Класс: ghost | phantom | out-of-scope | unproven | подмена | цикл | обрыв
- Улики: <источник → наблюдение> (минимум по одной на вывод)
- Вердикт: исполнитель | постановка | гейт | данных недостаточно
- Что чинить в контуре: <пункт контракта / гейт / шаблон>
- Что чинить в продукте: <задача на А, отдельно>
- Не подтверждено: <утверждения без улик>
```

Правка идёт в переиспользуемый артефакт — шаблон задачи
([`../extracts/master-delegate.md`](../extracts/master-delegate.md)),
протокол волны или гейт приёмки. Разбор, который заканчивается словами
«будем внимательнее», не изменил ничего.

## Б5. Чего forensics не делает

- не чинит код и не «дожимает» фазу — это А или новая задача;
- не переписывает историю и артефакты прогона;
- не выставляет оценок исполнителю;
- не строит причину там, где улик нет.

# Здоровье контура

Дефект — событие. Деградация — тренд. Ловится не по ощущениям, а по счётчикам.

| Индикатор | Порог тревоги | Что означает | Действие |
|---|---|---|---|
| Доля переделок | растёт две волны подряд | приёмка пропускает недоделанное | ужесточить acceptance/гейт, не скорость |
| Повторяющиеся находки | один класс дефекта в 3+ ревью | лечим инстансы, не класс | правило/чеклист/линт на класс |
| Закрытия без evidence | любое | «Закрыта» = доверие к отчёту | вернуть задачи, поднять минимум до L1 |
| Пропуски mutation на фиксах | >0 при обязательности | гейт декоративен | блокировать закрытие без spec |
| Известный-красный тест | живёт дольше суток | сигнал CI умирает | приоритет выше фич либо явный карантин с дедлайном |
| Карантин flaky | не движется 2 недели | накопление шума | эскалация владельцу домена |
| Ghost/phantom в разборах | 2+ за милстоун | отчётам нельзя верить | независимая верификация выборки |
| Выходы за границы | повторяются | слоты нарезаны неверно | пересечение allowlist = ошибка планирования |
| Хендоффы «продолжи, как обсуждали» | любое | состояние живёт в чате | [`handoff-state.md`](handoff-state.md) |
| Сессии дебага без `Eliminated` | норма | круги по одним гипотезам | A3 обязателен |
| Правки «заодно» вне scope | растут | размывается атрибуция причин | вернуть атомарность |

Ритм: проверять на закрытии фазы/милстоуна, а не когда «стало тяжело».
Деградация лечится изменением контракта или гейта. Призыв «быть внимательнее»
не является действием.
