# Extract — Wave Protocol (portable)

> Переносимое ядро параллельного исполнения. Сжатие GSD `execute-phase`,
> Hub `team-workflow` и практики Standard `wave-execution`.
> Процедура запуска — [`../skills/wave-orchestrate/SKILL.md`](../skills/wave-orchestrate/SKILL.md).

## 0. Инвариант

**Волна — это набор слотов, чьи множества изменяемых файлов попарно не
пересекаются.** Всё остальное в этом документе — следствия.

Два агента на одном файле — не параллелизм, а гонка. Побеждает тот, кто
записал последним, и он не знает, что кого-то затёр.

Слоты, которые только читают, не конфликтуют никогда — поэтому проверяющие
роли безопасно запускать все разом, сколько бы их ни было.

## 1. Подготовка

1. Outcome фазы одной фразой, goal-backward.
2. Atomic units: каждая — самостоятельный PASS/FAIL.
3. Граф зависимостей: что строго до чего.
4. Разрез на волны: внутри волны только disjoint file sets.
5. **Общие контракты правятся до параллели.** API, схемы, типы, базовые
   классы, фикстуры, конфиги — отдельным шагом, последовательно.

Пункт 5 — то, на чём горят чаще всего. Общий контракт нельзя «поделить»:
два слота, правящие его одновременно, дают либо конфликт, либо молчаливую
потерю одной из правок.

## 2. Делегирование слота

На каждый слот — [master-delegate.md](master-delegate.md) с уникальным
allowlist файлов.

Пересечение allowlist двух слотов одной волны = ошибка планирования, волна
не запускается. Проверка механическая, до старта: пересечь списки попарно.

Слот не видит переписку оркестратора. Формулировка «как договорились выше»
для него — пустая строка.

## 3. Резерв оркестратора

Индексы, оглавления, README разделов, файлы состояния и любые сводные
артефакты **не отдаются слотам**. Их правит оркестратор после волны.

Причина та же, что в пункте 1.5: индекс — это общий контракт. Десять слотов,
дописывающих строку в одну таблицу, затрут друг друга, и никто этого не
заметит, потому что каждый видел только свою строку.

## 4. Во время волны

- Слот не расширяет scope «заодно»
- Блокер → STOP слота и эскалация, не тихий обход
- Docs sync в той же сессии, если менялось поведение

## 5. Провал слота не роняет волну

Слот может умереть: лимит, таймаут, обрыв. Волна обязана это переживать.

| Состояние слота | Что делать |
|---|---|
| Завершён с вердиктом | Принять результат в сборку |
| Завершён без вердикта | Считать не выполненным, результат не принимать |
| Умер до записи | Файлы не тронуты, слот перезапускается или выполняется вручную |
| Умер во время записи | **Проверить файлы на обрыв до принятия решения** |

Последняя строка — единственная опасная. Частично записанный файл выглядит
существующим, а на деле оборван на середине.

Обязательные проверки перед сборкой: сбалансированы ли блоки кода, не
заканчивается ли файл на полуслове, проходит ли валидатор пакета.

**Отчёт слота не является доказательством того, что слот отработал.**
Источник истины — состояние файлов, а не текст отчёта. Слот, сообщивший
об успехе, мог умереть до записи; слот, не приславший отчёт, мог записать
всё до конца.

## 6. Сборка волны

1. Каждый слот: verdict + evidence
2. Сверка заявленного с фактическим состоянием файлов
3. Кросс-ревью при парных ролях
4. Independent verifier на critical/security
5. Оркестратор обновляет резерв из §3
6. Goal-verify фазы — не «все задачи отмечены»
7. Handoff/STATE note

## 7. Verify goal-backward

Спроси: *если бы задач не было, а был только outcome — доказан ли он?*

CI green без outcome evidence недостаточно: зелёный CI говорит, что ничего
не сломалось, а не что цель достигнута.

## 8. Частичный результат — нормальный исход

Волна, где сели не все слоты, даёт частичный результат. Это не провал:
принимается то, что прошло проверку §5, остальное переоткрывается.

Опасность здесь одна — **объявить волну завершённой по числу отчётов, а не
по числу проверенных артефактов**. Отчётов может быть десять, а изменений
на диске четыре.

## 9. Anti-patterns

| Антипаттерн | Почему плохо |
|---|---|
| Одна волна на весь монорепо | Конфликты, неатомарность, нечего откатывать по частям |
| «Сделай как в чате» | Слот переписки не видит |
| PASS без команды | Нет evidence |
| Мутация после «Закрыта» | Поздно: спецификация мутации должна быть в ACCEPTANCE |
| Индекс отдан слоту | Общий контракт в параллели — молчаливая потеря правок |
| Слот правит общий контракт | То же самое, только заметят позже |
| Приём результата по отчёту | Отчёт мог соврать или устареть на момент смерти слота |
| Расширение scope внутри слота | Разрез перестаёт быть непересекающимся задним числом |
