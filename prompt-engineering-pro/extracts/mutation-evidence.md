# Extract — Mutation Evidence (portable)

> Практика Touchstone / Hub Stage C. Вердикт `mutation_failed_to_build`
> предусмотрен не зря: сломанная сборка ≠ доказанный тест.

## Спецификация (обязательна в задаче)

```
что ломать:   <path> :: <фрагмент или условие>
какой тест:   <TestName или путь::case>
слой:         handler | service | repository | schema | ui | other
ожидание:     тест RED на мутации; после restore — GREEN
```

Без трёх полей статус «Закрыта» = доверие к отчёту, не доказательство.

## Протокол

1. Зафиксировать baseline GREEN на указанном тесте.  
2. Внести минимальную мутацию в **продакшн-код** (не в тест).  
3. Если пакет **не собирается** → вердикт `mutation_failed_to_build`;
   переформулировать мутацию (часто: unused import / generate breakage).
   **Не** засчитывать как PROVEN.  
4. При успешной сборке: тест обязан быть RED.  
5. Откатить мутацию → GREEN.  
6. Записать evidence: команды, имена тестов, путь guard'а.

## Вердикты

| Код | Когда |
|-----|-------|
| `PROVEN` | RED→restore→GREEN, слой совпал |
| `mutation_failed_to_build` | Сборка/generate упали |
| `layer_mismatch` | Тест проверяет копию/мок, не prod-guard |
| `NOT_PROVEN` | Нет RED или нет спецификации |
| `SKIPPED` | Явно вне scope с причиной |

## Layer mismatch — красный флаг

Если тест сам создаёт объект «как в проде» и проверяет его, а не прод-путь —
мутация прода ничего не докажет. Чини тест/слой, не закрывай задачу.
